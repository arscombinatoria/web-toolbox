# Web Toolbox — アーキテクチャー仕様

## 概要・設計方針

Web Toolboxは、GitHub Pagesで配信するバックエンドのない静的SPAです。ホーム画面と、IPアドレス確認・IP登録情報検索・全角／半角変換・Markdown表変換・正規表現ビジュアライザー・JST／UTC日時変換・JWTデバッガー・画像変換の8ツールで構成します。本書は現行実装の内部設計、変換規則、制約、設計判断と検証範囲を記載します。利用方法と開発手順は[README](../README.md)、エージェント向けの実装規約は[AGENTS.md](../AGENTS.md)を参照してください。

Vanilla TypeScript（strict）、ES Modules、Vite、HTML/CSS、ブラウザ標準APIを使用します。UIフレームワークや状態管理ライブラリは使用せず、各ツールのDOM操作と通信・変換処理を分離しています。共通UIはRegistryのメタデータから生成し、ツール本体は必要時に読み込みます。

入力・結果は画面内で扱い、ツールを離れると破棄します。IP確認・RDAPの外部API通信と、手動選択したテーマの保存については[セキュリティ・データ保護](#セキュリティデータ保護)に記載します。

## システム構成・モジュール構成

主要ファイルの構成は次のとおりです。Vitestのテストは対象モジュールに隣接し、E2Eは`tests/`に配置しています。

```text

  tsconfig.json                    # strict型チェック
  vite.config.ts                   # 配信base
  vitest.config.ts                 # Node既定・V8 Coverage
  playwright.config.ts             # ブラウザ・previewサーバー
  src/
    main.ts                        # 起動・選択状態・タイトル・フォーカス
    registry.ts                    # メタデータ・型・動的import
    router.ts                      # URL生成・History API・リンク操作
    tool-host.ts                   # マウント・破棄・読み込み競合制御
    components/
      home.ts                      # Registryからホームのカードを生成
      layout.ts                    # ヘッダー・サイドバー・モバイルメニュー

        index.ts / logic.ts / format.ts / preview.ts / xlsx.ts / style.css
      regex-visualizer/
```

各ツールの`index.ts`はDOM・イベント・非同期処理の状態を、`style.css`はツール固有の表示を担当します。IP確認の`api.ts`は通信とレスポンス検証、他ツールの`logic.ts`はDOMに依存しない変換処理を担当します。Markdown表の`xlsx.ts`はファイル生成専用です。`public/favicon.svg`はタブ用アイコンとして配信します。

### Registryと遅延読み込み

[src/registry.ts](../src/registry.ts)の`ToolDefinition`は`id`、`name`、`description`、`category`、`icon`、`load`を持ちます。`load`は固定パスを指定した動的importです。URLの文字列をimportパスに直接使用しません。共通の`ToolModule`型もRegistryで定義します。

`categories`の配列順はサイドバーのカテゴリ順、`tools`の配列順はカテゴリ内のツール順とホームのカード順になります。現在のツール順はIP確認、IP登録情報検索、全角・半角、Markdown表、正規表現、JWT、日時、画像変換です。ホームはツール登録に含めず、`components/home.ts`で表示します。

ホームのカードはRegistryのID・名前・説明・アイコンから生成し、サイドバーも同じツールアイコンを使います。アイコンは`lucide`の名前付きimportを使い、[components/icon.ts](../src/components/icon.ts)で文字色を継承する装飾SVGにします。ホーム表示時にはツールの`load`を呼ばず、ツール本体・正規表現Worker・regexpp・ExcelJS・joseを読み込まず、ipify・RDAPにも通信しません。ExcelJSはMarkdown表のダウンロード操作時、joseはJWTの署名検証操作時にさらに遅延読み込みします。

## ルーティング・画面ライフサイクル

### URLと履歴

[src/router.ts](../src/router.ts)は`?tool=<tool-id>`で画面を選択します。

| URLの状態 | 表示 |
| --- | --- |
| `tool`未指定（`null`） | ホーム |
| 登録済みID | 対応するツール |
| 空の`?tool=`、不明ID | 「ツールが見つかりません」と復帰用リンク |

不明IDをホームへ置換せず、URLも自動修正しません。復帰用の「既定のツールを開く」は`defaultToolId`の`ip-address`を指します。このIDは初回表示の選択には使いません。

`toolUrl`・`homeUrl`は現在のURLを複製し、パス・無関係なクエリ・ハッシュを保持します。ホームへのリンクでは`tool`をすべて削除します。通常のリンク選択ではIDが変わる場合だけ`pushState`を実行し、画面を更新します。`popstate`ではURLから再描画するだけで履歴を追加しません。初回表示・直接アクセス・再読み込みも同じURL解釈です。

ルーターが処理するのは`data-tool-id`または`data-home`付きリンクの、同一origin・同一pathnameへの通常クリックです。修飾キー付きクリック、左ボタン以外、別タブ指定、ダウンロード、処理済みイベントは横取りしません。

### マウント・破棄・競合制御

ツールの契約は同期関数`mount(container: HTMLElement): () => void`です。マウント中に表示を作り、通信などは内部で開始します。IP確認からRDAPへの一時入力に限り、任意の第2引数`input?: string`を受け取れます。返す破棄関数は、ツールが登録したリスナー・タイマー・通信などと表示要素を解放します。

[src/tool-host.ts](../src/tool-host.ts)の`show`は、`null`をホーム、`undefined`を不明ツール、それ以外をツール定義として扱います。遷移ごとに世代番号を更新し、旧画面の破棄関数を呼んでからコンテナを空にします。ホームも破棄関数を返します。

ツール読み込み中は`aria-busy`と読み込み案内を表示します。動的importはキャンセルできないため、完了時に世代番号を確認します。旧importの成功・失敗はマウントも案内の更新も行わず、新画面の`aria-busy`も解除しません。現在の読み込みまたはマウントが失敗すると、再読み込み・別ツール選択の案内と復帰用リンクを表示します。`destroy`も世代を更新し、破棄とコンテナの消去を行います。

`main.ts`は同じIDの再選択では再マウントしません。別ツール・ホームへ移動した後に戻る場合は新規マウントとなり、入力・設定・結果を復元しません。History APIには入力状態を格納しません。ホストはimportの競合を、各ツールは自身の通信・コピー・ファイル生成の競合と破棄を担当します。Clipboard APIやXLSX生成自体は中止せず、世代番号・破棄フラグで古い完了処理の表示やダウンロードを抑制します。

## UI・テーマ・アクセシビリティ

### 共通レイアウトとフォーカス

デスクトップはカテゴリ別の左サイドバーと右メイン、幅759px以下は開閉式メニューです。ホームのカードはデスクトップで2列、モバイルで1列です。ヘッダーのブランドリンクとサイドバー先頭の「ホーム」からホームへ戻れます。

`components/layout.ts`は同じサイドバーを通常の配置先と標準`dialog`の間で移動します。モバイルで閉じている間は`hidden`でリンクをフォーカス対象から外します。メニューボタンは`aria-expanded`と`aria-controls`を持ち、`showModal()`によるモーダル制御とTab端点の循環を使用します。開いたときは現在の選択リンク、不明IDなどで選択がなければ閉じるボタンにフォーカスします。

Escape・閉じるボタン・ダイアログ背景のクリックで閉じ、ネイティブのdialog動作でメニューボタンにフォーカスが戻ります。リンク選択時にも閉じ、遷移完了後に`main.ts`が新画面の`h1`へフォーカスします。デスクトップ幅へ変更した場合はメニューを閉じ、サイドバーを通常位置へ戻します。

選択リンクに`aria-current="page"`を付与します。ページタイトルはホームが`Web Toolbox`、ツールが`ツール名 | Web Toolbox`、不明IDが`ツールが見つかりません | Web Toolbox`です。初回表示では見出しへ自動フォーカスせず、リンク選択・履歴移動では現在の画面表示完了後に移します。本文へのスキップリンク、入力ラベル、fieldset/legend、キーボード操作、`:focus-visible`を備えます。

### テーマと状態通知

色・余白・角丸などは`src/styles/main.css`のCSS変数で管理し、ツール固有CSSも両テーマに対応します。システムフォントを使用し、`prefers-reduced-motion`ではアニメーション・トランジションなどを無効にします。

`index.html`のスクリプトはスタイル適用前に手動設定を復元します。未設定時の初期配色はCSSの`prefers-color-scheme`、起動後の配色は`components/theme.ts`が`data-theme`へ反映します。手動設定がない間はOS設定の変更に追従し、手動選択時は選択色を使用します。保存の詳細は次節を参照してください。

コピーは`navigator.clipboard.writeText`を使用します。権限拒否・API非対応などの例外を捕捉し、成功・失敗を`role="status"`で通知します。失敗してもreadonlyの出力欄を残し、手動選択・コピーを可能にします。コピー・生成の非同期完了は、入力変更や破棄後に古い通知を表示しないよう管理します。入力エラーは`role="alert"`や`aria-invalid`で示します。変換結果全文や定期更新する時計はライブリージョンにしません。

## セキュリティ・データ保護

ツール入力・変換結果・取得したIPは、URL・ログ・localStorage・sessionStorageなどへ保存しません。ブラウザ内の画面状態として保持し、切り替え時に破棄します。画像・XLSXの明示的なダウンロードとClipboard APIへの書き込みは利用者操作による出力です。

永続化するアプリ設定は手動選択したテーマのみです。localStorageの`web-toolbox-theme`に`light`または`dark`を保存し、「システム」で削除します。読み書き失敗は捕捉し、保存できなくても現在のテーマ選択とアプリ動作を継続します。

ツールのデータ取得のための外部通信はIP確認のipifyと、IP登録情報検索のRDAP.orgおよび標準リダイレクト先を例外とします。接続先・送信方針・外部依存は各ツールの仕様に記載しています。他ツールの入力を送信する処理はありません。ツールやExcelJS・joseの動的importは同一サイトの配信アセットを読み込みます。外部フォント・解析サービス・外部スクリプトは使用しません。

固定HTMLテンプレートにのみ`innerHTML`を使用し、利用者入力・変換結果・外部レスポンスはフォームの`value`または`textContent`で設定します。Markdownプレビューは許可するトークンのみDOM APIで生成し、入力HTMLやURL属性を反映しません。IP・RDAPレスポンスは`unknown`として型と形式を検証します。

## ツール別詳細仕様

以下はREADME・Registryと同じ掲載順です。各ツールのデータ保存・送信の共通方針は前節、テストの実行基盤は[テスト方針](#テスト方針)を参照してください。

### IPアドレス確認 — `ip-address`／ネットワーク

#### 通信と形式検証

`api.ts`はIPv4を`https://api.ipify.org?format=json`、IPv6を`https://api6.ipify.org?format=json`から取得します。`api64.ipify.org`や別サービスへのフォールバックは使用しません。位置情報・ローカルIPは取得しません。

ブラウザから直接通信するため、接続元IPがipifyへ伝わる旨を画面に明記します。fetchには`cache: 'no-store'`、`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`を指定し、アプリ独自のヘッダーや識別情報は追加しません。取得は各IPバージョンの接続環境、DNS、提供元の稼働状況・CORS設定に依存します。IPv6取得失敗だけでIPv6非対応とは判断できない旨も表示します。

HTTP成功後、JSONが非nullのオブジェクトで、`ip`が文字列かつ要求したIP形式であることを確認します。前後の空白除去や表記の正規化はせず、検証した文字列をそのまま返します。検証はアドレスの構文を対象とし、グローバルアドレス範囲の判定は行いません。

- IPv4：4オクテットのASCII十進表記、各0〜255です。先頭ゼロ、符号、空白、全角数字、IPv6を拒否します。
- IPv6：各1〜4桁の16進数8グループ、1回だけの`::`による1グループ以上の省略、末尾IPv4埋め込みに対応します。埋め込みIPv4も上記のIPv4検証を行い、2グループとして数えます。過剰・不足グループ、不正な16進数、空白、角括弧、ポート付き形式、ゾーンIDを拒否します。

内部エラー種別は`network`、`http`、`timeout`、`format`、`aborted`です。不正JSON・`ip`の欠落／型不正・IP形式不正はいずれも`format`、本文読み込み中の通信障害は`network`として扱います。UIは種別に応じた日本語の案内を表示し、画面切り替えによる中止は通信エラーとして通知しません。

#### UI・非同期処理・破棄

表示時に両APIを並行して自動取得します。各リクエストはJSON本文の読み込みを含め10秒でタイムアウトし、自動リトライしません。`api.ts`内のAbortControllerで呼び出し元の中止とタイムアウトを伝え、`finally`でタイマーと中止リスナーを解放します。

IPv4・IPv6は独立した結果・取得状態・コピーボタンを持ちます。一方の失敗で他方の成功を消去せず、先に成功した側は他方の完了前でもコピーできます。共通の再取得ボタンは両方の完了まで無効にし、再取得開始時に両方の旧IPとコピー通知を消去します。

IPv6の`network`・`timeout`は利用環境と一時障害を区別できないため、Infoアイコンと中立色で「IPv6を利用できない環境、または一時的に取得できない状態です。」と案内します。IPv4のエラー、およびIPv6のHTTP・レスポンス形式エラーは種別ごとの従来表示を維持します。

IPv4はreadonly input、IPv6は`rows="1"`のreadonly textareaです。IPv6の高さは取得開始・成功・ウィンドウリサイズ時に`scrollHeight`と枠線幅から再計算します。`field-sizing`に依存せず、折り返した内容全体を表示し、手動リサイズは無効にしています。各パネルの取得状態とコピー結果を別のstatusで通知します。

結果欄は幅100%を保ちつつ、IPv4は15文字、IPv6はIPv4埋め込み表記も含む45文字と内側余白・境界線を収める最大幅に制限します。狭い画面では親幅を超えず、IPv6の折り返しと高さ調整を維持します。

UIはリクエストのAbortController識別と破棄フラグで、古い取得・コピー完了を無視します。コピー中は該当ボタンを無効にします。再取得開始時に前回のcontrollerを中止し、破棄時にも通信を中止してコピー・再取得・resizeのリスナーを解除します。

#### 主なテスト

`api.test.ts`はHTTP・JSON・両IP形式の境界値、通信障害、本文読み込み中を含む10秒タイムアウト、開始前／実行中の中止、タイマー解放を検証します。`index.test.ts`は両バージョンの成功・失敗の組み合わせ、連打抑止、独立表示、再取得、コピーと破棄後の更新抑制、高さ再計算を検証します。

`tests/ip-address.spec.ts`は表示・再取得・実Clipboard API・エラー復帰・切り替え・狭幅両テーマを、`tests/ip-address-layout.spec.ts`はChromiumとFirefox、両テーマ、320／768／1280／1920pxでIPv4・IPv6の表示幅、最大長のIPv4・IPv6、折り返し、状態変化時の幅維持、IPv4との高さ、手動選択を検証します。実APIへの到達性はモックテストの保証範囲外です。

### IP登録情報検索 — `rdap-lookup`／ネットワーク

#### 通信・解析

`api.ts`は`https://rdap.org/ip/{IP}`へ直接fetchし、ブラウザ標準のリダイレクトに任せます。問い合わせ先判定・IANA Bootstrap・CORS回避プロキシ・`no-cors`は使いません。`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`cache: 'no-store'`を指定し、Acceptを含む独自ヘッダーは追加しません。AbortControllerと10秒タイマーはJSON本文読み込みにも適用し、完了時にタイマーと中止リスナーを解放します。自動リトライはありません。

入力は前後空白を除去し、既存のIP確認APIの`isIpv4`・`isIpv6`を再利用します。`logic.ts`は外部JSONを`unknown`から検証し、`objectClassName: 'ip network'`を要求します。任意フィールドの型不正・欠損は省略し、未知の拡張は生JSONに残します。`cidr0_cidrs`のIPv4／IPv6プレフィックスと整数の長さを検証し、CIDRを表示します。CIDRや所在地をIP範囲から推測しません。

entityを反復処理でネスト内まで走査し、roles・jCardのfn／org／email／tel／adrを型検証して抽出します。orgが配列の場合は先頭成分だけを組織名とし、後続の部署・部門は抽出しません。単一文字列のorgはそのまま扱います。管理組織は明示的なregistrantのorg、なければfnのみから取得し、Abuseメールはabuse役割のみから抽出します。registrantとabuseを兼ねるentityからは両方を独立して抽出します。technical／administrativeなどの公開情報も役割名とともに表示し、役割を推測で補いません。eventsのregistration／last changedは応答の日時文字列を表示します。

#### UI・遷移・破棄

通常表示・直接アクセス・再読み込み・戻る／進むでは自動検索せず、検索ボタン／Enterで検索します。IP確認の成功したパネルだけにRDAPリンクを表示し、再取得時に非表示にします。routerの`setNavigationInput`はリンクをキーとするWeakMapに一時入力を保持します。通常の同一SPAリンク操作時だけcallback→main→tool-host→mountの任意引数に渡し、リンク破棄時にも解除します。URL・History state・永続ストレージへは記録しません。遅い動的importは既存のホスト世代管理に従い、別画面に入力を持ち越しません。修飾キーや別タブ操作は通常リンクのままで、入力を引き継ぎません。

検索中はstatusで通知し、新規検索と入力変更は以前のRDAP・ipify通信を中止して結果を消去します。「クリア」は入力・結果・エラー・通知を消去して入力へフォーカスします。「自分のIPv4／IPv6」は明示操作時だけ既存ipify APIを呼び、成功時に入力へ設定して古いRDAP結果を消しますが、自動検索はしません。失敗時は入力と結果を保って通知します。IP確認とRDAPは独立したAbortControllerと世代番号を使い、中止を無視する非同期結果や古いコピー・保存完了通知を反映しません。破棄時は通信・イベントリスナー・タイマー・Object URLを解放します。

ネットワーク情報、管理組織とAbuse、役割別連絡先、登録情報、RDAPサーバーリンク、生JSONのdetailsを表示します。成功時には、ネットワーク情報の前に結果テキスト・JSONのコピーとJSON保存を出します。`createRdapDisplay`がUIとコピー文の共通データを作り、JSON表示・コピー・ダウンロードには同じ`JSON.stringify(data, null, 2)`文字列を使います。保存はUTF-8の`application/json;charset=utf-8` Blobを作り、IPをファイル名に含め、Object URLを1秒後または破棄時に解放します。欠損は省略または「情報なし」とし、国コードが実際の所在地を保証しないことを明示します。外部値はtextContentだけで描画し、リンクは認証情報を含まない絶対HTTPS URLだけを許可し、noopener／noreferrerを付けます。

404・429・その他HTTP・通信障害・timeout・不正JSON・非IP Network応答を区別します。ブラウザで区別できない通信障害をCORSと断定しません。失敗時は検証済み入力IPから生成したRDAP.org外部確認リンクを表示します。検索対象IPと接続元IPがRDAP.orgと転送先へ伝わることを画面に明記します。

### 全角・半角変換 — `width-converter`／テキスト・データ

#### 入出力とUnicode規則

`logic.ts`の純粋関数`convertWidth(input, direction, categories)`が変換を担当します。方向は`to-half`／`to-full`、カテゴリは英数字・記号・カタカナ・スペースの4つです。初期値は全角→半角、英数字・スペースON、記号・カタカナOFFです。記号はチェックボックスをONにすると変換します。全OFFでは入力をそのまま出力します。出力はreadonly textareaです。

`measureText`は入力・出力を`for...of`で一度走査し、Unicodeコードポイント数とLF行数を同時に数えます。空文字は0文字・0行、その他はLF数＋1行です。結合文字・空白も各コードポイントとして数え、textareaの折り返しは数えません。textarea.valueで正規化された改行を対象にします。ラベル横のカウンターIDを対応するtextareaの`aria-describedby`へ加え、既存説明との関連を保ちます。カウンターはライブリージョンにしません。

| カテゴリ | 変換範囲と制約 |
| --- | --- |
| 英数字 | ASCIIの`0–9`・`A–Z`・`a–z`と対応する全角英数字です。 |
| 記号 | ASCII U+0021–U+007Eから英数字を除いた文字と、対応するU+FF01–U+FF5Eです。チルダU+007E ↔ U+FF5E、バックスラッシュU+005C ↔ U+FF3Cを含みます。波ダッシュU+301C、円記号U+00A5・U+FFE5は保持します。 |
| カタカナ | 半角U+FF61–U+FF9Fに対応するカナ・小書き・長音・中黒・日本語句読点・濁点／半濁点です。句読点は記号カテゴリに依存しません。 |
| スペース | U+0020 ↔ U+3000のみです。タブ・改行・その他のUnicode空白は保持します。 |

カタカナ対応表は既知の半角1文字と、濁点・半濁点との組から生成します。NFKCを適用するのは対応表生成と、半角→全角の既知の半角カナおよび直後の濁点（半角または結合文字）の範囲だけです。全文を正規化しないため、丸数字・ローマ数字などの互換文字を変化させません。

合成済みのガ・パ・ヴ・ヷ・ヺなどと対応するカナ＋結合濁点に対応します。全角→半角では結合濁点U+3099・U+309A、幅のあるU+309B・U+309Cを半角U+FF9E・U+FF9Fへ変換します。半角→全角では単独の半角濁点・半濁点を結合文字U+3099・U+309Aにし、結合不能な組は基底カナと結合文字の並びになります。

ひらがなに続く結合濁点・半濁点はまとめて保持し、濁点だけを変換しません。ひらがな、ヵ・ヶ・ヮなど半角対応のないカナ、未選択カテゴリ、その他の非対応Unicodeも保持します。単独濁点などの扱いにより、全Unicodeで完全な往復一致は保証しません。

初期設定では`ＡＢＣ１２３！＠＃　ガギグ`が`ABC123！＠＃ ガギグ`になります。記号をONにすると`ABC123!@# ガギグ`になります。空入力は空出力となり、非対応文字を入力エラーにはしません。

### Markdown表変換 — `markdown-table`／テキスト・データ

#### 共通モデルとMarkdown解析

`logic.ts`は`TableData = { rows: string[][] }`を共通モデルとし、`parseMarkdown`・`parseMarkdownWithAlignments`・`parseTsv`・`toMarkdown`・`toTsv`を提供します。先頭行をヘッダーとして扱います。すべての方向で列数の不一致をエラーにし、補完・切り捨てを行いません。`parseMarkdown`は従来の戻り値を維持し、配置情報が必要な画面では同じ解析を繰り返さない`parseMarkdownWithAlignments`を使います。

Markdownは単一表を対象とし、先頭行がヘッダー、2行目が必須区切りです。区切りセルはハイフン3個以上で、`---`、`:---`、`---:`、`:---:`を受理し、それぞれ指定なし・左・右・中央配置として読み取ります。配置配列は列インデックスで管理し、列追加時は指定なし、列削除時は末尾から破棄します。外側パイプは省略可能、前後の空行は無視、途中の空行はエラー、空白のみの入力は空表です。行区切りCRLF／CRはLFへ揃えます。

パイプ直前の連続バックスラッシュが偶数なら列区切り、奇数ならセル内容として扱います。コードスパン内でもパイプのエスケープが必要です。外側パイプの外にあるASCIIスペース・タブは無視します。セル両端のASCIIスペース各1文字のみを構文の余白として除去し、それ以上の空白・タブ・全角空白は保持します。幅揃えの多数のスペースも内容になります。端の空セルと外側パイプの曖昧さを避けるため、空セルがある表は外側パイプ付きの形式が適しています。

装飾・HTMLエンティティは解釈せず保持します。`<br>`、`<br/>`、`<br />`（大小文字不問）のみLFへ変換します。同じ長さのバッククォート列で閉じるセル内コードスパンではタグを文字列として保持し、閉じないバッククォートは通常の文字として扱います。通常部分ではバックスラッシュをパイプ・バックスラッシュ・`<`・バッククォートの前だけエスケープとして解釈し、エスケープされた`<`からは改行タグを認識しません。コードスパン内で解除するエスケープはパイプとバックスラッシュのみです。

変換は完全なCommonMark/GFMパーサーではありません。属性付きタグ、コードブロック、HTML構文の入れ子などは解析対象外です。複数表・結合セルには対応しません。

#### TSV解析と出力規則

TSVは状態機械で解析し、セル全体を囲む引用符、引用符内部の`""`、セル内タブ・改行、空セル・末尾空セルを扱います。行区切りはCRLF／LF／CRです。閉じない引用符、囲みの外の引用符、閉じ引用符後の区切り以外の文字はエラーです。引用符内の改行は解析時にはそのまま保持します。

空文字だけを空表とし、空白文字はセル内容です。最終改行1つは行終端として扱い、追加の空行は空セル1つの行として列数を検証します。`""`は空セル1つ、タブだけなら空セル2つです。

- TSV出力：行区切りCRLF、列区切りタブです。タブ・改行・引用符を含むセルを引用符で囲み、内部の引用符を二重化します。1列だけの空セルも`""`とし、空表と区別します。
- Markdown出力：`toMarkdown(table, options?)`はオプション省略時に従来の出力を保ちます。`alignments`は列ごとに`none`・`left`・`center`・`right`を指定し、`padding`は初期状態でオフです。出力時は外側パイプとASCIIスペース各1文字を付け、配置区切りを3ハイフン以上で生成します。バックスラッシュ・パイプ・バッククォートと文字列としてのbrタグをエスケープし、実際のセル内CRLF／LF／CRだけを`<br>`へ統一します。

`format.ts`はエスケープ後のセルソースを`string-width`で測り、ASCII・全角・半角カナ・絵文字・結合記号・エスケープ文字を含むMarkdown列幅を調整します。幅計測用の文字列だけNFC正規化し、未合成の結合記号もゼロ幅として扱います。出力セル値は変更しません。タブ・制御文字はそのまま保持しますが、タブ幅は表示環境に依存するため、こうしたセルの見た目が厳密に揃うことは保証しません。パディングによる出力全体は1,000,000 UTF-16文字までで、区切り・パイプ・改行を含めた正確なサイズを空白生成前に計算します。超過時はエラーとし、切り詰めません。

#### 安全な表プレビュー

Markdownプレビューは変換用パーサーの`TableData`を再利用して形と上限を確認し、表示用にMarkdownを別途解析します。Markdown→Excelでは入力Markdown、Excel→Markdownでは生成したMarkdownを表示します。`preview.ts`は遅延importし、`markdown-it` 15.0.3のトークン列から`table`・`thead`・`tbody`・`th`・`td`と、太字・斜体・取り消し線・コード・改行だけをDOM APIで作ります。配置は既知の3種だけ固定CSSクラスへ写します。`textContent`を使い、任意HTML、イベント属性、style、URLをDOM属性にしません。リンクは通常の文字、画像は代替テキストになり、外部リソースは取得しません。`<br>`、`<br/>`、`<br />`だけ改行要素として扱い、コード内・エスケープ済みのタグは文字列として表示します。

このパーサーはGFM系テーブルとMarkdown装飾のプレビュー専用で、変換解析と意味が異なる場合があります。連続バックスラッシュ数の偶奇を扱う既存解析に対し`markdown-it` 15は直前がバックスラッシュなら常にパイプをエスケープ扱いにするため、区切りパイプ直前に偶数本の2本以上がある場合はプレビューを停止して理由を出します。トークン表の行・列構造も変換結果と比較し、不一致時に理由を表示します。プレビューを止めても変換結果・コピー・XLSXは利用できます。

解析前にプレビュー入力を200行（ヘッダー含む）・50列・5,000セル・200,000 UTF-16文字以下に制限し、トークン列は50,000個までDOM化します。上限を超える場合は切り詰めずプレビュー理由を表示し、既存変換は続けます。プレビュー枠は横スクロール可能でキーボードフォーカスを受け取ります。

`markdown-it`はGitHubで使う表・装飾をトークンとして解析する目的で採用し、初回ツールロード後のプレビュー時だけ遅延ロードします。`string-width` 5.1.2はUnicodeの表示幅に使います。最新の9.0.0では`Intl.Segmenter`とUnicode `v`正規表現がブラウザimportに残り、対応対象のFirefox 114／Safari 16.4で既存変換を壊し得るため、Node 12以降と古いブラウザに対応する5.1.2に固定しました。依存はいずれもMITで、推移依存もlockfileで固定します。

Node 26／Vite 8.3.8の本番ビルドでは、初期アプリJSは14.10 kB（gzip 5.75 kB）で変更前と同じです。Markdown表ツールのJSは34.80 kB（gzip 11.02 kB、変更前8.96 kB／4.06 kB）、プレビューの遅延チャンクは101.48 kB（gzip 42.59 kB）、ツールCSSは3.16 kB（gzip 0.99 kB、変更前1.42 kB／0.56 kB）です。プレビューは初回描画でのみ読み込みます。既存のXLSX生成チャンクは952.39 kB（gzip 265.60 kB）のままです。

textareaはCRLFをLFへ正規化しますが、コピーは変換時に生成した同じ文字列を保持して使うため、TSVはCRLFのままコピーします。TSVをExcelへ貼り付ける際の数値・日付・数式への自動型判定は完全には制御できません。文字列型の確実な保持にはXLSX出力を案内します。

モデルの往復検証は矩形の文字列表（空表以外は1列以上）を対象とします。TSVはセル内のCRLF／LF／CRも含めて保持します。Markdownの完全一致の往復はセル内改行がLFのモデルに限り、CRLF／CRはLFに正規化した値を期待します。列配置の意味は維持しますが、原文の区切り文字数や構文上の余白は再現しません。パディングの追加空白はセル内容として残ることがあります。

#### XLSX生成

`xlsx.ts`はExcelJS 4.4から移行した`exceljs-community` 5.2.1（MIT）を使用します。既存のXLSX出力仕様を維持しながら依存を置き換え、ブラウザ用ビルドと文字列型・書式・列幅・折り返しのAPIを利用します。バージョンは固定し、推移依存はlockfileで管理します。現行のVitest設定でNode向けエントリが動作するため、専用aliasは設定していません。

ダウンロード時だけ`import('./xlsx')`し、入力・変換・TSVコピーでは読み込みません。ExcelJSを含む生成用コードは遅延チャンクとなるため、初期ロードに含まれません。具体的なバンドルサイズは固定仕様にせず、必要時に`npm run build`の出力で確認します。

出力ファイルは`table.xlsx`、ワークシート名は`Table`です。全セルを文字列で設定し、表示形式`@`、折り返し・上揃え、1行目太字とします。セル内のCRはOOXMLのエスケープ表現にしてXMLの改行正規化を避け、入力中のエスケープ風文字列も保護します。列幅は各行のセルを改行で分け、コードポイントが255以下なら1、それ以外なら2として数えた長さに余白2を加え、8〜60の範囲に制限します。ExcelJSによる幅9の列の省略を防ぐため、列にも表示形式`@`を設定します。

数式オブジェクトを使用しないため、先頭ゼロ、長い数字、日付風・数式風文字列を文字列型として保持します。上限は1,048,576行、16,384列、1セル32,767で、セル長はJavaScriptの`string.length`（UTF-16コード単位）で判定します。超過は切り詰めず生成エラーにします。XLSXのアップロード・読み込みには対応しません。

#### UI・非同期処理・破棄

初期方向はMarkdown→Excelです。方向・入力の変更で再計算し、空表ではコピー・ダウンロードを無効にします。Excel→Markdownでは各列の配置選択を表示し、列幅パディングは初期オフです。列設定UIは最大50列ずつ表示し、51列以上で範囲と全列数、前後ページ操作を表示します。全列の配置配列は保持し、ページ移動時もMarkdown出力へ反映します。ヘッダー表示とアクセシブル名は80 UTF-16文字で省略し、長いヘッダーによる設定欄の拡張を抑えます。列数が減少した際は末尾の配置を破棄し、現在ページを有効範囲へ戻します。パディングをオンにすると追加空白が再変換時のセル内容として残る注意を表示します。解析エラーやパディング出力上限時は古い結果とプレビューを消し、操作を無効にしてalertと`aria-invalid`で通知します。プレビューの解析差・上限超過は理由を別に案内し、変換結果・コピー・XLSXを維持します。Excel→Markdownではダウンロードボタンを隠します。クリアは入力・配置配列・ページを初期化し、入力欄へフォーカスします。列幅設定はツールを開いている間保持し、離脱時に入力・結果・配置・ページを破棄します。

#### 構文・図の意味・制約

regexppのECMAScript 2025として構造図を解析します。フラグは`d g i m s u v y`、`u/v`は排他です。別の「マッチ確認」機能は選択中の同じパターン・フラグを、そのブラウザのネイティブ`RegExp`で新規コンパイルしてテスト文字列へ適用します。regexpp解析・構造図とマッチ確認は別のWorkerと別の結果・エラー表示を使います。一方が受理しても他方の動作は保証しません。

- 連続文字は文字列、選択は並列経路、空の選択は「空（0文字）」とします。空白をtrimしません。スペースは`␣`、制御文字・不可視文字・XML非対応文字・単独サロゲートは可視のコードポイント表記にします。
- 文字クラス・範囲・Unicodeプロパティは原文を表示します。v集合の`&&`は共通部分、`--`は差集合と明記し、入れ子・`\q{…}`も保持します。集合を列挙・計算しません。文字列プロパティもパーサーの構文として受理します。
- `* + ? {m} {m,} {m,n}`と非貪欲形を、合計回数・優先順位のラベルと矢印付きの迂回・反復線で表現します。線だけで回数を決めず、ラベルの合計回数が制約です。巨大な回数も原文のラベルだけで示し、回数分のメモリを確保しません。`{0}`と`{0,0}`は本体を通りません。
- 捕捉グループにソース順の番号と名前を付け、非キャプチャと区別します。ECMAScript 2025の局所フラグも枠に明記し、`m/s`の変更は内部だけに反映します。選択肢間の重複名はregexppの規則に従います。
- 後方参照は点線の参照ノードと捕捉先番号で示し、捕捉先へ実行経路を接続しません。捕捉文字列に一致することと、未参加・前方参照が空文字列に一致し得ることを注意欄に明記します。
- アンカー・単語境界・肯定／否定先読み・後読みは**0文字の条件**です。主経路には条件ノードだけを置き、先読み・後読みの内部図は別セクションに置きます。後読みの内部はソース順表示で、実際の評価は右→左と明記します。入れ子の条件も独立した番号にします。
- `i`による文字集合の展開、検索開始位置、バックトラッキング順、全到達不能経路の判定は行いません。`d/g/y`は検索時の動作であり構造の分岐を増やしません。空の文字クラスには意味上の注意を出しますが、集合演算の結果が空になる場合などの完全な意味解析は行いません。

#### マッチ確認の動作と制約

「マッチを確認」ボタンの明示操作だけで起動し、テスト文字列の編集では自動実行しません。`match-protocol.ts`がWorker契約・上限、`match-runner.ts`が前段入力検証・Worker生成・世代管理・2秒期限、`match-worker.ts`がネイティブ`RegExp`のコンパイル・走査、`match-view.ts`が安全なDOM結果表示を担当します。Workerの実行制限を超えた場合はterminateし、部分結果を返しません。期限はWorker構築直前に始め、Worker起動時間を含めます。Workerの起動・実行エラーは図のエラーや図Workerの中止には波及しません。

初期の`lastIndex`は0です。`g`なしは最初の一致だけを返します。`g`ありは通常の`RegExp.exec`順で全体検索し、`y`があれば各`lastIndex`での一致だけを試します。空一致を繰り返す際は`u/v`ならUnicodeコードポイント、その他はUTF-16コード単位で次位置へ進み、入力末尾の空一致は一度だけ返します。マッチ全体の範囲は`match.index`と一致文字列の長さから求めます。`d`選択時はネイティブの`indices`から捕捉範囲を表示し、それ以外では捕捉の値と未定義／空文字の区別のみ表示します。結果の範囲はUTF-16コード単位の0始まり、終端を含まない位置です。

強調表示は画面上にあるテスト文字列をマッチ部分ごとのテキストノードと`mark`で構成し、入力文字列そのものは変更しません。ゼロ幅一致は空の視覚マーカー要素で示し、コピー対象文字を追加しません。ユーザー由来のパターン・入力・捕捉値・エラーは`textContent`またはテキストノードで挿入します。番号付き捕捉、名前付き捕捉（番号付きと同じ値を重複して含む）は閉じた`details`内に保持し、開いた時だけDOMを作ります。入力・共有パターンやフラグの変更、停止、クリア、IME変換、破棄では結果Workerを終了し、旧Worker・古いcapture開閉イベントを破棄します。テスト文字列編集は図解析へ影響しません。テーマ変更はマッチ結果とWorkerへ影響しません。

| マッチ確認の上限 | 動作 |
| --- | --- |
| パターン4,096 UTF-16コード単位、テスト文字列32,768 UTF-16コード単位 | UIとWorkerの両方で検証。超過時はWorker起動前に拒否 |
| 1,000マッチ | 1,000件を得た時点で走査を止め、実際にさらに一致があるか調べず「残り未確認」と示す |
| 捕捉値4,096件 | 番号付き・名前付きの各項目、未定義値、同じ値の重複を別々に計数。超過候補は格納しない |
| 返却文字列合計262,144 UTF-16コード単位 | 全一致文字列、各捕捉文字列、名前付き捕捉の名前を重複分も含め逐次検査。超過する候補は格納しない |
| Worker起動を含む2,000ms | deadline到達でWorkerをterminateし、部分結果を返さない。端末性能を問わず処理時間を保証する値ではない |

走査中にマッチ数・捕捉数・返却文字列上限へ達した場合は先行する完全な一致だけを返し、正確な総数とは誤認させず未確認の残りを明記します。各候補は保存前に、捕捉値・名前を配列へ加える前に累計上限を確認します。図とマッチ確認は入力・結果を外部送信せず、URL・History state・ログ・Cookie・永続ストレージへ保存しません。テーマ設定の既存保存はこの入力データと別です。

構文エラー、安全上限、描画エラーは区別してalertに表示し、構文エラーだけ入力を`aria-invalid=true`にします。regexppのエラー位置はUTF-16オフセットを1始まりで表示します。意味上の注意は構文エラーとは別欄です。空入力・空の選択・一致しない集合も明示的に描き、無言の空白を返しません。パーサーの診断本文は英語の場合があります。

図はmain.cssの既存カラートークンのライト／ダーク両配色と背景矩形・システムフォントをSVG内に持ちます。ホストのCSS変数がBlob内のSVGへ継承されないため、メインスレッドで保持するテーマ非依存の基本SVGに固定のdata-theme属性を追加して表示・保存します。テーマ変更はルート属性のMutationObserverで検知し、Workerの再起動・再解析は行いません。保存後は環境のテーマに依存せず保存時の配色を維持します。周辺UIは既存CSS変数を使用します。量指定子は上側に右向きの省略経路、下側に左向きの戻り経路をまとめ、囲み枠はグループに限定します。短い図と各セクションの経路は中央に配置します。デスクトップでは自然幅の80%を下限として表示領域に合わせ、モバイルでは原寸表示します。それ以上に広い図はキーボードで操作できる図の枠内に横・縦スクロールを限定します。保存するSVGは原寸のままです。

#### Worker・上限・リソース管理

`protocol.ts`にメッセージと共有定数、`runner.ts`にWorkerの生成・停止・世代管理、`worker.ts`に解析・描画の入口を分離します。UIは入力変更直後に旧図・警告・エラー・ダウンロードを無効化し、旧Workerをterminateしてから200msデバウンスします。IME変換中は停止し、確定後に更新します。空文字も解析対象です。「解析を中止」で待機・実行の両方を中断できます。

最新入力ごとにWorkerを作成し、結果返却時・エラー時・4秒タイムアウト時に停止します。キューに残ったイベントも世代番号で破棄します。ツール破棄時はWorker・デバウンス・期限タイマー・イベントリスナー・表示用URL・ダウンロード用URLを解放し、テーマ監視を解除します。画像のload/errorも入力世代・表示URLと破棄状態を確認し、旧画像イベントが新しい画面の操作を有効化しないようにします。

| 上限 | 理由 |
| --- | --- |
| 入力4,096 UTF-16コード単位 | 一般的な手書き式を収めつつ、Workerへの巨大な文字列コピーと解析前のメモリを抑える。超過はWorker起動前にも拒否 |
| 800 ASTノード・深さ48 | 小さな文字列でも選択・入れ子で膨らむ描画を抑え、再帰処理とDOM相当要素数を制限。regexppのVisitorで計測し循環参照をたどらない |
| 各辺16,000px・面積1,200万px | ブラウザの画像描画寸法とラスタライズ負荷を抑える。RGBA単一面相当は最大約48MBだが、実ブラウザの総メモリ量を保証する値ではない |
| SVG100万文字 | レイアウト後のシリアライズ・メインスレッドへの転送・Blob確保を制限 |
| Worker処理4秒（起動時間込み） | 解析自体の病的入力・低速環境でも強制終了し、UIを応答可能に保つ |

どの上限でも切り詰めた図は表示せず、分割を促します。AST制限より前のパーサー再帰エラーも制限として通知し、応答しないWorkerは期限で停止します。小さい端末や低速端末でも無制限の負荷にならないことを優先した上限です。

#### 入力・SVGの安全性とダウンロード

入力・結果・診断はURL、History state、ストレージ、ログに保存せず、外部送信・CDN・追加フォントも使いません。構造図Workerでは正規表現を実行しません。明示的なマッチ確認は別Worker内でネイティブRegExpをテスト文字列へ適用し、2秒deadlineでWorkerを終了します。正規表現の実行負荷にはこの期限と結果上限を適用します。ブラウザやOSがWorkerを即時終了できる保証ではありません。

描画要素は`svg/g/path/rect/circle/text/title/desc/style`だけをアダプターが生成し、属性・CSS・パスへユーザー入力を挿入しません。ラベルはXML特殊文字をエスケープし、XML 1.0非対応文字と単独サロゲートは可視化します。外部参照・リンク・イベント属性・スクリプト・foreignObjectは生成しません。UIの固定HTML以外は`textContent/value`で扱います。

SVG文字列を`innerHTML`へ挿入せず、`image/svg+xml`のBlob URLを`img.src`に設定します。画像読込失敗も明示して操作を無効化します。表示URLはテーマ更新・入力変更・破棄で解放し、ダウンロードは同じBlobから独立したURLを作り、1秒後または破棄時に解放します。ダウンロード直後の入力変更でも、表示URLの解放がファイル取得を妨げません。

### JST・UTC日時変換 — `datetime`／日時

#### 時計と24時間対応表

現在のJST・UTC年月日時分、詳細変換、JST基準の日付選択と24時間対応表の順にDOMへ配置します。表示・読み上げ・フォーカス順もこの順です。時計は60秒間隔とタブ再表示時に更新し、詳細入力を上書きしません。時計をライブリージョンにはしません。

表はJST 00:00〜11:00と12:00〜23:00のセマンティックな2表で、各表にJST・UTC・日付の見出しを設けます。CSS Gridで、サイドバーを含めても2表分の幅が取れる1100px以上の画面幅では横並び、それ未満では縦並びにします。狭い画面でページ横スクロールを必要としません。各captionは時間範囲を示します。UTCの時分と「前日／同日」を表示します。JST 00〜08時はUTCの前日、09〜23時は同日です。日付の初期値はJSTの今日で、「今日へ戻る」で復帰します。不正日付は補正せず、エラーを表示して両表を空にします。日付はロケールに依存しないテキスト欄へ`YYYY-MM-DD`で入力します。

選択日がJSTの今日なら現在の時間帯を背景色と「現在」で示します。選択行は左線・ボタン枠・「選択中」および`aria-pressed`で区別します。時刻ボタンは共通の親要素でイベント委譲し、キーボードでも選択できます。詳細欄をJST・表の日付・選択時刻の00秒に設定しますが、選択操作ではスクロールやフォーカスを強制しません。表下の「詳細変換欄へ戻る」操作時だけ詳細見出しにフォーカスし、スクロールします。History APIは変更しません。詳細の日時が表の行の瞬間と一致した場合も選択表示になります。

日付をまたいでも表の選択日付を自動変更せず、今日と異なれば現在時間帯のハイライトを消します。詳細欄のUTC選択や「現在時刻を入力」は表の基準日付を変えません。

#### 入出力・境界条件

詳細入力はJST／UTC、`YYYY-MM-DD`の日付、24時間制`HH:mm:ss`のテキスト欄です。時刻は`HH:mm`も受理し、秒省略時は00秒です。3つの日時欄は`type="text"`、プレースホルダーと補足で形式を明記し、`autocomplete="off"`・`spellcheck="false"`を設定します。入力マスクや自動補正は行わず、直接入力・貼り付け・キーボード編集をそのまま厳密に検証します。変更時に即座に変換します。「現在時刻を入力」は選択ゾーンの現在日時を秒まで固定形式で設定し、初回マウントでも現在のJST日時を設定します。

出力はJST日時・UTC日時（通常`YYYY-MM-DD HH:mm:ss`）、ISO 8601（UTC、末尾Z、秒精度）、整数のUnix秒・ミリ秒です。各値に個別コピーとreadonly欄を設けます。ISO・Unix timeは出力専用です。

入力年は0001〜9999年の先発グレゴリオ暦です。日付・時刻は厳密に検証し、不正値をDateの自動補正に任せません。1900年は平年、2000年はうるう年として扱います。24:00、うるう秒、ミリ秒入力は非対応です。不正入力では出力を消去し、コピーを無効にします。

変換境界の出力は0000年・10000年も扱います。例えば`0001-01-01 00:00:00 JST`のUTCは`0000-12-31 15:00:00`、`9999-12-31 23:59:59 UTC`のJSTは`10000-01-01 08:59:59`です。入力としてその年を受理するわけではありません。1970年以前の負のUnix timeにも対応します。

`logic.ts`はUnixミリ秒を基準とし、JSTを全期間UTC+09:00固定で計算します。歴史上の時差や夏時間を再現しません。UTC getterと`setUTCFullYear`を使い、0〜99年が1900年代になるDateの特殊処理と端末のローカルタイムゾーンへの依存を避けます。`Date.parse`による入力解釈は行いません。

#### コピー・破棄・主なテスト

コピー成功・失敗をstatusで通知し、入力更新の世代番号と破棄フラグで古い完了通知を抑制します。破棄時は時計タイマーを止め、AbortControllerで入力・ボタン・`visibilitychange`などのリスナーを解除します。

`logic.test.ts`は全24行、月末・年末・うるう年・0〜99年・入出力年境界、不正入力、秒省略、ISO・Unixの正負出力を検証します。epochの前後1秒と0秒、UTC／JSTの往復、入力範囲外になる境界出力も確認します。ローカル依存性はNode.js 26のTypeScript読み込みで別プロセスを起動し、`UTC`・`Asia/Tokyo`・`America/Los_Angeles`・`Pacific/Kiritimati`で夏時間切り替え日の変換・24時間表を比較します。`index.test.ts`は固定時計とfake timerで日付境界・再表示・破棄、コピー待機中の変更／破棄を確認します。

`index.test.ts`は前後半各12行と時系列、両表からの選択、11時台から12時台へのハイライト移動、不正な表日付からの復帰、固定形式・秒省略・詳細入力エラーからの復帰、時計とコピー競合・破棄を検証します。`tests/datetime.spec.ts`は固定時計と`America/Los_Angeles`のローカルゾーンで、表とハイライト、日付・行の選択、詳細変換、不正入力、実コピーと失敗、モバイル両テーマ、時間帯更新、切り替えを検証します。`tests/datetime-layout.spec.ts`はChromium・Firefoxで`ja-JP`／`en-US`、異なるブラウザタイムゾーン、1280pxでの2列、390px／320pxでの縦並びと横はみ出し、両表のキーボード／クリック選択、意図しないフォーカス移動の有無、明示的な詳細欄への復帰を確認します。クリップボード権限を使う既存の詳細コピー検証はChromiumのみです。

### 画像変換 — `image-converter`

`encoder.ts`はJPEG・PNG・WebP・JPEG XLのシグネチャとAVIFのISO BMFF `ftyp` を確認し、指定があればMIME型も照合します。AVIFでは通常サイズ・拡張サイズ、ファイル長、ブランド配列の4バイト境界を検証し、majorまたはcompatible brandの `avif`・`avis` を受け付けます。これらの形式は、画像要素と `createImageBitmap` でブラウザ標準のデコーダーを使って読み込みます。ファイルサイズを先に制限し、画像要素の寸法・画素数をビットマップ生成前に確認します。一時的な入力URLは読み込みの中止・成功・失敗時に解放します。JPEGは白を塗ってから画像を描き、PNGは透明な画布に描きます。`toBlob`の結果が空または指定MIME型と違う場合は失敗です。出力サイズと品質の対応はブラウザに依存します。

Oxipngは `@jsquash/oxipng` 2.3.0の単一スレッド生成コードをWorkerから直接読み込み、画像をBrowser PNGにエンコードしてから再圧縮する段階を設けず、Canvasの8-bit sRGB RGBA ImageDataを `optimise_raw` へ渡します。Workerはデコード済みImageBitmapの複製を受け取り、OffscreenCanvasに描いて `getImageData(..., { colorSpace: 'srgb' })` で画素を正規化し、その後にBitmapとCanvasを解放してからWasmを呼びます。レベルは1〜6で初期値2、インターレースと完全透明画素のRGB最適化は初期状態でオフです。レベル5・6は時間がかかる場合があり、より高いレベルが小さいファイルを作るとは限りません。完全透明画素のRGB最適化は完全透明な画素だけを対象にし、そのRGB値を変更する場合があります。

左右は各自のOxipng設定をメモリ内に保ち、入力世代・レベル・インターレース・完全透明画素最適化を組にして同一出力を共有します。実行中は消費側を記録し、片側が設定変更・入力確定・中止・破棄で離れても他側の要求が残れば処理を続け、最後の消費側が離れるとAbortControllerでWorkerを終了します。完了Blobは表示中の側がある間だけマップに残るため、最大2件です。異なる設定は共有Workerキューで直列化します。キュー待機は中止でき、Web Locks対応ブラウザではWorker自身も共通のロックを取得して `terminate()` 後にブラウザがWasmを回収するまで保持します。Web Locksのない環境ではメインスレッドのFIFOキューで実行中Workerを1つに制限します。AVIF、Jpegli、MozJPEG、WebP、JPEG XL、JPEG 2000、画質評価も同じキューとロックを使います。

このWasmが保つのは、入力のブラウザ正規化後の8-bit sRGB RGBA画素です。元ファイルのビット深度・ICCプロファイル・EXIFなどのメタデータやアニメーションの保持は保証しません。出力は静止PNGです。入力は他の変換と同じ32 MiB、8,192px、1,600万画素の上限を使います。最大寸法でのWasm高水位割り当ては実ブラウザ・端末で別途確認し、端末のメモリにより上限内でも失敗することがあります。圧縮結果はSSIMULACRA2の採点対象外です。

パッケージと同梱Wasmの供給元・バージョン・チェックサム、単一スレッド生成物を選んだ理由、ライセンス表示は `public/licenses/oxipng/` に記録します。npmパッケージの汎用エントリーポイントが宣言する `wasm-feature-detect` は使わず、生成済み単一スレッドGlueと静的Wasm URLをWorker内で動的ロードします。初期画面や他ツールではOxipngのJavaScript/Wasmを取得しません。出力例 `sample-right-oxipng-o2.png` は元名・左右・圧縮レベルを表します。

#### AVIF (libaom)

`@jsquash/avif` 2.1.1の内部モジュール `codec/enc/avif_enc.js` と同梱の単一スレッド版Wasmを使います。依存するネイティブライブラリはlibavif 1.0.1、libaom 3.7.0、SharpYUV 0.4.0です。ViteはWorkerとWasmを `/web-toolbox/` 配下で配信し、AVIF出力の選択時に同一オリジンから取得します。エンコード専用ビルドを選択することで、配信するAVIFのWasmは1本です。Worker間の排他はWeb LocksまたはFIFOを使い、SharedArrayBufferやクロスオリジン分離を必要としません。 [依存関係と第三者ライセンス](../public/licenses/avif/NOTICE)

Workerは複製されたImageBitmapを受け取り、OffscreenCanvasから取得した8-bit sRGB RGBAをエンコーダーに渡します。Wasmを実行する前にBitmapとCanvasを解放します。Workerで各辺8,192px・1,600万画素の制限と画素長を確認し、エンコード後にも出力の `ftyp` を検証します。静止画のプレビューと評価にはブラウザのデコーダーを使います。画像の色はsRGBに正規化します。jSquashの出力はCICPの色原色と伝達特性を未指定とし、検証対象ブラウザではsRGBとして表示します。 [ChromiumのAVIF色管理](https://chromium.googlesource.com/chromium/src/+/ff5d6077839fe16c5a01a6ef6c2e796efdee1b0b/third_party/blink/renderer/platform/image-decoders/avif/avif_image_decoder.cc)

`avif/options.ts` が設定範囲と初期値を管理します。可逆圧縮を選ぶと品質100・透明度品質100・4:4:4を適用し、設定欄にも実効値を表示します。解除時には保持していた値を再表示します。3値がすべて一致するとlibavifはRGBをidentity行列で格納し、正規化後のRGBAを保持します。チェックボックスの状態と独立した実効設定から、画質評価の可否、共有キーと保存名を決めます。速度は0〜10を渡し、libavifの速度9と10は同じ最速プリセットになります。デノイズ、タイル分割、SharpYUV、チューニング等はjSquashの既定値を使います。

左右の実効設定が一致する間は、入力世代・エンコーダー・品質・透明度品質・速度・色差サンプリングで実行中のジョブと完了Blobを共有します。利用側がなくなった時点で、取得・初期化・変換中のWorkerは終了します。入力の確定や設定の変更で、世代が一致しない変換・プレビュー結果を失効させます。変換・プレビューは `image/avif` のBlobを扱い、保存名の拡張子は `.avif` です。Firefoxはファイルの取り扱い設定に従って、保存後にAVIFを新しいタブで開く場合があります。

Workerは複製したImageBitmapをOffscreenCanvasで白背景に合成し、8-bit sRGB RGBAに正規化します。各辺8,192 px以下、総画素数16,000,000以下、RGBA長を検証し、Wasm取得の前にBitmapとCanvasを解放します。画像処理はブラウザ内で完結します。WorkerとWasmは選択時に `/web-toolbox/` の同一オリジンから取得します。JPEGの入力、プレビュー、採点にはブラウザ標準のデコーダーを使います。出力は8-bit sRGBの静止画で、元のICCプロファイル、EXIF、HDR、広色域、ビット深度は保持しません。

Qualityは1〜100の整数、Distanceは0.1〜25.0の0.1刻みです。各側が両方の値を保持し、選択中の指定方式だけを符号化に使います。Qualityは公式 `jpegli_quality_to_distance()` で変換し、`jpegli_set_distance()` の `force_baseline` をTRUEにします。初期値はQuality 90、保存されるDistanceは1.0、4:4:4、Progressive Level 2、適応量子化とハフマン最適化はオンです。4:4:4、4:4:0、4:2:2、4:2:0で輝度の水平・垂直サンプリング係数を変更してからDistanceを設定し、量子化テーブルのサンプリング補正を選択形式に合わせます。レベル0はSequentialで、レベル1・2はハフマン最適化を強制します。レベル0では各側に保存していた最適化設定を使用します。

変換は既存の共有WorkerキューとWeb Locksを通ります。180msのデバウンスを使い、入力世代・現在の指定方式と値・サンプリング・Progressive Level・適応量子化・実効ハフマン設定が一致する左右でジョブと完了Blobを共有します。最後の利用側が離れると待機・取得・符号化を取り消します。入力と設定の世代を照合し、キャンセルや切り替え後の結果を破棄します。ファイル名は `sample-left-jpegli-q90-444-p2-aq-opt.jpg`、`sample-right-jpegli-d1.5-420-p0-aq-noopt.jpg` の形式です。Quality 100を含むすべてのJpegli出力に既存のSSIMULACRA2評価と制限を適用します。

Wasm ABIはRGBAポインター、バイト長、幅・高さ、画質指定方式と値（Distanceは10倍の整数）、圧縮設定、結果領域のポインターを受け取ります。C++は線形メモリ内の入力・結果領域とその非重複を確認し、`JCS_EXT_RGBA` で行を渡します。ラッパーが出力バッファを所有し、再確保の成否を確認します。エラーコールバックをWasmのC++例外で処理し、上流の一時オブジェクトのデストラクターを実行して圧縮器と出力を解放します。成功時に結果領域へ出力ポインターと長さを書き込みます。TypeScriptは符号化後の現在の線形メモリから結果を独立したArrayBufferにコピーし、入力、出力、結果領域を解放します。フレームの寸法とサンプリング、Sequential・Progressiveのマーカー、上流のレベル別スキャン順序、EOIを検証します。4:4:4のProgressiveではDCを1スキャンにまとめ、それ以外では成分ごとに分けます。

#### JPEG XL (libjxl)

エンコーダーはlibjxl 0.13.0（コミット `5a7da83447212fe4900fc29ce97430b881caa67e`）です。Highway 1.2.0とBrotli 1.2.1はリリースに対応するコミットを使い、色管理のskcmsはICCパーサーの修正を含む公式コミット `074a8d439d75df5bff2746458306f7760ee74dd8` を使用します。供給元と各ソースのSHA-256はビルドスクリプトとライセンスのディレクトリに記録しています。skcmsは展開後に正規化したソースツリーを照合します。 [供給元とチェックサム](../public/licenses/jxl/DEPENDENCIES.txt)

`bash scripts/jxl/build.sh` でソースを取得してSHA-256を検証し、WebP・MozJPEGと同じダイジェストのLinux amd64 Emscripten 4.0.20コンテナをネットワーク無効で実行します。Releaseの `-O3`、LTO、Wasm SIMDを使った単一スレッド静的リンクで、線形メモリは16 MiBから最大1 GiBまで拡張できます。CLI、テスト、ベンチマーク、画像入出力ライブラリ、多スレッド処理、JPEG再構築を対象から外します。通常のViteビルドとCIはリポジトリ内のWasmを使用します。SharedArrayBufferやクロスオリジン分離は不要です。 [再現ビルド](../scripts/jxl/build.sh)

リンクレポートとWasmエクスポートを確認しました。Brotliはエンコーダーと共通部、skcmsはCMSの実装とベースライン変換をリンクします。HighwayのSIMDコードはヘッダーから取り込まれます。libjxlの静的アーカイブからは、パッチ辞書の生成に使う内部フレームデコードなど、符号化に必要な共有コードを選択します。公開JPEG XLデコーダーのエントリーポイントとBrotliデコーダーはリンク対象から外しています。

Cラッパーは各呼び出しの前に前回の出力を解放し、幅・高さとRGBA長を照合します。公開C APIでフレームを追加し、`JxlEncoderProcessOutput` の結果を必要に応じて拡張する出力バッファに蓄積します。終了時にエンコーダーを破棄し、成功時のみ出力ポインターと長さを公開します。TypeScriptは `JxlEncoderVersion` を照合し、符号化後の現在のメモリビューから結果をコピーして入力と出力の確保領域を解放します。

入力の形式判定はraw codestreamの `FF 0A` と12バイトのJPEG XLコンテナシグネチャを受け付けます。MIME型が指定されていれば実データと照合し、拡張子は形式判定に使いません。プレビュー可否は2 × 2の有効なJPEG XLに対する `HTMLImageElement.decode()` で、入力可否は同じ画像要素からの `createImageBitmap(image)` で確認します。プレビューが非対応の場合は両側のJPEG XL出力選択肢を無効化し、入力の非対応も明示します。入力は標準デコーダーの画像読み込み、寸法確認、ビットマップ生成を既存形式と共通に行います。実際の各出力も画像要素でデコードしてから表示します。評価Workerは `createImageBitmap(Blob)` を同じ小画像で試し、非対応の場合はJPEG XLの採点だけを除外します。Chromium Headless Shell 159.0.8154.6とFirefox 159.0では既定設定で3経路が利用できました。

Workerは入力のImageBitmapを複製して受け取り、OffscreenCanvasで8-bit sRGB RGBAへ正規化します。BitmapとCanvasを解放してからWasmを取得し、符号化結果を線形メモリから独立したArrayBufferにコピーしてシグネチャを検証します。ViteのWorkerとWasmはJPEG XL出力選択時に `/web-toolbox/` の同一オリジンから取得します。画像と変換結果の処理はブラウザ内で完結し、デコードもブラウザ標準機能で行います。

可逆・非可逆でアルファのDistanceは0です。libjxl 0.13.0はDistance 10以上で色の再サンプリング倍率を自動で2にし、アルファの倍率も同じ値以上にします。アルファを元の解像度で保持するため、色とアルファの倍率を両方とも1に指定します。色のDistanceは非可逆時に0.1〜15.0を0.1刻みで設定し、初期値は1.0です。可逆時は0を表示して操作を無効にし、各側の非可逆設定は保持します。Effortは初期値7で範囲は1〜10の整数です。符号化時に、可逆では `JxlEncoderSetFrameLossless` と完全透明画素のRGB保持を指定し、非可逆では `JxlEncoderSetFrameDistance` を指定します。保証範囲はCラッパーに渡した正規化後のRGBA値です。Canvasの色管理・アルファ処理の前後で画素値が変わる場合があります。出力は8-bit sRGBの静止画です。

設定変更は180msデバウンスします。ジョブと完了Blobの共有キーは入力世代・実効Distanceの10倍整数または可逆モード・Effortです。可逆時の保存名は `sample-right-jxl-lossless-e7.jxl`、非可逆時は `sample-right-jxl-d1.0-e7.jxl` の形式です。待機・取得・変換中の中止は既存の共有WorkerキューとWeb Locksを利用し、最後の利用側が離れるとジョブを取り消します。入力世代と左右の変換世代を照合して最新のプレビューだけを反映します。可逆出力はSSIMULACRA2による採点から除外します。

libjxl 0.13.0は上流のセキュリティ修正を含み、Brotli 1.2.1にはCVE-2026-111497の修正が含まれます。libjxlのCVE-2026-82522はコンテナデコーダーの脆弱性で、採用バージョンには修正が含まれます。skcmsはCLUTとICCタグ番号の境界検査を修正した公式コミットに更新しました。エンコーダーは正規化済みのRGBAと固定sRGBを入力とし、入力ファイルのビットストリームとメタデータはブラウザのデコード経路で扱います。各ライブラリとEmscriptenランタイムのライセンス・著作権表示、およびNOTICEをサイトに同梱します。 [libjxlのリリースノート](https://github.com/libjxl/libjxl/releases/tag/v0.13.0) · [libjxlのアドバイザリ](https://github.com/advisories/GHSA-8q4m-qc33-25q8) · [skcmsのCLUTに関するアドバイザリ](https://osv.dev/vulnerability/OSV-2026-600) · [skcmsのタグ番号に関する報告](https://issues.chromium.org/issues/530237174) · [第三者ライセンス](../public/licenses/jxl/NOTICE)

#### JPEG 2000 (OpenJPEG)

JP2（`.jp2`）はシグネチャとPart 1の `ftyp` を確認し、J2K（`.j2k`、`.j2c`）はSOCとSIZマーカーで識別します。MIME型があればJP2とJ2Kを照合します。空のMIME、汎用JPEG 2000型、`application/octet-stream` はJPEG 2000のシグネチャが合う場合に受け付けます。入力・出力ともOpenJPEGを使い、ブラウザのJPEG 2000デコーダーやJPEG XLの対応状況に依存しません。WorkerとWasmはJPEG 2000の入出力時に同一オリジンから取得します。

正式リリースは2.5.4が最新でした。OSV-2025-219は2.5.4を影響範囲に含み、修正 `91d08b11a72764f6d199f32fa0c1b1abd4edc2ad` は `d33cbecc148d3affcdf403211fddc2cc5d442379` で上流にマージされています。採用した `8314119b067c0fc77834731168daaebd379fdb12` はこれらに加え、符号化側の整数オーバーフロー修正（CVE-2026-6192、#1628）と、インターリーブされたタイルパート（#1644）およびMCO（#1666）のデコード修正を含みます。CVE-2026-107080には、上流PR #1674のゼロ高に対する境界チェックをローカルパッチとして適用します。上流リポジトリは保守停止と明記しています。 [正式リリース](https://github.com/uclouvain/openjpeg/releases/tag/v2.5.4) · [OSV-2025-219](https://osv.dev/vulnerability/OSV-2025-219) · [採用コミット](https://github.com/uclouvain/openjpeg/commit/8314119b067c0fc77834731168daaebd379fdb12) · [CVE-2026-107080](https://security-tracker.debian.org/tracker/CVE-2026-107080) · [上流修正PR](https://github.com/uclouvain/openjpeg/pull/1674) · [上流の保守状況](https://github.com/uclouvain/openjpeg/pull/1654)

`scripts/openjpeg/build.sh` は固定したソースをSHA-256で照合し、ダイジェストを固定したLinux amd64のEmscripten環境でネットワークを遮断してWasmをビルドします。独立した2回のビルドでWasmのSHA-256が一致しました。通常のViteビルドとCIは同梱Wasmを使います。単一スレッドのStandalone Wasmに符号化・復号を含め、O3、LTO、Wasm SIMDを有効にします。入力と出力はメモリ経由で、CLIや外部画像入出力ライブラリはリンクしません。線形メモリの上限は1 GiBです。 [ビルドスクリプト](../scripts/openjpeg/build.sh) · [供給元、再現手順、ライセンス](../public/licenses/openjpeg/DEPENDENCIES.txt)

非可逆はPSNR（20〜60 dB、初期値40）または圧縮率（2〜100、初期値10）をOpenJPEGに直接指定します。指定方式の初期値はPSNRです。可逆時は両方の値を保存したまま無効化します。符号化には非可逆で9/7 DWTとICT、可逆で5/3 DWTとRCTを使います。1品質レイヤー、LRCP、64×64コードブロック、色差サブサンプリングなし、最小辺に応じて最大6段の解像度を選びます。不透明な画像はRGB、透明度がある画像はRGBAを格納し、後者にはJP2のチャンネル定義でアルファを示します。可逆圧縮はWasmへ渡す時点の画素値を保持します。正規化や再表示ではブラウザの色管理とCanvas・ImageBitmapのアルファ丸めが適用されます。

外部ファイルは32 MiB、各辺8,192 px、1,600万画素までです。WasmラッパーはJP2ボックスとコードストリームの範囲、およびSIZマーカーの寸法・成分・タイル数を事前検査します。ヘッダー解析後は成分数・ビット深度・位置・寸法・サンプリングを再確認し、入力を4,096タイルと768 MiBの推定復号バッファ容量で制限してから画素を展開します。sRGB、グレースケール、対応するアルファとsYCCを8-bit sRGB RGBAへ正規化します。色空間の指定がないJ2Kは1成分をグレースケール、3成分をRGBと扱います。ICC、CMYK、パレットカラー、乗算済みアルファなど対応外の構成はエラーになります。出力に元のICC、EXIF、HDR、広色域、ビット深度は引き継ぎません。ヘッダー検査に加え、共有キューとWeb Locksの排他制御、Worker終了による中止、Wasm上限を適用します。 上流で未解決のデコード時のリソース枯渇（CVE-2019-6988、CVE-2023-39327・39328・39329）が残ります。別の入力を選ぶかツールを閉じると、進行中の読み込みを中止できます。 [Debianのセキュリティ追跡情報](https://security-tracker.debian.org/tracker/source-package/openjpeg2)

変換Worker内で入力ImageBitmapを8-bit sRGB RGBAに正規化し、同じインスタンスで符号化と結果の復号を行います。符号化用のWasmバッファを解放してから復号し、JP2のバイト列とプレビュー用ImageBitmapを移譲します。比較にはCanvasを使い、保存、容量と増減率、採点キャッシュにはJP2 Blobを使います。入力世代と実効設定をキーに、同じ条件の左右で変換ジョブ・Blob・ImageBitmapを共有します。180msの設定デバウンス中も一致する要求を追跡し、最後の利用側が離れると未完の処理を中止し、完了済みならビットマップを閉じます。CanvasとObject URLの解放は各側が担当します。採点には非可逆出力のプレビュー画像を複製して移譲します。保存名は設定に応じて `sample-left-openjpeg-psnr40.jp2`、`sample-right-openjpeg-r10.jp2`、`sample-right-openjpeg-lossless.jp2` などになります。

#### JPEG 2000の実測

Linux x86_64のCodexコンテナ（Xeon Platinum 8573C、CPU割当2コア、メモリ上限8 GiB）で、Node.js 26.13.0、Playwright 1.65.1、Chromium Headless Shell 159.0.8154.6を使いました。計時を挿入した同じ本番ビルドをローカルの `/web-toolbox/` で配信し、PSNR 40 dBで4サンプルを各1回ずつ逐次変換しました。時間はWorker内の `encodeJp2Pixels` と `decodeJp2Pixels` の呼び出し前後で、Wasmとのバッファコピーと解放を含みます。取得・初期化、入力の正規化、ImageBitmap生成、Canvas描画、評価は計時区間の外です。線形メモリは変換用Wasmの `memory.buffer.byteLength` で、符号化直後と復号直後は同じ値でした。ブラウザプロセス全体のメモリ使用量は計測していません。SSIMULACRA2は同じブラウザで手動評価しました。

#### 比較操作とリソース管理

エンコーダーの表示名・MIME型・拡張子・品質指定の有無を `encoder.ts` に定義し、`index.ts` では共通のテンプレートから左右の設定パネルを生成します。入力を一度デコードして得たビットマップを左右で共有します。Originalはビットマップを描いた共通Canvasを使い、保存時は元のファイルを返します。変換結果は各側の画像要素またはJPEG 2000用のCanvasに表示し、入力画像のCSSピクセル寸法で中央配置します。ステージの高さは入力画像の縦横比を基準に決め、画面高の65%を上限にします。左右の見出しはステージ内に重ね、`pointer-events: none` で比較線・パン操作を妨げません。画像レイヤーも同様にポインターを受けません。画像レイヤーを左右別の固定ビューポートでクリップして透明画素から反対側が透けるのを防ぎます。比較位置は境界バー上の単一の数値状態で管理し、ビューポート上のCSSクリップ位置を変更します。境界バーはPointer EventsとPointer Captureで操作できるARIA sliderで、矢印キーは1%、Shift併用は10%、Home・Endは両端へ移動します。ドラッグ中のタッチスクロールを抑え、境界バーの操作をパンへ伝播させません。25〜400%のズームとパンは各出力に共通の表示変換を適用し、表示領域基準の比較位置には影響しません。倍率ボタンはステージ直下に配置し、位置の変更では変換・画質評価を起動しません。パンは画像がビューポートより小さい軸では中央に置き、大きい軸では端が見える範囲に制限します。

各側が選択形式、形式ごとの設定、変換状態、結果Blob、Object URL、変換世代を持ちます。設定変更時はその側の結果と保存操作を無効化し、最後の設定入力から180ms待って処理します。設定が一致する場合は、同じ入力に対する反対側の実行中の変換または成功済みのBlobを使います。結果URLは各側で個別に発行し、設定変更・入力変更・破棄時に解放します。保存名には元の名前を基に左右と変換形式に応じた設定を含めます。読み込み済み画像のファイル名・寸法・元サイズは「画像を変更」操作と同じ領域にまとめます。左右のカードには形式と選択中の形式に応じた設定欄を表示します。容量タイルには元サイズ・出力サイズ・符号付き増減率を並べ、丸め前のバイト数から方向を判定します。減少は緑、増加は黄、同じサイズは中立色で示し、増減率を丸めた結果が+0%や-0%になる場合も、元のバイト数で方向を判定します。Originalは元ファイルを使うため0%です。評価スコアと容量タイルは狭い画面で縦に並び、保存ボタンはカード全幅です。

サンプル一覧のDOMは画像選択ボタンと比較・変換セクションより前に固定し、選択状態が変わっても一覧を移動・再生成しません。列数はコンテンツ幅に応じて最大4列にし、モバイルでは2列にします。各カードはサムネイル・名前・寸法・形式・サイズを表示します。詳細は狭い幅でも折り返して表示し、寸法・形式・ファイルサイズをボタンのアクセシブルな名前にも含めます。選択中は強調表示と `aria-pressed` で示し、次の画像を読み込み中は現在の選択を維持します。画像本体と軽量なサムネイルは `public/samples/` に置き、URLはViteの `BASE_URL` を基準に組み立てます。画像本体はボタンを押した時点で `fetch()` し、ファイル名とMIME型を指定して `File` にします。デコードと変換は通常のファイル選択・ドロップと同じ処理を通り、選択中の出力形式・変換設定・自動評価設定を使います。 [素材と再生成手順](sample-images.md)

ファイルやサンプルを選ぶと候補の読み込み世代を進め、前の候補を `AbortController` で中止します。取得とデコードの完了時に現在の候補かを確かめ、古い候補から遅れて届いたビットマップを閉じます。候補の読み込み中や失敗時も、表示中の入力世代・比較結果・評価を維持します。デコードと新しい表示Canvasへの描画が成功した時点で入力世代を進め、旧評価・変換タイマー・Object URL・ビットマップを解放し、旧Canvasの寸法をゼロにして置き換えます。変換・プレビュー完了時は入力世代と各側の変換世代を照合します。変換用Canvasは完了時に寸法をゼロにし、ツール破棄時は候補の読み込み、表示中の画像のリソース、イベントリスナーを解放します。

サンプルの取得・デコードに成功したとき、比較プレビューが画面外ならステージを最小限スクロールして表示します。プレビューが既に画面内、読み込み中、失敗時にはスクロールせず、サンプルボタンのフォーカスを保ちます。

初回のドロップボタンは読み込み成功後に非表示になります。ボタンにフォーカスがある場合は「画像を変更」ボタンへ移します。両ボタンは同じファイル入力を開きます。初回のボタンと比較画像エリアはファイルのドラッグを受け付け、それぞれでdragenter/dragleaveの深さを追跡して子要素間を移動するときも強調表示を維持します。

元画像と左右の出力サイズは `encoder.ts` の `formatFileSize()` で表示します。1,000 B未満は整数B、1,000 B以上1,000,000 B未満はKB、1,000,000 B以上はMBとし、1 KB = 1,000 B、1 MB = 1,000,000 Bです。KB・MBは日本語ロケールで小数点以下最大2桁に整形します。元ファイル比は表示用に丸める前のバイト数から「（出力サイズ − 元ファイルサイズ）÷ 元ファイルサイズ × 100」で求め、Originalでは元ファイルを使うため0%です。

#### SSIMULACRA2

画質評価はBrowser JPEG、JPEG (Jpegli)、JPEG (MozJPEG)、非可逆AVIF、非可逆WebP、非可逆JPEG XL、非可逆JPEG 2000の出力Blobを元画像と比較します。Originalは「基準画像」、Browser PNGは「画質評価は未対応」、Oxipng、可逆AVIF、可逆WebP、可逆JPEG XL、可逆JPEG 2000は「可逆圧縮（スコア評価対象外）」と表示します。評価対象の欄には実測スコアのほか、変換待ち、未評価、評価待機中、評価中、失敗、評価制限を表示します。評価の実行・中止と自動評価の切り替えは、左右のカードの下にまとめます。採点準備前とWorker側で、各辺8 px以上かつ10,000,000画素以下かを共通の `quality/rules.ts` で検査します。元の寸法で採点し、通常変換・保存には画像入力の制限を適用します。

`quality/client.ts`は入力のデコード済みImageBitmapを複製してWorkerへ移譲し、評価対象のBlobまたはプレビュー画像を渡します。Browser JPEGのエンコーダーはHTML Canvasの `toBlob` を使用します。JPEG 2000にはプレビューのImageBitmapの複製を移譲し、評価時の再デコードを省きます。評価Workerは他の形式のBlobを標準APIでデコードします。すべての形式で`paint.ts` の白背景描画をエンコーダーと共有して、元画像と同寸法の8ビットsRGBに正規化します。比較色はブラウザのデコードと色管理に依存します。元画像のEXIF向きは既存のデコード結果に従い、変換JPEGに元のメタデータが保持されることは前提としません。アルファ自体の採点、広色域・HDRの精度保証、異なるブラウザ間の数値一致は対象外です。

「画質の自動評価」は初期状態でオンになり、設定はツールの表示中だけ保持します。画像入力や形式・品質変更から800ms経過し、対象出力の変換とプレビューの準備が完了した時点で自動評価を開始します。画像の読み込みが済んでからオンに切り替えた場合も、操作から800ms待ちます。品質変更の変換には既存の180msデバウンスを使います。評価用タイマーは変換完了時に残りの待機時間がある場合だけ設定します。「画質を評価」は変換完了後すぐに実行します。

評価は単一のWorkerで直列に実行します。採点直前に未評価の出力Blobを選び、入力世代と実行中のジョブを照合して結果を反映します。入力ごとの `WeakMap<Blob, number>` で同一Blobの結果を共有します。設定変更時は変更側の旧スコアを即時失効させ、反対側の有効なスコアを保持します。新しい入力の確定、設定変更、「評価を中止」、ツール破棄は待機と実行を取り消し、自動評価をオフにしたときは自動評価だけを取り消します。手動中止や失敗の後は、画像・形式・品質の変更、手動評価、またはオフからオンへの切り替えで再開します。

対象Blobがある場合だけWorkerを起動し、完了・中止・失敗で終了します。中止は採点エラー表示の対象外です。採点エラーが発生しても、変換と保存はそれぞれ利用できます。有限のスコアは負値や100を超える値も含めて小数1桁で表示します。

`worker-slot.ts`の共有FIFOキューはAVIF、Jpegli、MozJPEG、Oxipng、WebP、JPEG XL、JPEG 2000、画質評価のWorkerを同時に1つだけ実行します。Web Locks APIが使える環境では各Workerが共通ロックを取得し、ブラウザがWorkerを破棄するまで保持します。`terminate()` から実際の破棄まで時間がかかる場合に、次の処理は同じロックの解放を待ってWorkerを起動します。ロック待ちとFIFOキュー待ちは中止できます。Web Locks APIのない環境では、FIFOキューが現在のWorkerの完了または終了まで次を待ちます。

## テスト方針

### 単体テストとカバレッジ

[vitest.config.ts](../vitest.config.ts)はNode環境を既定として`src/**/*.test.ts`を実行し、モックを復元します。DOMやブラウザ固有のAPIを必要とするテストファイルだけに`// @vitest-environment jsdom`を指定し、実際の依存関係と検証対象に応じて環境を選びます。これにより、DOMに依存しない変換処理、通信、署名検証、JSON、XLSX、Worker処理では不要なjsdom初期化を避けます。純粋な変換処理の境界値・不正入力・Unicodeに加え、UIの非同期完了、通信中止、リスナー・タイマーの破棄を検証します。Playwrightは実ブラウザでのレイアウトや操作を検証し、Vitestによる単体テストと責務を分担します。ツール固有の対象は前節にまとめています。

共通基盤では`router.test.ts`がURL・標準リンク操作・履歴通知、`tool-host.test.ts`が遅いimportの成功／失敗と新画面の競合、ホーム遷移、破棄契約、`components/home.test.ts`がRegistry順のカードと未ロード、`components/theme.test.ts`がOS追従・手動保存・ストレージ拒否・購読解除を検証します。

`npm test`は通常のVitest実行、`npm run test:coverage`はV8 Coverageを有効にし、`text`と`json-summary`を出力します。`coverage.include`は`src/`のJS/TSコード全体を指定し、未importのソースも対象にします。test/spec・`__tests__`・型宣言を除外し、起動処理・共通UI・ルーター・ホスト・8ツールを含めます。最低閾値は設定せず、Playwrightのカバレッジを合算しません。Vitestと`@vitest/coverage-v8`は同一の完全バージョンに固定しています。

### E2Eと検証範囲

[playwright.config.ts](../playwright.config.ts)はビルド済み`dist/`をVite previewで配信し、`http://127.0.0.1:4173/web-toolbox/`を使用します。E2Eコマンド自体はビルドしないため、事前の`npm run build`が必要です。サーバーは既存プロセスを再利用せず、指定ポートで起動します。CIでは`test.only`を禁止し、診断用に失敗時に1回再試行します。`failOnFlakyTests: true`により再試行でのみ成功したケースもコマンドを失敗させ、失敗時のtraceを保持します。

Firefoxではスモークに加えて既存の`tests/ip-address-layout.spec.ts`を実行し、IP欄の高さ・折り返し・画面幅への追従を両テーマで維持します。詳細なコピー・ダウンロード・IME・モバイル操作などはChromium中心とし、Firefoxへ全ケースを複製しません。WebKitはSafari系のフォーム・レイアウト差の検出に有効ですが、追加ブラウザとOS依存の配備・実行のCI負荷が増えるため今回は追加しません。Safari固有の検証が必要になった時点で共通スモークへの追加を検討します。

## JWTデバッガーの詳細

`sample.ts`に公開学習用のUTF-8 Secretと、事前にHS256署名した固定Compact JWSを定義します。mount時に入力へ設定して既存のdecodeを実行し、署名は未検証のまま操作を待ちます。共有Secretは`type="text"`で平文表示し、デバッグ時に値を確認できます。ブラウザやパスワードマネージャーによる保存確認が抑制される保証はありません。初期デモSecretはJWT入力変更時に消去しますが、Secretを手動編集した時点で初期値扱いを解除し、以後のJWT変更では保持します。アルゴリズム変更とクリアでは従来どおりキーを消去します。クリア後は空のまま、再読み込み・ツール復帰による新しいmountでのみサンプルを再設定します。入力やキーは保存しません。

`jwt-debugger`をテキスト・データカテゴリへ登録。`logic.ts`は256KiBのUTF-8入力上限、3セグメント、厳密なBase64URL（非ゼロ末尾ビットも拒否）、fatal UTF-8、JSONオブジェクトを検証し、形式別エラーを返します。Header/Payloadは配列・nullを拒否。署名空欄はnoneのデコード用途として許容します。

Claimsはiss/sub/aud/exp/nbf/iat/jtiを説明し、audの文字列配列も扱います。NumericDateは有限数値で評価し、expは現在時刻がexp以上で期限切れ、nbfは現在時刻が到達したら利用可能、未来iatは警告のみです。UTC/JST双方のDate表現範囲を確認し、小数秒の比較はNumber値で行います。表示はDateのミリ秒精度、JSTはUTC+09:00固定です。1秒ごとに端末時計で再評価し、破棄時にタイマー解除します。発行者・Audienceの期待値照合、時計ずれ許容値は扱いません。

`verify.ts`は検証操作時のみバンドル済みjoseを動的importし、compactVerifyで署名だけを確認します。明示選択したHS256/RS256/ES256の許可リストとHeaderのalg一致を要求し、importSPKIとjose/Web Cryptoでキー種別・曲線等を確認します。none、その他alg、b64:falseやcrit拡張は検証不可。Base64 Secretはパディングを含む標準Base64を厳密にデコードします。エラーは固定メッセージに置換し、入力やライブラリエラーをログに出しません。

UIは安全なvalue/textContent、readonly出力、独立したClaims・署名状態を使用します。入力・キー・方式変更、クリア、破棄で世代を更新し、検証・コピー完了時に世代と破棄状態を確認します。中止不能な暗号処理は完了後の表示を抑制し、破棄時はリスナー・タイマー・DOM入力と表示をクリアします。JavaScript文字列やWeb Crypto内部メモリの物理消去は保証できません。外部取得、URL/History/ストレージ/Cookie保存は行いません。

画面のDOM順はEncoded JWT、Signature、Decoded（Header、Payload、署名検証）、Claims・日時評価です。52rem以上ではコンテナクエリで入力・Signatureを左列、Header・Payload・署名検証を右列に配置し、Claimsを両列の下へ全幅で表示します。それより狭ければDOM順の一列表示となり、ビューポートではなくツールの実幅に追従します。左右列は内容に応じた高さを保ち、入力欄を右列に合わせて伸ばしません。デコード状態は入力近くに未入力・デコード済み・デコード失敗を表示します。署名検証は未検証・検証中・署名一致・署名不一致・検証不可をアイコン、文言、状態別バッジで示し、検証不可の理由と鍵長警告を別表示します。デコード、署名、Claims・日時評価は独立した評価です。Claimsの項目は狭い幅では1列、52rem以上では2列で、各説明のdt/ddを組にして表示します。JWT入力・Header・Payload・Signatureは対応ブラウザーで内容に合わせて高さを変え、それぞれ12rem・18rem・24rem・9remを上限とする内部スクロール領域です。縦方向の手動リサイズに対応し、JWT変更時はインライン高さを解除して内容に合わせ直します。`field-sizing: content`非対応ブラウザーではtextareaの`rows`値を初期高さとして使います。

隣接Vitestテストは形式・Unicode・NumericDate境界、元JSONの巨大整数・小数・指数表記の保持とコピー、実際にテスト用キーで署名したHS256/RS256/ES256の成功・不一致・改ざん・不正キー・非対応alg、デコード・検証の状態表示、入力変更によるリセット、UI競合・破棄・非保存を検証します。`tests/jwt-debugger.spec.ts`は実署名、実Clipboardによるコピー成功とモック失敗時の手動コピー、直接アクセス・再読み込み・履歴、ライト／ダーク両テーマの320/768/1280/1920px、幅の動的切替、新しいDOM順と2列／1列配置、Claimsの1/2列切替、長いJWT・Claim値の折り返しと横はみ出し、キーボード、forced-colors、非通信・非保存を確認します。

JWTの表示・コピーは`json.ts`で構文検証済みの元JSONを字句単位に走査し、文字列外の空白のみ整形します。数値トークン・文字列リテラル・キー順・重複キーを保持し、Number値の再出力は行いません。深いJSONの出力膨張を抑えるためインデントは32階層で上限にします。`decodeJwt`は元のUTF-8文字列、表示JSON、解析済みオブジェクトを分離して返します。

日時Claimsはトップレベルの数値トークンをNumberの最短十進表記と係数・桁位置で比較します。丸め、オーバーフロー、アンダーフローで十進値が変わった場合は日時・期限判定を控え、精度警告を表示します。通常の0.1等の小数は従来どおり受理します（IEEE 754の二進表現が十進小数と完全一致することは要求しません）。巨大指数を展開せず、重複キーはJSON.parseと同じく最後の値に対応させます。表示の精度保持と、Number／Dateによる評価・ミリ秒表示の制約は独立しています。

JWT入力・Header・Payloadの色分けは`highlight.ts`が元の表示文字列を字句走査し、`textContent`とテキストノードだけで描画します。JSONの数値・エスケープ・重複キーを再生成しません。JWTの3セグメントはオレンジ・パープル・グリーン、JSONのキー・文字列・数値・真偽値/nullはブルー・グリーン・オレンジ・パープルで表示します。各色はライト／ダーク別のツール内CSS変数で定義します。

操作とコピー・デコード・検証の正本は従来の`textarea.value`です。背面の`pre`は`aria-hidden`・`pointer-events: none`とし、フォント・行高・余白・折り返しを揃え、scrollイベントとResizeObserverで表示領域とスクロールを同期します。変換中のIME、forced-colors、印刷、ResizeObserver非対応環境では通常のtextarea文字表示を使用します。字句が不正な場合、表示文字列が256Ki UTF-16コード単位を超える場合、JSONの表示トークンが2,048個を超える場合も色分けを省略し、非表示層のレイアウト負荷を避けます。これは描画専用の制限で、デコード・署名検証の256KiB上限や可否を変更しません。表示層の文字列を解析・コピーに使わず、破棄時は監視とイベント・表示内容を解放します。

ハイライト単体テストでは分類、ネスト・配列・Unicode、数値リテラルと文字列の完全保持、HTMLの安全性と描画上限を確認します。UI単体テストでは表示層の改変が検証・コピーへ影響しないこと、監視の破棄、描画上限とデコードの独立性を確認します。JWT E2Eでは両テーマ、選択コピー・貼り付け・Undo/Redo、長文の折り返し・スクロール・リサイズ、320px、IMEイベントとforced-colorsへの切り替えを検証します。IMEは合成イベントによる確認で、実際のOS IMEやSafari/WebKitは自動検証の対象外です。
