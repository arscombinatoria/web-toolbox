# Web Toolbox — アーキテクチャーと初期仕様

## 1. 状態と前提

第7段階でトップページを追加。JST・UTC日時変換まで実装済み。第2段階の共通基盤は維持する。Registry、共通レイアウト、History APIによる遷移、テーマ、マウント・破棄と読み込み競合制御、CI/CDを備える。4つの初期ツールはすべて利用可能。

サイト名はWeb Toolbox、リポジトリ名は`web-toolbox`。Vanilla TypeScript、Vite、HTML/CSS、Vitest、必要最小限のPlaywright、GitHub Actions、GitHub Pages、Node.js LTSを採用する。UIフレームワークとバックエンドは導入しない。

指定仕様に構成上の矛盾はない。「入力データを外部送信しない」原則に対してIP確認APIは明示的な例外とする。API提供元には接続元IP等が伝わるが、他ツールの入力を送信してはならない。

以下の「採用する設計」は実装を進めるための判断。「推奨初期仕様」は要件にない詳細の提案で、最後の未決事項と併せて実装時に確定する。

## 2. モジュール構成（採用する設計）

```text
src/
  main.ts                 # 起動と画面遷移の統括
  router.ts               # History APIと標準リンク操作
  tool-host.ts            # マウント・破棄と読み込み競合制御
  registry.ts             # メタデータ、型、遅延読み込み関数
  components/             # ホーム（home.ts）、共通レイアウト、サイドバー、テーマ切り替え
  styles/                 # デザイントークン、共通スタイル
  tools/
    ip-address/
    width-converter/
    datetime/
    markdown-table/
tests/                    # Playwrightの主要シナリオ
public/                   # 必要な静的アセットのみ
docs/
  architecture.md
.github/workflows/        # CIとmainからのPages公開
```

各ツールは必要に応じて`index.ts`（DOMとイベント）、`logic.ts`（純粋関数）、`logic.test.ts`（Vitest）に分ける。IP通信はUIから分離した関数とし、通信のテストは単体テスト側に置く。空のディレクトリや不要なファイルは先に作らない。ルートの`index.html`と各種設定は基盤段階で作成済み。

Registryのエントリーは`id`、`name`、`description`、`category`、`load`を持つ。`load`は固定のモジュールパスを指定する動的importであり、一覧表示だけでツール本体を読み込まない。IDは一意かつ安定させ、`categories`の配列順をカテゴリ順、`tools`の配列順をカテゴリ内の表示順とする。共通型はRegistryにまとめ、抽象化のためだけに別階層を設けない。

ツールモジュールの基本契約は`mount(container: HTMLElement): () => void`。マウント自体は同期的に行い、通信等は内部で開始する。返された破棄関数はリスナー、タイマー、AbortController、購読を解放する。破棄済みのUIを非同期コールバックが更新しないようにする。

切り替え制御側は世代番号等で現在の遷移を識別する。動的import自体はキャンセルできないため、読み込み完了後も最新の遷移か確認する。旧ツールを破棄してコンテナを片付け、ロード中・ロード失敗を表示できるようにする。ツールAからBへ素早く切り替えてもAが遅れてマウントされないことを保証する。

## 3. URLとGitHub Pages（採用する設計）

- 公開URLは`https://<owner>.github.io/web-toolbox/?tool=datetime`等。クエリ方式なのでPages側のSPAフォールバックや独自404は不要。
- 同一サイト内のツールリンクは現在のURLを基に`URL`/`URLSearchParams`で構築し、パスと無関係なクエリを維持する。
- 通常の選択操作は`pushState`と画面更新、`popstate`はURLから再描画するだけとし、履歴を追加しない。同一ツールの再選択で不要な履歴を作らない。
- 修飾キー付きクリック等の標準リンク操作を妨げない。直接アクセスと再読み込みでも同じツールを表示する。
- `/web-toolbox/`（`tool`未指定時のみ）はトップページを表示する。ルーターのIDは未指定を`null`、空IDは空文字として区別する。不明ID・空IDは従来どおり説明と有効なツールへの導線を表示し、URLを勝手に置換しない。
- 個別URL `?tool=ip-address`、`?tool=width-converter`、`?tool=markdown-table`、`?tool=datetime` は維持する。ヘッダーのブランドリンクとサイドバー先頭の「ホーム」（モバイル共通）で戻れ、ホームURLは`tool`のみ削除する。
- Viteの公開用`base`は`/web-toolbox/`。アセットはimportまたは`import.meta.env.BASE_URL`に基づいて参照し、`/assets/...`のようなドメインルート固定を避ける。
- ビルド成果物を実際のサブパスで配信して検証する。カスタムドメイン等へ移す場合はbaseを明示的に変更する。

ホームはRegistryのツールではなく`components/home.ts`で表示する。カードのID・名前・説明・順序は`tools`から生成し、デスクトップは2列、モバイルは1列のリンク一覧とする。ツールの機能一覧は第5節を参照。ホームのタイトルは`Web Toolbox`、ツールは従来の`ツール名 | Web Toolbox`。ホーム表示ではツールのloadを呼ばず、ipify・ExcelJS・外部リクエストを発生させない。

`tool-host.show`は`null`をホーム、`undefined`を不明ツールとして扱う。ホーム遷移も世代番号を更新してツールを破棄し、旧importの成功・失敗による上書きを防ぐ。ホームも破棄関数を返し、遷移後の見出しフォーカスは共通処理で行う。

## 4. 共通UIと安全性

デスクトップはカテゴリ別の左サイドバーと右メイン。モバイルは開閉式とし、開閉ボタンに`aria-expanded`と対象を設定する。隠れたリンクをフォーカス可能にしない。オーバーレイ方式を選ぶ場合はEscapeで閉じ、閉じた際のフォーカスを戻す。選択リンクに`aria-current`を付け、画面切り替え後の見出しへのフォーカスやページタイトルを整える。

色・余白・角丸等はCSS変数で管理する。ライト／ダーク両方でフォーカス、文字、エラー、選択状態が判別できるようにする。動きは控えめにし、`prefers-reduced-motion`を尊重する。

テーマは、手動選択がない間は`prefers-color-scheme`に追従し、選択したライト／ダークのみlocalStorageに保存する。「システム」で保存を解除でき、ストレージが利用できなくても動作する。`index.html`の短いスクリプトでスタイル適用前に手動設定を復元し、未設定時の初期配色はCSSのメディアクエリで決定する。入力内容・変換結果の永続保存は初期スコープ外とする。

モバイル（幅760px未満）は同じサイドバーを標準`dialog`へ移動して表示し、ネイティブのモーダル制御とTab端点の循環でフォーカスを制限する。閉じている間は`hidden`でリンクをフォーカス対象から外す。Escape・背景クリック・閉じるボタンではメニューボタンへ、ツール選択では表示後の見出しへフォーカスを移す。

コピーにはClipboard APIを使い、成功・失敗を通知する。権限拒否や非対応時は手動選択・コピー可能な出力を残す。状態通知は支援技術にも伝え、リアルタイム変換のたびに全文を読み上げさせない。

外部フォント、解析サービス、外部スクリプト等は追加しない。MarkdownをHTMLとしてプレビューする機能もスコープ外。外部レスポンスも信頼せず、型・形式を検証する。

## 5. 初期ツール

### IPアドレス確認 — `ip-address`／ネットワーク

- IPv4は`https://api.ipify.org?format=json`、IPv6は`https://api6.ipify.org?format=json`から並行して取得する。`api64.ipify.org`は使用しない。ローカルIPの探索は行わない。
- 再取得、コピー、ローディング、エラー、タイムアウトを提供します。位置情報は取得しません。
- 外部APIを使うことと接続元IPが提供元へ伝わることを画面に明記する。
- HTTP失敗、通信失敗、JSON不正、`ip`欠落、IPv4／IPv6形式不正を区別可能な内部エラーとして扱い、利用者には分かりやすく表示する。
- AbortControllerで時間切れ・再取得・アンマウント時に中止し、タイマーを必ず解放する。古いリクエストの結果が新しい結果を上書きしないようにする。
- 確定仕様：ツール表示時に取得、タイムアウト10秒、自動リトライなし。切り替えによる中止を通信エラーとして通知しない。
- `index.ts`がUI・コピー・破棄を担当し、`api.ts`が通信・HTTP判定・unknownのJSON検証・IPv4／IPv6検証・中止・タイマー解放を担当する。IPv4は4オクテット（0〜255）の十進表記とし、先頭ゼロ、符号、空白、IPv6を拒否する。IPv6は8グループの16進表記、1回だけの`::`省略、末尾IPv4埋め込み表記に対応する。過剰・不足グループ、不正な16進数、空白、角括弧、ポート、ゾーンIDは拒否する。両形式の通信・タイムアウト処理は`api.ts`内で共有する。
- `cache: no-store`、`credentials: omit`、`referrerPolicy: no-referrer`を指定する。追加ヘッダーや識別情報は付与しない。IPはストレージ・ログへ保存しない。
- IPv4・IPv6は独立した表示・取得状態・コピーボタンを持つ。一方の失敗で他方の成功結果を消去しない。先に成功したアドレスは他方の完了を待たず表示・コピーできる。共通の再取得ボタンは両方の通信が終わるまで無効にし、開始時に両方の旧IPを消去する。取得中・成功・通信エラー・HTTPエラー・タイムアウト・形式エラーを区別する。readonly入力（IPv6は折り返し可能なtextarea）で手動選択を可能にし、成功時のみClipboard APIによるコピーを有効にする。各取得状態とコピー結果は別のpoliteなstatusで通知する。
- UI内のAbortController識別と破棄フラグにより古い取得・コピー結果を無視する。tool-hostは動的importの競合、ツールは自身の通信の破棄を担当する。
- `api.test.ts`・`index.test.ts`で通信とUIの失敗・中止・破棄を検証する。Playwrightの共通fixtureで全E2Eのipifyをモックし、実サービスには通信しない。`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`で検証する。実API接続は別途確認が必要。
- IPv6欄は`rows="1"`を基本とし、取得開始・成功時とウィンドウのリサイズ時に`scrollHeight`と枠線幅から高さを再計算する。折り返し時にも全体を表示し、手動リサイズは無効にする。Chromium／Firefoxで動作するよう`field-sizing`には依存せず、resizeリスナーは破棄時に解除する。
- 各IPバージョンの接続環境、DNS、提供元の稼働状況、CORSに依存する。IPv6取得失敗をIPv6非対応と断定しない旨を画面に明記する。失敗時に別サービスへ無断で切り替えない。

### 全角・半角変換 — `width-converter`／テキスト・データ

- 確定仕様：全角→半角、半角→全角のラジオボタンと、英数字・記号・カタカナ・スペースの独立したチェックボックスをfieldset/legendでグループ化する。初期値は全角→半角、英数字・記号・スペースON、カタカナOFF。全OFFでは入力をそのまま出力する。
- `logic.ts`の純粋関数`convertWidth(input, direction, categories)`が変換を担当し、`index.ts`が入力・設定変更、IME、コピー、破棄、`style.css`が既存CSS変数を使うライト／ダーク・レスポンシブ表示を担当する。入力値は書き換えず、readonly textareaへ結果を表示する。
- 英数字はASCII英数字と対応する全角英数字。記号はASCII U+0021–U+007Eから英数字を除いた文字と全角U+FF01–U+FF5Eの対応のみ。チルダU+007E ↔ U+FF5E、バックスラッシュU+005C ↔ U+FF3Cを含む。波ダッシュU+301C、円記号U+00A5、U+FFE5は保持する。
- カタカナは半角U+FF61–U+FF9Fに対応するカナ・小書き・長音・中黒・句読点・濁点を扱う。日本語句読点はカタカナ側に統一し、記号の選択に依存しない。対応表生成時の半角1文字と濁点の組、半角→全角変換時の既知の半角カナと任意の濁点（半角または結合文字）だけをNFKCで正規化する。全文へのNFKCは適用しない。
- 合成済みガ・パ・ヴ・ヷ等と、対応するカナ＋結合濁点・半濁点を扱う。全角→半角では結合濁点U+3099・U+309Aおよび幅のあるU+309B・U+309Cを半角U+FF9E・U+FF9Fへ変換する。逆方向の単独半角濁点は結合文字U+3099・U+309Aへ変換する。結合不能な組は基底文字と結合文字を保持するため、全Unicodeで完全な往復一致は保証しない。
- スペースはU+0020とU+3000のみ。タブ・改行・その他の空白、丸数字・ローマ数字・ひらがな・ヵ・ヶ・ヮ等の対応がない文字、未選択カテゴリは保持する。初期設定で`ＡＢＣ１２３！＠＃　ガギグ`は`ABC123!@# ガギグ`になる。
- `compositionstart`で変換中にし、変換中や`InputEvent.isComposing`がtrueの入力イベントは更新を抑える。`compositionend`で解除して更新し、その後の最終inputも受け付けてイベント順序の差異に対応する。設定変更も変換中は更新を保留する。
- Clipboard APIの成功・失敗は`role="status"`で通知し、出力全文はライブリージョンにしない。手動選択を常に可能にする。コピー待機中は連打を防止し、入力・設定変更後の古い通知は世代番号で抑制する。破棄フラグで非同期完了後のDOM更新を防ぎ、AbortControllerで全リスナーを解除する。
- 入出力は外部送信せず、URL・ログ・localStorage等にも保存しない。ツール切り替え時に入力を破棄する。変換の対応範囲・非対応例を画面とREADMEに記載する。
- `logic.test.ts`で各カテゴリ、両方向、濁点・小書き・ASCII全範囲・半角カナ全範囲・非対象Unicodeを検証する。Playwrightは初期設定、設定変更、リアルタイム更新、IMEイベント順序、コピー成功・失敗と保留中の切り替え、手動選択、入力非保存・非送信、長文のモバイル両テーマ表示を検証する。既存のIP確認E2Eは維持する。

### 日時・UTC変換 — `datetime`／日時

- 第6段階の確定仕様。現在のJST・UTC年月日時分、JST基準の日付選択、24時間対応表、詳細変換の順に表示する。
- 表はJST 00:00〜23:00の24行。UTC時刻と前日／同日を表示。初期日付はJSTの今日。「今日へ戻る」で復帰できる。入力が不正ならエラーとし、補正せず表を空にする。
- 選択日がJSTの今日なら現在の時間帯を背景色と「現在」で示す。選択行は左線・ボタン枠・「選択中」で区別。各行のボタンはキーボード操作可能で、選択により詳細をJST・表の日付・その時刻の00秒に設定する。
- 時計は60秒間隔とタブ再表示時に更新する。時計にライブリージョンは設定しない。日付が変わっても表の選択日付は保持し、今日と異なればハイライトを消す。破棄時にタイマーと全リスナーを解除する。
- 時計の更新では詳細入力を上書きしません。
- 詳細入力はJST／UTC、日付、時分秒のみ。変更時に即座に変換する。「現在時刻を入力」は選択ゾーンの現在日時を秒まで設定する。表の基準日には影響しない。
- 出力はJST日時・UTC日時（YYYY-MM-DD HH:mm:ss）、ISO 8601（UTCの末尾Z、秒精度）、整数のUnix秒・ミリ秒。それぞれ個別コピーとreadonly欄による手動選択を提供する。ISO・Unix timeは出力専用で、入力フォームは設けない。
- 入力年は0001〜9999年（先発グレゴリオ暦）。変換で範囲をまたぐ出力は0000年・10000年を許す。ミリ秒入力と、うるう秒は非対応。負のUnix timeは対応する。
- `logic.ts`の純粋関数で厳密に年月日・時刻を検証し、Unixミリ秒を基準に変換する。JSTは全期間UTC+09:00固定。UTC getterとsetUTCFullYearを使い、0〜99年の1900年代への変換やローカルタイムゾーン依存を避ける。Date.parseによる入力解釈はしない。
- コピー成功・失敗はstatusで通知し、入力変更・破棄後の古いコピー完了は無視する。外部送信・永続保存は行わない。CSS変数で両テーマ・モバイル・フォーカス表示に対応する。
- Vitestは24行、日付・年・うるう年境界、不正入力、ISO・Unix出力、fake timerによる時計と破棄を検証。Playwrightは固定時計とAmerica/Los_Angelesのローカルゾーンで主要操作・コピー・両テーマ・切り替えを検証する。

### Markdown表変換 — `markdown-table`／テキスト・データ

- 第5段階の確定仕様。`logic.ts`の`TableData = { rows: string[][] }`を共通モデルとして、純粋関数`parseMarkdown`、`parseTsv`、`toMarkdown`、`toTsv`で解析・出力する。UIとXLSX生成は別モジュール。列数不一致は全方向でエラーとし、補完・切り捨てをしない。
- Markdownは単一表のみ。先頭行がヘッダー、2行目が必須区切り（`---`、`:---`、`---:`、`:---:`、ハイフン3個以上）。外側パイプは省略可能。前後の空行は無視、途中の空行はエラー。空白のみの入力は空表。連続バックスラッシュの偶奇でパイプを判定し、コードスパン内でもパイプはエスケープ必須。
- セル両端のASCIIスペース各1文字だけを構文上の余白として除去する。それを超える空白、タブ、全角空白は内容として保持する。幅揃え目的の多数のスペースも内容になる。外側パイプの外の空白は無視する。外側パイプと端の空セルの曖昧さを避けるため、空セルを含む表は外側パイプ付きの出力形式を推奨する。
- Markdown装飾やHTMLエンティティは解釈せず保持する。通常の`<br>`、`<br/>`、`<br />`（大小文字不問）のみLFにする。同じ長さのバッククォート列で閉じたセル内コードスパンでは改行タグを変換しない。閉じないバッククォートは文字扱い。バックスラッシュでエスケープした`<`も改行にしない。バックスラッシュはパイプ・バックスラッシュ・`<`・バッククォートの前のみエスケープとして解釈する。完全なCommonMark/GFMパーサーではなく、属性付きタグ、コードブロック、HTML構文の入れ子、複数表、結合セルは非対応。
- TSVは状態機械で解析する。セル全体を囲む引用符、内部の`""`、タブ、CRLF/LF/CR、空セル・末尾空セルに対応する。閉じない引用符、囲みの外の引用符、閉じ引用符の後の文字はエラー。最終行の改行1つは行終端として扱い、追加の空行は空セル1つの行として検証する。空文字だけは空表、空白文字はセル内容。セル内の改行は解析時には保持する。
- TSV出力は行区切りCRLF。タブ・改行・引用符を含むセルを引用符で囲み、引用符を二重化する。Markdown出力は標準`---`、外側パイプとASCIIスペース各1文字、行区切りLF。バックスラッシュ・パイプ・バッククォートと文字列のbrタグをエスケープし、セル内CRLF/LF/CRを`<br>`に統一する。配置情報は失われる。HTMLプレビューはしない。
- `xlsx.ts`はExcelJS 4.4（MIT）を使用。ブラウザ用ビルドと、文字列型・書式・列幅・折り返しのAPIがあり、独自ZIP/XML生成を避けるため採用した。追加の直接依存は`exceljs`のみ（ZIP等の推移依存はlockfile）。ダウンロード操作でのみ`import('./xlsx')`し、入力・TSVコピーでは読み込まない。Vite出力は独立した約930 kB（gzip約257 kB）のチャンクとなり、サイズ警告は残るが初期ロードには含まれない。
- ワークシート名は`Table`。全セルを文字列で設定し、表示形式`@`、折り返し・上揃え、1行目太字。列幅は文字数（非Latinは2幅）を参考に8〜60で制限する。数式オブジェクトは使用せず、先頭ゼロ・長い数字・日付風・数式風文字列を保持する。Excel上限（1048576行、16384列、1セル32767文字）超過は生成エラー。XLSXアップロードは非対応。
- UIは既存の全角・半角変換に合わせたfieldset、ラジオ、ラベル付きtextarea、クリア・コピー・ダウンロード、status/alert、CSS変数による両テーマ・狭幅対応。入力・方向変更で再計算し、エラー時は古い結果を消去して操作を無効化。入力・結果を送信・永続保存しない。TSVのExcel貼り付けは自動型判定を完全に制御できず、文字列の確実な保持にはXLSXを案内する。
- コピー・生成中の連打を防ぎ、世代番号と破棄フラグで古い非同期完了を無視する。リスナーはAbortControllerで破棄。Object URLはダウンロード開始後1秒またはツール破棄時に解放する。
- Vitestは各純粋関数・引用符の不正入力・空白・エスケープ・改行・数値風文字列と、実XLSX生成後の再読み込み（セル型・値・書式・幅）を検証。Playwrightは本番ビルドで方向切替、結果更新、実Clipboard APIと失敗、遅延チャンク、実ダウンロードと再読み込み、モバイル両テーマ、既存ツールへの切替を検証する。

## 6. 検証とCI/CD

Vitest + V8 Coverageで単体テストのカバレッジを計測します。`vitest`と`@vitest/coverage-v8`は同一の完全バージョンに固定し、更新時も同時に変更します。`npm test`は単体テストを実行し、`npm run test:coverage`は追加で`text`と`json-summary`を出力します。`coverage.include`で`src/`配下のJS/TSコード全体を指定し、未importのファイルも0%として含めます。テスト（test/spec、__tests__）と型宣言のみ除外し、各ツール、ルーター、画面ホスト、起動処理・共通UIを対象とします。最低閾値は設けず、PlaywrightのE2Eカバレッジは合算しません。

CIは`npm ci`の後、`npm run test:coverage`、Node.js標準のバッジ生成テスト（`npm run test:badge`）、`npm run build`、Playwrightの順に実行します。型チェックは`build`内の`npm run typecheck`で行い、Viteビルドの前に実行します。Playwright成功後、`main`へのpushに限り`scripts/generate-coverage-badge.mjs`が`coverage/coverage-summary.json`の`total.lines.pct`を検証して`dist/coverage.svg`を生成し、Pages成果物に含めます。READMEは公開SVGを参照します。数値欠損・不正JSON・範囲外等はエラー終了し、計測値を補完しません。生成ファイルはGit管理せず、外部バッジサービスや追加トークン・権限は使用しません。

Vitestは変換処理の境界値・不正入力・Unicodeの特殊ケースを中心にする。具体例は濁点の結合／分離、変換対象外の互換文字、うるう年、日付境界をまたぐJST／UTC変換、秒とミリ秒、パイプとバックスラッシュ、末尾空セル。外部APIはモックし、正常・タイムアウト・不正レスポンス・中止を検証する。

Playwrightは直接URL、ツール切り替え、戻る／進む、遅いimportや通信の競合、代表的な入力→結果、モバイルサイドバーとキーボード操作に絞る。単体テストの全ケースを重複させない。ブラウザ側の通信もモックし、CIから実APIを叩かない。

`playwright.config.ts`のChromiumプロジェクトは主要シナリオ全体を実行し、Firefoxプロジェクトは`ip-address-layout.spec.ts`のみを実行します。後者は両テーマでIPv4欄との高さの比較、IPv6の長短・取得失敗時の表示、1920pxと320px間のリサイズによる折り返し・高さの伸縮、全体の表示と手動選択を検証します。Firefoxで他ツールの主要操作を検証する設定ではありません。ブラウザの準備には`npx playwright install --with-deps chromium firefox`を使用します。E2Eは事前ビルドした`dist/`をVite previewで`http://127.0.0.1:4173/web-toolbox/`に配信し、既存サーバーを再利用せず検証します。

Node.js 24 LTSを`.nvmrc`と`engines`で固定する。PRと`main`へのpushで型チェック、Vitest、Viteビルド、Playwrightを実行する。基盤の単体テストはjsdomで読み込み競合・破棄・テーマ・標準リンク操作を検証し、E2Eは本番ビルドのサブパス配信で4画面・履歴・テーマ復元・モバイル操作を確認する。

`.github/workflows/ci-pages.yml`は`main`へのpushに限り、CI成功後に公式Pages Actionsで`dist/`を`github-pages` environmentへデプロイする。基本権限は`contents: read`、デプロイジョブのみ`pages: write`と`id-token: write`を使用する。PRは古い実行をキャンセルし、Pagesデプロイは直列化する。PagesのSourceはGitHub Actionsに設定する（README参照）。実公開はマージ後に別途確認する。

## 7. 確定事項と後続段階の未決事項

確定済みの技術スタック・4ツール・クエリ方式を変更する提案はない。次の細部は推奨初期仕様をたたき台として実装時に確定し、本書とテストへ反映する。未決を理由に基盤実装全体を止める必要はない。

| 項目 | 推奨・判断が必要な点 |
| --- | --- |
| 初期表示・不明ID（確定） | `tool`未指定でホーム、空・不明IDは案内表示 |
| テーマ（確定） | 手動選択のみ保存、未選択時はOS追従、「システム」で解除 |
| IP取得（確定） | 表示時取得、10秒タイムアウト、自動リトライなし、キャッシュ不使用 |
| 全角・半角（確定） | ASCII／半角カナの対応範囲に限定、単独濁点は結合文字、初期値は全角→半角・英数字／記号ON。詳細は第5節 |
| 日時（確定） | JST基準24時間表、秒精度、入力0001〜9999年、ISO・Unixは出力専用。詳細は第5節 |
| Markdown／TSV（確定） | 引用符付き複数行セル、文字列XLSX、空白・エスケープ規則は第5節 |
| ツール切り替え | 初期案は入力を引き継がない。保持が必要なら別途仕様化 |
| 実行・公開環境（確定） | Node.js 24 LTS、モダンブラウザ（主要E2EはChromium、IP欄のレイアウトはFirefoxでも限定検証）、mainからActionsでPages公開 |

後続は、個別の依頼範囲で各ツールの処理とテストを追加する。初期4ツールは実装済み。入力履歴・永続保存はスコープ外。
