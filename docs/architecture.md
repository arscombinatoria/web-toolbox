# Web Toolbox — アーキテクチャー仕様

## 概要・設計方針

Web Toolboxは、GitHub Pagesで配信するバックエンドのない静的SPAです。ホーム画面と、IPアドレス確認・全角／半角変換・Markdown表変換・JST／UTC日時変換の4ツールで構成します。本書は現行実装の内部設計、変換規則、制約、設計判断と検証範囲を記載します。利用方法と開発手順は[README](../README.md)、エージェント向けの実装規約は[AGENTS.md](../AGENTS.md)を参照してください。

Vanilla TypeScript（strict）、ES Modules、Vite、HTML/CSS、ブラウザ標準APIを使用します。UIフレームワークや状態管理ライブラリは使用せず、各ツールのDOM操作と通信・変換処理を分離しています。共通UIはRegistryのメタデータから生成し、ツール本体は必要時に読み込みます。

入力・結果は画面内で扱い、ツールを離れると破棄します。IP確認の外部API通信と、手動選択したテーマの保存については[セキュリティ・データ保護](#セキュリティデータ保護)に記載します。

## システム構成・モジュール構成

主要ファイルの構成は次のとおりです。Vitestのテストは対象モジュールに隣接し、E2Eは`tests/`に配置しています。

```text
web-toolbox/
  index.html                       # HTML、スタイル適用前のテーマ復元
  package.json / package-lock.json # コマンド・依存関係
  .nvmrc                           # Node.jsのメジャーバージョン
  tsconfig.json                    # strict型チェック
  vite.config.ts                   # 配信base
  vitest.config.ts                 # jsdom・V8 Coverage
  playwright.config.ts             # ブラウザ・previewサーバー
  src/
    main.ts                        # 起動・選択状態・タイトル・フォーカス
    registry.ts                    # メタデータ・型・動的import
    router.ts                      # URL生成・History API・リンク操作
    tool-host.ts                   # マウント・破棄・読み込み競合制御
    components/
      home.ts                      # Registryからホームのカードを生成
      layout.ts                    # ヘッダー・サイドバー・モバイルメニュー
      theme.ts                     # OS追従・手動テーマ・保存
    styles/main.css                # 共通レイアウト・CSS変数・両テーマ
    tools/
      ip-address/
        index.ts / api.ts / style.css
      width-converter/
        index.ts / logic.ts / style.css
      markdown-table/
        index.ts / logic.ts / xlsx.ts / style.css
      datetime/
        index.ts / logic.ts / style.css
  tests/                           # Playwrightのスモーク・詳細操作・IP欄レイアウト
    fixtures.ts                    # 全E2E共通のipifyモック
  scripts/
    generate-coverage-badge.mjs
    generate-coverage-badge.test.mjs
  docs/architecture.md
  .github/workflows/ci-pages.yml
```

各ツールの`index.ts`はDOM・イベント・非同期処理の状態を、`style.css`はツール固有の表示を担当します。IP確認の`api.ts`は通信とレスポンス検証、他ツールの`logic.ts`はDOMに依存しない変換処理を担当します。Markdown表の`xlsx.ts`はファイル生成専用です。現在、`public/`ディレクトリはありません。

### Registryと遅延読み込み

[src/registry.ts](../src/registry.ts)の`ToolDefinition`は`id`、`name`、`description`、`category`、`load`を持ちます。`load`は固定パスを指定した動的importです。URLの文字列をimportパスに直接使用しません。共通の`ToolModule`型もRegistryで定義します。

`categories`の配列順はサイドバーのカテゴリ順、`tools`の配列順はカテゴリ内のツール順とホームのカード順になります。現在のツール順はIP確認、全角・半角、Markdown表、日時です。ホームはツール登録に含めず、`components/home.ts`で表示します。

ホームのカードはRegistryのID・名前・説明から生成します。ホーム表示時にはツールの`load`を呼ばず、ツール本体・ExcelJSを読み込まず、ipifyにも通信しません。ExcelJSはMarkdown表のダウンロード操作時にさらに遅延読み込みします。

## ルーティング・画面ライフサイクル

### URLと履歴

[src/router.ts](../src/router.ts)は`?tool=<tool-id>`で画面を選択します。

| URLの状態 | 表示 |
| --- | --- |
| `tool`未指定（`null`） | ホーム |
| 登録済みID | 対応するツール |
| 空の`?tool=`、不明ID | 「ツールが見つかりません」と復帰用リンク |

不明IDをホームへ置換せず、URLも自動修正しません。復帰用の「既定のツールを開く」は`defaultToolId`の`ip-address`を指します。このIDは初回表示の選択には使いません。

`toolUrl`・`homeUrl`は現在のURLを複製し、パス・無関係なクエリ・ハッシュを保持します。ホームへのリンクでは`tool`をすべて削除します。通常のリンク選択ではIDが変わる場合だけ`pushState`を実行し、画面を更新します。`popstate`ではURLから再描画するだけで履歴を追加しません。初回表示・直接アクセス・再読み込みも同じURL解釈です。

ルーターが処理するのは`data-tool-id`または`data-home`付きリンクの、同一origin・同一pathnameへの通常クリックです。修飾キー付きクリック、左ボタン以外、別タブ指定、ダウンロード、処理済みイベントは横取りしません。

### マウント・破棄・競合制御

ツールの契約は同期関数`mount(container: HTMLElement): () => void`です。マウント中に表示を作り、通信などは内部で開始します。返す破棄関数は、ツールが登録したリスナー・タイマー・通信などと表示要素を解放します。

[src/tool-host.ts](../src/tool-host.ts)の`show`は、`null`をホーム、`undefined`を不明ツール、それ以外をツール定義として扱います。遷移ごとに世代番号を更新し、旧画面の破棄関数を呼んでからコンテナを空にします。ホームも破棄関数を返します。

ツール読み込み中は`aria-busy`と読み込み案内を表示します。動的importはキャンセルできないため、完了時に世代番号を確認します。旧importの成功・失敗はマウントも案内の更新も行わず、新画面の`aria-busy`も解除しません。現在の読み込みまたはマウントが失敗すると、再読み込み・別ツール選択の案内と復帰用リンクを表示します。`destroy`も世代を更新し、破棄とコンテナの消去を行います。

`main.ts`は同じIDの再選択では再マウントしません。別ツール・ホームへ移動した後に戻る場合は新規マウントとなり、入力・設定・結果を復元しません。History APIには入力状態を格納しません。ホストはimportの競合を、各ツールは自身の通信・コピー・ファイル生成の競合と破棄を担当します。Clipboard APIやXLSX生成自体は中止せず、世代番号・破棄フラグで古い完了処理の表示やダウンロードを抑制します。

## UI・テーマ・アクセシビリティ

### 共通レイアウトとフォーカス

デスクトップはカテゴリ別の左サイドバーと右メイン、幅759px以下は開閉式メニューです。ホームのカードはデスクトップで2列、モバイルで1列です。ヘッダーのブランドリンクとサイドバー先頭の「ホーム」からホームへ戻れます。

`components/layout.ts`は同じサイドバーを通常の配置先と標準`dialog`の間で移動します。モバイルで閉じている間は`hidden`でリンクをフォーカス対象から外します。メニューボタンは`aria-expanded`と`aria-controls`を持ち、`showModal()`によるモーダル制御とTab端点の循環を使用します。開いたときは現在の選択リンク、不明IDなどで選択がなければ閉じるボタンにフォーカスします。

Escape・閉じるボタン・ダイアログ背景のクリックで閉じ、ネイティブのdialog動作でメニューボタンにフォーカスが戻ります。リンク選択時にも閉じ、遷移完了後に`main.ts`が新画面の`h1`へフォーカスします。デスクトップ幅へ変更した場合はメニューを閉じ、サイドバーを通常位置へ戻します。

選択リンクに`aria-current="page"`を付与します。ページタイトルはホームが`Web Toolbox`、ツールが`ツール名 | Web Toolbox`、不明IDが`ツールが見つかりません | Web Toolbox`です。初回表示では見出しへ自動フォーカスせず、リンク選択・履歴移動では現在の画面表示完了後に移します。本文へのスキップリンク、入力ラベル、fieldset/legend、キーボード操作、`:focus-visible`を備えます。

### テーマと状態通知

色・余白・角丸などは`src/styles/main.css`のCSS変数で管理し、ツール固有CSSも両テーマに対応します。システムフォントを使用し、`prefers-reduced-motion`ではアニメーション・トランジションなどを無効にします。

`index.html`のスクリプトはスタイル適用前に手動設定を復元します。未設定時の初期配色はCSSの`prefers-color-scheme`、起動後の配色は`components/theme.ts`が`data-theme`へ反映します。手動設定がない間はOS設定の変更に追従し、手動選択時は選択色を使用します。保存の詳細は次節を参照してください。

コピーは`navigator.clipboard.writeText`を使用します。権限拒否・API非対応などの例外を捕捉し、成功・失敗を`role="status"`で通知します。失敗してもreadonlyの出力欄を残し、手動選択・コピーを可能にします。コピー・生成の非同期完了は、入力変更や破棄後に古い通知を表示しないよう管理します。入力エラーは`role="alert"`や`aria-invalid`で示します。変換結果全文や定期更新する時計はライブリージョンにしません。

## セキュリティ・データ保護

ツール入力・変換結果・取得したIPは、URL・ログ・localStorage・sessionStorageなどへ保存しません。ブラウザ内の画面状態として保持し、切り替え時に破棄します。XLSXの明示的なダウンロードとClipboard APIへの書き込みは利用者操作による出力です。

永続化するアプリ設定は手動選択したテーマのみです。localStorageの`web-toolbox-theme`に`light`または`dark`を保存し、「システム」で削除します。読み書き失敗は捕捉し、保存できなくても現在のテーマ選択とアプリ動作を継続します。

ツールのデータ取得のために外部へ通信するのはIP確認のみです。接続先、送信方針、外部サービスへの依存は[IPアドレス確認](#ipアドレス確認--ip-addressネットワーク)に集約しています。他ツールの入力を送信する処理はありません。ツールやExcelJSの動的importは同一サイトの配信アセットを読み込みます。外部フォント・解析サービス・外部スクリプトは使用しません。

固定HTMLテンプレートにのみ`innerHTML`を使用し、利用者入力・変換結果・外部レスポンスはフォームの`value`または`textContent`で設定します。MarkdownのHTMLプレビューは行いません。IPレスポンスは`unknown`として型と形式を検証します。

## ツール別詳細仕様

以下はREADME・Registryと同じ掲載順です。各ツールのデータ保存・送信の共通方針は前節、テストの実行基盤は[テスト方針](#テスト方針)を参照してください。

### IPアドレス確認 — `ip-address`／ネットワーク

#### 通信と形式検証

`api.ts`はIPv4を`https://api.ipify.org?format=json`、IPv6を`https://api6.ipify.org?format=json`から取得します。`api64.ipify.org`や別サービスへのフォールバックは使用しません。位置情報・ローカルIPは取得しません。

ブラウザから直接通信するため、接続元IPがipifyへ伝わる旨を画面に明記します。fetchには`cache: 'no-store'`、`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`を指定し、アプリ独自のヘッダーや識別情報は追加しません。取得は各IPバージョンの接続環境、DNS、提供元の稼働状況・CORS設定に依存します。IPv6取得失敗だけでIPv6非対応とは判断できない旨も表示します。

HTTP成功後、JSONが非nullのオブジェクトで、`ip`が文字列かつ要求したIP形式であることを確認します。前後の空白除去や表記の正規化はせず、検証した文字列をそのまま返します。検証はアドレスの構文を対象とし、グローバルアドレス範囲の判定は行いません。

- IPv4：4オクテットのASCII十進表記、各0〜255です。先頭ゼロ、符号、空白、全角数字、IPv6を拒否します。
- IPv6：各1〜4桁の16進数8グループ、1回だけの`::`による1グループ以上の省略、末尾IPv4埋め込みに対応します。埋め込みIPv4も上記のIPv4検証を行い、2グループとして数えます。過剰・不足グループ、不正な16進数、空白、角括弧、ポート付き形式、ゾーンIDを拒否します。

内部エラー種別は`network`、`http`、`timeout`、`format`、`aborted`です。不正JSON・`ip`の欠落／型不正・IP形式不正はいずれも`format`、本文読み込み中の通信障害は`network`として扱います。UIは種別に応じた日本語の案内を表示し、画面切り替えによる中止は通信エラーとして通知しません。

#### UI・非同期処理・破棄

表示時に両APIを並行して自動取得します。各リクエストはJSON本文の読み込みを含め10秒でタイムアウトし、自動リトライしません。`api.ts`内のAbortControllerで呼び出し元の中止とタイムアウトを伝え、`finally`でタイマーと中止リスナーを解放します。

IPv4・IPv6は独立した結果・取得状態・コピーボタンを持ちます。一方の失敗で他方の成功を消去せず、先に成功した側は他方の完了前でもコピーできます。共通の再取得ボタンは両方の完了まで無効にし、再取得開始時に両方の旧IPとコピー通知を消去します。

IPv4はreadonly input、IPv6は`rows="1"`のreadonly textareaです。IPv6の高さは取得開始・成功・ウィンドウリサイズ時に`scrollHeight`と枠線幅から再計算します。`field-sizing`に依存せず、折り返した内容全体を表示し、手動リサイズは無効にしています。各パネルの取得状態とコピー結果を別のstatusで通知します。

UIはリクエストのAbortController識別と破棄フラグで、古い取得・コピー完了を無視します。コピー中は該当ボタンを無効にします。再取得開始時に前回のcontrollerを中止し、破棄時にも通信を中止してコピー・再取得・resizeのリスナーを解除します。

#### 主なテスト

`api.test.ts`はHTTP・JSON・両IP形式の境界値、通信障害、本文読み込み中を含む10秒タイムアウト、開始前／実行中の中止、タイマー解放を検証します。`index.test.ts`は両バージョンの成功・失敗の組み合わせ、連打抑止、独立表示、再取得、コピーと破棄後の更新抑制、高さ再計算を検証します。

`tests/ip-address.spec.ts`は表示・再取得・実Clipboard API・エラー復帰・切り替え・狭幅両テーマを、`tests/ip-address-layout.spec.ts`はChromiumとFirefoxで長いIPv6の折り返し、広幅／狭幅間の伸縮、IPv4との高さ、手動選択を検証します。実APIへの到達性はモックテストの保証範囲外です。

### 全角・半角変換 — `width-converter`／テキスト・データ

#### 入出力とUnicode規則

`logic.ts`の純粋関数`convertWidth(input, direction, categories)`が変換を担当します。方向は`to-half`／`to-full`、カテゴリは英数字・記号・カタカナ・スペースの4つです。初期値は全角→半角、英数字・記号・スペースON、カタカナOFFです。全OFFでは入力をそのまま出力します。入力値自体は書き換えず、readonly textareaへ結果を表示します。

| カテゴリ | 変換範囲と制約 |
| --- | --- |
| 英数字 | ASCIIの`0–9`・`A–Z`・`a–z`と対応する全角英数字です。 |
| 記号 | ASCII U+0021–U+007Eから英数字を除いた文字と、対応するU+FF01–U+FF5Eです。チルダU+007E ↔ U+FF5E、バックスラッシュU+005C ↔ U+FF3Cを含みます。波ダッシュU+301C、円記号U+00A5・U+FFE5は保持します。 |
| カタカナ | 半角U+FF61–U+FF9Fに対応するカナ・小書き・長音・中黒・日本語句読点・濁点／半濁点です。句読点は記号カテゴリに依存しません。 |
| スペース | U+0020 ↔ U+3000のみです。タブ・改行・その他のUnicode空白は保持します。 |

カタカナ対応表は既知の半角1文字と、濁点・半濁点との組から生成します。NFKCを適用するのは対応表生成と、半角→全角の既知の半角カナおよび直後の濁点（半角または結合文字）の範囲だけです。全文を正規化しないため、丸数字・ローマ数字などの互換文字を変化させません。

合成済みのガ・パ・ヴ・ヷ・ヺなどと対応するカナ＋結合濁点に対応します。全角→半角では結合濁点U+3099・U+309A、幅のあるU+309B・U+309Cを半角U+FF9E・U+FF9Fへ変換します。半角→全角では単独の半角濁点・半濁点を結合文字U+3099・U+309Aにし、結合不能な組は基底カナと結合文字の並びになります。

ひらがなに続く結合濁点・半濁点はまとめて保持し、濁点だけを変換しません。ひらがな、ヵ・ヶ・ヮなど半角対応のないカナ、未選択カテゴリ、その他の非対応Unicodeも保持します。単独濁点などの扱いにより、全Unicodeで完全な往復一致は保証しません。

初期設定では`ＡＢＣ１２３！＠＃　ガギグ`が`ABC123!@# ガギグ`になります。空入力は空出力となり、非対応文字を入力エラーにはしません。

#### 更新・コピー・破棄

入力・設定変更で同期変換します。`compositionstart`でIME変換中とし、その間と`InputEvent.isComposing`がtrueの入力イベントでは更新を抑制します。設定変更も変換中は保留します。`compositionend`で更新し、その後の最終inputも受け付けてイベント順序の違いに対応します。クリアは入力と変換中状態をリセットし、入力欄へフォーカスします。

コピー中は連打を防止し、入力・設定変更やIME開始で更新した世代番号により古い通知を抑制します。破棄時はフラグを立て、AbortControllerで全リスナーを解除して表示を削除します。

#### 主なテスト

`logic.test.ts`は全カテゴリ・両方向、ASCII全94文字、半角カナ全範囲、合成／結合濁点・単独濁点・結合不能な組、ひらがなの保護、非対象Unicode、空入力・長文を検証します。`index.test.ts`はコピー成功／失敗が破棄後のDOMを更新せず、イベントも解除されることを検証します。

`tests/width-converter.spec.ts`は初期値・設定変更・即時更新・IMEイベント順序、実Clipboard APIと失敗、保留中コピー後の変更／切り替え、手動選択、入力非保存・非送信、長文のモバイル両テーマ表示を検証します。

### Markdown表変換 — `markdown-table`／テキスト・データ

#### 共通モデルとMarkdown解析

`logic.ts`は`TableData = { rows: string[][] }`を共通モデルとし、`parseMarkdown`・`parseTsv`・`toMarkdown`・`toTsv`を提供します。先頭行をヘッダーとして扱います。すべての方向で列数の不一致をエラーにし、補完・切り捨てを行いません。

Markdownは単一表を対象とし、先頭行がヘッダー、2行目が必須区切りです。区切りセルはハイフン3個以上で、`---`、`:---`、`---:`、`:---:`を受理します。配置情報は保持しません。外側パイプは省略可能、前後の空行は無視、途中の空行はエラー、空白のみの入力は空表です。行区切りCRLF／CRはLFへ揃えます。

パイプ直前の連続バックスラッシュが偶数なら列区切り、奇数ならセル内容として扱います。コードスパン内でもパイプのエスケープが必要です。外側パイプの外にあるASCIIスペース・タブは無視します。セル両端のASCIIスペース各1文字のみを構文の余白として除去し、それ以上の空白・タブ・全角空白は保持します。幅揃えの多数のスペースも内容になります。端の空セルと外側パイプの曖昧さを避けるため、空セルがある表は外側パイプ付きの形式が適しています。

装飾・HTMLエンティティは解釈せず保持します。`<br>`、`<br/>`、`<br />`（大小文字不問）のみLFへ変換します。同じ長さのバッククォート列で閉じるセル内コードスパンではタグを文字列として保持し、閉じないバッククォートは通常の文字として扱います。通常部分ではバックスラッシュをパイプ・バックスラッシュ・`<`・バッククォートの前だけエスケープとして解釈し、エスケープされた`<`からは改行タグを認識しません。コードスパン内で解除するエスケープはパイプとバックスラッシュのみです。

完全なCommonMark/GFMパーサーではありません。属性付きタグ、コードブロック、HTML構文の入れ子などは解析対象外です。複数表・結合セル・HTMLプレビューには対応しません。

#### TSV解析と出力規則

TSVは状態機械で解析し、セル全体を囲む引用符、引用符内部の`""`、セル内タブ・改行、空セル・末尾空セルを扱います。行区切りはCRLF／LF／CRです。閉じない引用符、囲みの外の引用符、閉じ引用符後の区切り以外の文字はエラーです。引用符内の改行は解析時にはそのまま保持します。

空文字だけを空表とし、空白文字はセル内容です。最終改行1つは行終端として扱い、追加の空行は空セル1つの行として列数を検証します。`""`は空セル1つ、タブだけなら空セル2つです。

- TSV出力：行区切りCRLF、列区切りタブです。タブ・改行・引用符を含むセルを引用符で囲み、内部の引用符を二重化します。1列だけの空セルも`""`とし、空表と区別します。
- Markdown出力：外側パイプとASCIIスペース各1文字を付け、標準`---`区切り、行区切りLFで生成します。バックスラッシュ・パイプ・バッククォートと文字列としてのbrタグをエスケープし、実際のセル内CRLF／LF／CRだけを`<br>`へ統一します。

textareaはCRLFをLFへ正規化するため、コピー時は表示欄の値ではなく共通モデルから再生成します。TSVをExcelへ貼り付ける際の数値・日付・数式への自動型判定は完全には制御できません。文字列型の確実な保持にはXLSX出力を案内します。

モデルの往復検証は矩形の文字列表（空表以外は1列以上）を対象とします。TSVはセル内のCRLF／LF／CRも含めて保持します。Markdownの完全一致の往復はセル内改行がLFのモデルに限り、CRLF／CRはLFに正規化した値を期待します。Markdown原文の配置指定・区切り・余白などの構文を再現する保証はありません。

#### XLSX生成

`xlsx.ts`はExcelJS 4.4（MIT）を使用します。ブラウザ用ビルドと文字列型・書式・列幅・折り返しのAPIがあり、独自のZIP/XML生成を避けられるため採用しています。追加の直接依存は`exceljs`のみで、推移依存はlockfileで管理します。

ダウンロード時だけ`import('./xlsx')`し、入力・変換・TSVコピーでは読み込みません。ExcelJSを含む生成用コードは遅延チャンクとなるため、初期ロードに含まれません。具体的なバンドルサイズは固定仕様にせず、必要時に`npm run build`の出力で確認します。

出力ファイルは`table.xlsx`、ワークシート名は`Table`です。全セルを文字列で設定し、表示形式`@`、折り返し・上揃え、1行目太字とします。列幅は各行のセルを改行で分け、コードポイントが255以下なら1、それ以外なら2として数えた長さに余白2を加え、8〜60の範囲に制限します。

数式オブジェクトを使用しないため、先頭ゼロ、長い数字、日付風・数式風文字列を文字列型として保持します。上限は1,048,576行、16,384列、1セル32,767で、セル長はJavaScriptの`string.length`（UTF-16コード単位）で判定します。超過は切り詰めず生成エラーにします。XLSXのアップロード・読み込みには対応しません。

#### UI・非同期処理・破棄

初期方向はMarkdown→Excelです。方向・入力の変更で再計算し、空表ではコピー・ダウンロードを無効にします。解析エラー時は古い結果を消去し、操作を無効にしてalertと`aria-invalid`で通知します。Excel→Markdownではダウンロードボタンを隠します。クリアは入力を空にして入力欄へフォーカスします。

コピーと生成それぞれの連打を防ぎ、世代番号と破棄フラグで入力・方向変更前や破棄後の完了を無視します。XLSXはimport後と生成後の両方で確認するため、古い入力のファイルをダウンロードしません。生成失敗はstatusで通知します。Object URLはダウンロード開始操作の1秒後、またはツール破棄時に解放します。破棄時はタイマーも解放し、AbortControllerでリスナーを解除します。

#### 主なテスト

`logic.test.ts`は区切り・列数・空白・空セル、連続バックスラッシュ、コードスパンとbr、TSVの引用符・改行・不正入力、出力と往復、数値風文字列の保持を検証します。往復は共通の固定ケースとシード`0x5eed1234`の128表で両形式を検証し、Unicode・絵文字・結合文字、引用符・バッククォート、リテラルbrと実改行を組み合わせます。形式をまたぐ往復とCRLF／CRの正規化も別に検証します。`xlsx.test.ts`は実ファイルを再読み込みし、ヘッダーとデータの文字列型・数式風文字列・Unicode・空セル・書式・折り返し・列幅を検証します。行数・列数・UTF-16セル長の上限直前・上限・超過、空表・不揃いな列数、書き込み失敗も確認します。上限検証を`validateXlsxTable`に分離し、行数上限は同じ短い行を共有する参照配列で検証するため、100万行のXLSXは生成しません。`index.test.ts`は生成中の変更・破棄、生成失敗、Object URL解放を検証します。

`tests/markdown-table.spec.ts`は両方向・エラー・クリア・再訪時の入力破棄、実Clipboard APIと失敗、XLSX遅延読み込み・実ダウンロード・再読み込み、非送信・非保存、モバイル両テーマとキーボード操作を検証します。

### JST・UTC日時変換 — `datetime`／日時

#### 時計と24時間対応表

現在のJST・UTC年月日時分、JST基準の日付選択と24時間対応表、詳細変換の順に表示します。時計は60秒間隔とタブ再表示時に更新し、詳細入力を上書きしません。時計をライブリージョンにはしません。

表はJST 00:00〜23:00の24行で、UTCの時分と「前日／同日」を表示します。JST 00〜08時はUTCの前日、09〜23時は同日です。日付の初期値はJSTの今日で、「今日へ戻る」で復帰します。不正日付は補正せず、エラーを表示して表を空にします。

選択日がJSTの今日なら現在の時間帯を背景色と「現在」で示します。選択行は左線・ボタン枠・「選択中」および`aria-pressed`で区別します。時刻ボタンはキーボードで選択でき、詳細欄をJST・表の日付・選択時刻の00秒に設定します。詳細の日時が表の行の瞬間と一致した場合も選択表示になります。

日付をまたいでも表の選択日付を自動変更せず、今日と異なれば現在時間帯のハイライトを消します。詳細欄のUTC選択や「現在時刻を入力」は表の基準日付を変えません。

#### 入出力・境界条件

詳細入力はJST／UTC、`YYYY-MM-DD`の日付、時分秒です。時刻は`HH:mm`または`HH:mm:ss`を受理し、秒省略時は00秒です。変更時に即座に変換します。「現在時刻を入力」は選択ゾーンの現在日時を秒まで設定し、初回マウントでも現在のJST日時を設定します。

出力はJST日時・UTC日時（通常`YYYY-MM-DD HH:mm:ss`）、ISO 8601（UTC、末尾Z、秒精度）、整数のUnix秒・ミリ秒です。各値に個別コピーとreadonly欄を設けます。ISO・Unix timeは出力専用です。

入力年は0001〜9999年の先発グレゴリオ暦です。日付・時刻は厳密に検証し、不正値をDateの自動補正に任せません。1900年は平年、2000年はうるう年として扱います。24:00、うるう秒、ミリ秒入力は非対応です。不正入力では出力を消去し、コピーを無効にします。

変換境界の出力は0000年・10000年も扱います。例えば`0001-01-01 00:00:00 JST`のUTCは`0000-12-31 15:00:00`、`9999-12-31 23:59:59 UTC`のJSTは`10000-01-01 08:59:59`です。入力としてその年を受理するわけではありません。1970年以前の負のUnix timeにも対応します。

`logic.ts`はUnixミリ秒を基準とし、JSTを全期間UTC+09:00固定で計算します。歴史上の時差や夏時間を再現しません。UTC getterと`setUTCFullYear`を使い、0〜99年が1900年代になるDateの特殊処理と端末のローカルタイムゾーンへの依存を避けます。`Date.parse`による入力解釈は行いません。

#### コピー・破棄・主なテスト

コピー成功・失敗をstatusで通知し、入力更新の世代番号と破棄フラグで古い完了通知を抑制します。破棄時は時計タイマーを止め、AbortControllerで入力・ボタン・`visibilitychange`などのリスナーを解除します。

`logic.test.ts`は全24行、月末・年末・うるう年・0〜99年・入出力年境界、不正入力、秒省略、ISO・Unixの正負出力を検証します。epochの前後1秒と0秒、UTC／JSTの往復、入力範囲外になる境界出力も確認します。ローカル依存性はNode.js 24のTypeScript読み込みで別プロセスを起動し、`UTC`・`Asia/Tokyo`・`America/Los_Angeles`・`Pacific/Kiritimati`で夏時間切り替え日の変換・24時間表を比較します。`index.test.ts`は固定時計とfake timerで日付境界・再表示・破棄、コピー待機中の変更／破棄を確認します。

`tests/datetime.spec.ts`は固定時計と`America/Los_Angeles`のローカルゾーンで、表とハイライト、日付・行の選択、詳細変換、不正入力、実コピーと失敗、モバイル両テーマ、時間帯更新、切り替えを検証します。

## テスト方針

### 単体テストとカバレッジ

[vitest.config.ts](../vitest.config.ts)は既定のjsdom環境で`src/**/*.test.ts`を実行し、モックを復元します。DOMを使わないMarkdown／TSV・日時の`logic.test.ts`はファイル単位でNode環境を指定します。純粋な変換処理の境界値・不正入力・Unicodeに加え、UIの非同期完了、通信中止、リスナー・タイマーの破棄を検証します。ツール固有の対象は前節にまとめています。

共通基盤では`router.test.ts`がURL・標準リンク操作・履歴通知、`tool-host.test.ts`が遅いimportの成功／失敗と新画面の競合、ホーム遷移、破棄契約、`components/home.test.ts`がRegistry順のカードと未ロード、`components/theme.test.ts`がOS追従・手動保存・ストレージ拒否・購読解除を検証します。

`npm test`は通常のVitest実行、`npm run test:coverage`はV8 Coverageを有効にし、`text`と`json-summary`を出力します。`coverage.include`は`src/`のJS/TSコード全体を指定し、未importのソースも対象にします。test/spec・`__tests__`・型宣言を除外し、起動処理・共通UI・ルーター・ホスト・4ツールを含めます。最低閾値は設定せず、Playwrightのカバレッジを合算しません。Vitestと`@vitest/coverage-v8`は同一の完全バージョンに固定しています。

### E2Eと検証範囲

[playwright.config.ts](../playwright.config.ts)はビルド済み`dist/`をVite previewで配信し、`http://127.0.0.1:4173/web-toolbox/`を使用します。E2Eコマンド自体はビルドしないため、事前の`npm run build`が必要です。サーバーは既存プロセスを再利用せず、指定ポートで起動します。CIでは`test.only`を禁止し、診断用に失敗時に1回再試行します。`failOnFlakyTests: true`により再試行でのみ成功したケースもコマンドを失敗させ、失敗時のtraceを保持します。

Chromiumはホームと4ツールの主要シナリオを実行します。`tests/app.spec.ts`は直接URL・再読み込み・戻る／進む、空／不明ID、テーマ復元とOS追従、ストレージ拒否、モバイルメニューとフォーカス、ホームの非通信・遅延ロード・両テーマのカード配置を検証します。単体テストと同じ全境界値をE2Eへ重複させる構成にはしていません。

`tests/smoke.spec.ts`の5ケースはChromium・Firefox共通です。ホームからの遷移・URL・戻る／進む・再読み込み、IPv4／IPv6表示と再取得、文字種選択と双方向の文字幅変換、Markdown／TSV変換とエラー復帰、JSTの24時間表選択とUTC入力・epoch出力を検証します。ブラウザのタイムゾーンをロサンゼルスに固定し、端末の時間帯に依存しない操作を確認します。

Firefoxではスモークに加えて既存の`tests/ip-address-layout.spec.ts`を実行し、IP欄の高さ・折り返し・画面幅への追従を両テーマで維持します。詳細なコピー・ダウンロード・IME・モバイル操作などはChromium中心とし、Firefoxへ全ケースを複製しません。WebKitはSafari系のフォーム・レイアウト差の検出に有効ですが、追加ブラウザとOS依存の配備・実行のCI負荷が増えるため今回は追加しません。Safari固有の検証が必要になった時点で共通スモークへの追加を検討します。

単体テストのfetchモックとE2E共通の`tests/fixtures.ts`でipifyを置換するため、実APIにはアクセスしません。CI成功だけでは実サービスの接続・CORS・IPv6到達性を保証せず、必要時に別途確認します。

## CI/CD・GitHub Pages

### 実行環境とパイプライン

Node.jsは24 LTSを使用し、[.nvmrc](../.nvmrc)の`24`と[package.json](../package.json)の`engines: 24.x`でローカル・CIのメジャーバージョンを揃えます。`build`は`npm run typecheck && vite build`で、`typecheck`は`tsc --noEmit`です。

[.github/workflows/ci-pages.yml](../.github/workflows/ci-pages.yml)はPRと`main`へのpushで起動します。CIジョブは次の順に実行します。

1. checkout、`.nvmrc`に従ったNode.jsセットアップ、`npm ci`。
2. `npm run test:coverage`による単体テストとカバレッジ計測。
3. `npm run test:badge`によるNode.js標準テストランナーのバッジ生成テスト。
4. `npm run build`による型チェックとViteビルド。
5. Chromium・FirefoxとOS依存パッケージのインストール、`npm run test:e2e`。
6. `main`へのpushの場合のみカバレッジSVGを生成し、`dist/`をPages成果物としてアップロード。

型チェックの独立した重複ステップはありません。PRでは検証・カバレッジのログ出力まで行い、SVG生成・Pages成果物のアップロード・デプロイは行いません。

### カバレッジバッジ

[scripts/generate-coverage-badge.mjs](../scripts/generate-coverage-badge.mjs)は`coverage/coverage-summary.json`の`total.lines.pct`を読み、`dist/coverage.svg`を生成します。表示はLinesの値を小数点以下1桁に丸めたものです。色は丸め前の値で90%以上・80%以上・60%以上・60%未満に分けます。

数値の欠損、数値以外、非有限値、0〜100の範囲外、不正JSONや読み取り失敗はエラーとし、CLIを失敗終了させます。計測値の補完は行いません。`generate-coverage-badge.test.mjs`が表示・色境界・不正値・ファイル入出力とCLI失敗を検証します。

SVGはE2E成功後に生成してPages成果物に含め、READMEが公開SVGを参照します。ローカル生成もカバレッジ計測とビルドの後に行います。`coverage/`と`dist/`はGit管理対象外です。外部バッジサービスや追加トークン・権限は使用しません。

### 配信パス・権限・公開条件

[vite.config.ts](../vite.config.ts)の`base`は`/web-toolbox/`です。公開先は`https://arscombinatoria.github.io/web-toolbox/`を前提とします。ツール選択はクエリ方式なので、GitHub PagesのSPAフォールバックや独自404は不要です。Viteがimportしたアセット・遅延チャンクのパスを生成し、画面リンクは現在のパスを保持します。公開パスやカスタムドメインを変更する場合は、ViteのbaseとPlaywrightの配信パスを見直す必要があります。

デプロイジョブは`main`へのpushに限り、CI成功後にGitHub公式Pages Actionsで`dist/`を`github-pages` environmentへ公開します。ActionsはコミットSHAに固定しています。ワークフローの基本権限は`contents: read`で、デプロイジョブのみに`pages: write`と`id-token: write`を付与します。

ワークフローのconcurrencyはworkflow名とrefの組み合わせで、PRの古い実行だけをキャンセルします。デプロイジョブは別途`pages`グループで直列化し、実行中のデプロイをキャンセルしません。リポジトリのPages Source・Actions許可・environment制限の設定手順はREADMEを参照してください。設定ファイルやローカルテストだけでは公開成功を確定できず、マージ後のActionsと公開URLで確認します。
