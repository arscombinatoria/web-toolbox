# Web Toolbox — アーキテクチャー仕様

## 概要・設計方針

Web Toolboxは、GitHub Pagesで配信するバックエンドのない静的SPAです。ホーム画面と、IPアドレス確認・IP登録情報検索・全角／半角変換・Markdown表変換・JavaScript正規表現ビジュアライザー・JST／UTC日時変換・JWTデバッガーの7ツールで構成します。本書は現行実装の内部設計、変換規則、制約、設計判断と検証範囲を記載します。利用方法と開発手順は[README](../README.md)、エージェント向けの実装規約は[AGENTS.md](../AGENTS.md)を参照してください。

Vanilla TypeScript（strict）、ES Modules、Vite、HTML/CSS、ブラウザ標準APIを使用します。UIフレームワークや状態管理ライブラリは使用せず、各ツールのDOM操作と通信・変換処理を分離しています。共通UIはRegistryのメタデータから生成し、ツール本体は必要時に読み込みます。

入力・結果は画面内で扱い、ツールを離れると破棄します。IP確認・RDAPの外部API通信と、手動選択したテーマの保存については[セキュリティ・データ保護](#セキュリティデータ保護)に記載します。

## システム構成・モジュール構成

主要ファイルの構成は次のとおりです。Vitestのテストは対象モジュールに隣接し、E2Eは`tests/`に配置しています。

```text
web-toolbox/

  package.json / package-lock.json # コマンド・依存関係

  tsconfig.json                    # strict型チェック
  vite.config.ts                   # 配信base
  vitest.config.ts                 # jsdom・V8 Coverage
  playwright.config.ts             # ブラウザ・previewサーバー
  src/
    main.ts                        # 起動・選択状態・タイトル・フォーカス
    registry.ts                    # メタデータ・型・動的import
    router.ts                      # URL生成・History API・リンク操作
    tool-host.ts                   # マウント・破棄・読み込み競合制御
    components/
      home.ts                      # Registryからホームのカードを生成

    tools/
      ip-address/
        index.ts / api.ts / style.css
      rdap-lookup/
        index.ts / api.ts / logic.ts / style.css
      width-converter/
        index.ts / logic.ts / style.css
      markdown-table/
        index.ts / logic.ts / xlsx.ts / style.css
```

各ツールの`index.ts`はDOM・イベント・非同期処理の状態を、`style.css`はツール固有の表示を担当します。IP確認の`api.ts`は通信とレスポンス検証、他ツールの`logic.ts`はDOMに依存しない変換処理を担当します。Markdown表の`xlsx.ts`はファイル生成専用です。`public/favicon.svg`はタブ用アイコンとして配信します。

### Registryと遅延読み込み

[src/registry.ts](../src/registry.ts)の`ToolDefinition`は`id`、`name`、`description`、`category`、`load`を持ちます。`load`は固定パスを指定した動的importです。URLの文字列をimportパスに直接使用しません。共通の`ToolModule`型もRegistryで定義します。

`categories`の配列順はサイドバーのカテゴリ順、`tools`の配列順はカテゴリ内のツール順とホームのカード順になります。現在のツール順はIP確認、IP登録情報検索、全角・半角、Markdown表、正規表現、JWT、日時です。ホームはツール登録に含めず、`components/home.ts`で表示します。

ホームのカードはRegistryのID・名前・説明から生成します。ホーム表示時にはツールの`load`を呼ばず、ツール本体・正規表現Worker・regexpp・ExcelJS・joseを読み込まず、ipify・RDAPにも通信しません。ExcelJSはMarkdown表のダウンロード操作時、joseはJWTの署名検証操作時にさらに遅延読み込みします。

## ルーティング・画面ライフサイクル

### URLと履歴

[src/router.ts](../src/router.ts)は`?tool=<tool-id>`で画面を選択します。

| URLの状態 | 表示 |
| --- | --- |
| `tool`未指定（`null`） | ホーム |
| 登録済みID | 対応するツール |
| 空の`?tool=`、不明ID | 「ツールが見つかりません」と復帰用リンク |

不明IDをホームへ置換せず、URLも自動修正しません。復帰用の「既定のツールを開く」は`defaultToolId`の`ip-address`を指します。このIDは初回表示の選択には使いません。

`toolUrl`・`homeUrl`は現在のURLを複製し、パス・無関係なクエリ・ハッシュを保持します。ホームへのリンクでは`tool`をすべて削除します。通常のリンク選択ではIDが変わる場合だけ`pushState`を実行し、画面を更新します。`popstate`ではURLから再描画するだけで履歴を追加しません。初回表示・直接アクセス・再読み込みも同じURL解釈です。

ルーターが処理するのは`data-tool-id`または`data-home`付きリンクの、同一origin・同一pathnameへの通常クリックです。修飾キー付きクリック、左ボタン以外、別タブ指定、ダウンロード、処理済みイベントは横取りしません。

### マウント・破棄・競合制御

ツールの契約は同期関数`mount(container: HTMLElement): () => void`です。マウント中に表示を作り、通信などは内部で開始します。IP確認からRDAPへの一時入力に限り、任意の第2引数`input?: string`を受け取れます。返す破棄関数は、ツールが登録したリスナー・タイマー・通信などと表示要素を解放します。

[src/tool-host.ts](../src/tool-host.ts)の`show`は、`null`をホーム、`undefined`を不明ツール、それ以外をツール定義として扱います。遷移ごとに世代番号を更新し、旧画面の破棄関数を呼んでからコンテナを空にします。ホームも破棄関数を返します。

ツール読み込み中は`aria-busy`と読み込み案内を表示します。動的importはキャンセルできないため、完了時に世代番号を確認します。旧importの成功・失敗はマウントも案内の更新も行わず、新画面の`aria-busy`も解除しません。現在の読み込みまたはマウントが失敗すると、再読み込み・別ツール選択の案内と復帰用リンクを表示します。`destroy`も世代を更新し、破棄とコンテナの消去を行います。

`main.ts`は同じIDの再選択では再マウントしません。別ツール・ホームへ移動した後に戻る場合は新規マウントとなり、入力・設定・結果を復元しません。History APIには入力状態を格納しません。ホストはimportの競合を、各ツールは自身の通信・コピー・ファイル生成の競合と破棄を担当します。Clipboard APIやXLSX生成自体は中止せず、世代番号・破棄フラグで古い完了処理の表示やダウンロードを抑制します。

## UI・テーマ・アクセシビリティ

### 共通レイアウトとフォーカス

デスクトップはカテゴリ別の左サイドバーと右メイン、幅759px以下は開閉式メニューです。ホームのカードはデスクトップで2列、モバイルで1列です。ヘッダーのブランドリンクとサイドバー先頭の「ホーム」からホームへ戻れます。

`components/layout.ts`は同じサイドバーを通常の配置先と標準`dialog`の間で移動します。モバイルで閉じている間は`hidden`でリンクをフォーカス対象から外します。メニューボタンは`aria-expanded`と`aria-controls`を持ち、`showModal()`によるモーダル制御とTab端点の循環を使用します。開いたときは現在の選択リンク、不明IDなどで選択がなければ閉じるボタンにフォーカスします。

Escape・閉じるボタン・ダイアログ背景のクリックで閉じ、ネイティブのdialog動作でメニューボタンにフォーカスが戻ります。リンク選択時にも閉じ、遷移完了後に`main.ts`が新画面の`h1`へフォーカスします。デスクトップ幅へ変更した場合はメニューを閉じ、サイドバーを通常位置へ戻します。

選択リンクに`aria-current="page"`を付与します。ページタイトルはホームが`Web Toolbox`、ツールが`ツール名 | Web Toolbox`、不明IDが`ツールが見つかりません | Web Toolbox`です。初回表示では見出しへ自動フォーカスせず、リンク選択・履歴移動では現在の画面表示完了後に移します。本文へのスキップリンク、入力ラベル、fieldset/legend、キーボード操作、`:focus-visible`を備えます。

### テーマと状態通知

色・余白・角丸などは`src/styles/main.css`のCSS変数で管理し、ツール固有CSSも両テーマに対応します。システムフォントを使用し、`prefers-reduced-motion`ではアニメーション・トランジションなどを無効にします。

`index.html`のスクリプトはスタイル適用前に手動設定を復元します。未設定時の初期配色はCSSの`prefers-color-scheme`、起動後の配色は`components/theme.ts`が`data-theme`へ反映します。手動設定がない間はOS設定の変更に追従し、手動選択時は選択色を使用します。保存の詳細は次節を参照してください。

コピーは`navigator.clipboard.writeText`を使用します。権限拒否・API非対応などの例外を捕捉し、成功・失敗を`role="status"`で通知します。失敗してもreadonlyの出力欄を残し、手動選択・コピーを可能にします。コピー・生成の非同期完了は、入力変更や破棄後に古い通知を表示しないよう管理します。入力エラーは`role="alert"`や`aria-invalid`で示します。変換結果全文や定期更新する時計はライブリージョンにしません。

## セキュリティ・データ保護

ツール入力・変換結果・取得したIPは、URL・ログ・localStorage・sessionStorageなどへ保存しません。ブラウザ内の画面状態として保持し、切り替え時に破棄します。XLSXの明示的なダウンロードとClipboard APIへの書き込みは利用者操作による出力です。

永続化するアプリ設定は手動選択したテーマのみです。localStorageの`web-toolbox-theme`に`light`または`dark`を保存し、「システム」で削除します。読み書き失敗は捕捉し、保存できなくても現在のテーマ選択とアプリ動作を継続します。

ツールのデータ取得のための外部通信はIP確認のipifyと、IP登録情報検索のRDAP.orgおよび標準リダイレクト先を例外とします。接続先・送信方針・外部依存は各ツールの仕様に記載しています。他ツールの入力を送信する処理はありません。ツールやExcelJS・joseの動的importは同一サイトの配信アセットを読み込みます。外部フォント・解析サービス・外部スクリプトは使用しません。

固定HTMLテンプレートにのみ`innerHTML`を使用し、利用者入力・変換結果・外部レスポンスはフォームの`value`または`textContent`で設定します。MarkdownのHTMLプレビューは行いません。IP・RDAPレスポンスは`unknown`として型と形式を検証します。

## ツール別詳細仕様

以下はREADME・Registryと同じ掲載順です。各ツールのデータ保存・送信の共通方針は前節、テストの実行基盤は[テスト方針](#テスト方針)を参照してください。

### IPアドレス確認 — `ip-address`／ネットワーク

#### 通信と形式検証

`api.ts`はIPv4を`https://api.ipify.org?format=json`、IPv6を`https://api6.ipify.org?format=json`から取得します。`api64.ipify.org`や別サービスへのフォールバックは使用しません。位置情報・ローカルIPは取得しません。

ブラウザから直接通信するため、接続元IPがipifyへ伝わる旨を画面に明記します。fetchには`cache: 'no-store'`、`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`を指定し、アプリ独自のヘッダーや識別情報は追加しません。取得は各IPバージョンの接続環境、DNS、提供元の稼働状況・CORS設定に依存します。IPv6取得失敗だけでIPv6非対応とは判断できない旨も表示します。

HTTP成功後、JSONが非nullのオブジェクトで、`ip`が文字列かつ要求したIP形式であることを確認します。前後の空白除去や表記の正規化はせず、検証した文字列をそのまま返します。検証はアドレスの構文を対象とし、グローバルアドレス範囲の判定は行いません。

- IPv4：4オクテットのASCII十進表記、各0〜255です。先頭ゼロ、符号、空白、全角数字、IPv6を拒否します。
- IPv6：各1〜4桁の16進数8グループ、1回だけの`::`による1グループ以上の省略、末尾IPv4埋め込みに対応します。埋め込みIPv4も上記のIPv4検証を行い、2グループとして数えます。過剰・不足グループ、不正な16進数、空白、角括弧、ポート付き形式、ゾーンIDを拒否します。

内部エラー種別は`network`、`http`、`timeout`、`format`、`aborted`です。不正JSON・`ip`の欠落／型不正・IP形式不正はいずれも`format`、本文読み込み中の通信障害は`network`として扱います。UIは種別に応じた日本語の案内を表示し、画面切り替えによる中止は通信エラーとして通知しません。

#### UI・非同期処理・破棄

表示時に両APIを並行して自動取得します。各リクエストはJSON本文の読み込みを含め10秒でタイムアウトし、自動リトライしません。`api.ts`内のAbortControllerで呼び出し元の中止とタイムアウトを伝え、`finally`でタイマーと中止リスナーを解放します。

IPv4・IPv6は独立した結果・取得状態・コピーボタンを持ちます。一方の失敗で他方の成功を消去せず、先に成功した側は他方の完了前でもコピーできます。共通の再取得ボタンは両方の完了まで無効にし、再取得開始時に両方の旧IPとコピー通知を消去します。

IPv4はreadonly input、IPv6は`rows="1"`のreadonly textareaです。IPv6の高さは取得開始・成功・ウィンドウリサイズ時に`scrollHeight`と枠線幅から再計算します。`field-sizing`に依存せず、折り返した内容全体を表示し、手動リサイズは無効にしています。各パネルの取得状態とコピー結果を別のstatusで通知します。

UIはリクエストのAbortController識別と破棄フラグで、古い取得・コピー完了を無視します。コピー中は該当ボタンを無効にします。再取得開始時に前回のcontrollerを中止し、破棄時にも通信を中止してコピー・再取得・resizeのリスナーを解除します。

#### 主なテスト

`api.test.ts`はHTTP・JSON・両IP形式の境界値、通信障害、本文読み込み中を含む10秒タイムアウト、開始前／実行中の中止、タイマー解放を検証します。`index.test.ts`は両バージョンの成功・失敗の組み合わせ、連打抑止、独立表示、再取得、コピーと破棄後の更新抑制、高さ再計算を検証します。

`tests/ip-address.spec.ts`は表示・再取得・実Clipboard API・エラー復帰・切り替え・狭幅両テーマを、`tests/ip-address-layout.spec.ts`はChromiumとFirefoxで長いIPv6の折り返し、広幅／狭幅間の伸縮、IPv4との高さ、手動選択を検証します。実APIへの到達性はモックテストの保証範囲外です。

### IP登録情報検索 — `rdap-lookup`／ネットワーク

#### 通信・解析

`api.ts`は`https://rdap.org/ip/{IP}`へ直接fetchし、ブラウザ標準のリダイレクトに任せます。問い合わせ先判定・IANA Bootstrap・CORS回避プロキシ・`no-cors`は使いません。`credentials: 'omit'`、`referrerPolicy: 'no-referrer'`、`cache: 'no-store'`を指定し、Acceptを含む独自ヘッダーは追加しません。AbortControllerと10秒タイマーはJSON本文読み込みにも適用し、完了時にタイマーと中止リスナーを解放します。自動リトライはありません。

入力は前後空白を除去し、既存のIP確認APIの`isIpv4`・`isIpv6`を再利用します。`logic.ts`は外部JSONを`unknown`から検証し、`objectClassName: 'ip network'`を要求します。任意フィールドの型不正・欠損は省略し、未知の拡張は生JSONに残します。`cidr0_cidrs`のIPv4／IPv6プレフィックスと整数の長さを検証し、CIDRを表示します。CIDRや所在地をIP範囲から推測しません。

entityを反復処理でネスト内まで走査し、roles・jCardのfn／org／email／tel／adrを型検証して抽出します。orgが配列の場合は先頭成分だけを組織名とし、後続の部署・部門は抽出しません。単一文字列のorgはそのまま扱います。管理組織は明示的なregistrantのorg、なければfnのみから取得し、Abuseメールはabuse役割のみから抽出します。registrantとabuseを兼ねるentityからは両方を独立して抽出します。technical／administrativeなどの公開情報も役割名とともに表示し、役割を推測で補いません。eventsのregistration／last changedは応答の日時文字列を表示します。

#### UI・遷移・破棄

通常表示・直接アクセス・再読み込み・戻る／進むでは自動検索せず、検索ボタン／Enterで検索します。IP確認の成功したパネルだけにRDAPリンクを表示し、再取得時に非表示にします。routerの`setNavigationInput`はリンクをキーとするWeakMapに一時入力を保持します。通常の同一SPAリンク操作時だけcallback→main→tool-host→mountの任意引数に渡し、リンク破棄時にも解除します。URL・History state・永続ストレージへは記録しません。遅い動的importは既存のホスト世代管理に従い、別画面に入力を持ち越しません。修飾キーや別タブ操作は通常リンクのままで、入力を引き継ぎません。

検索中はstatusで通知し、新規検索と入力変更は以前の通信を中止して結果を消去します。世代番号と破棄フラグで中止を無視する古い応答・コピー完了も反映しません。破棄時は通信とイベントリスナーを解除します。

ネットワーク情報、管理組織とAbuse、役割別連絡先、登録情報、RDAPサーバーリンク、生JSONのdetails／コピーを表示します。欠損は省略または「情報なし」とし、国コードが実際の所在地を保証しないことを明示します。外部値はtextContentだけで描画し、リンクは認証情報を含まない絶対HTTPS URLだけを許可し、noopener／noreferrerを付けます。

404・429・その他HTTP・通信障害・timeout・不正JSON・非IP Network応答を区別します。ブラウザで区別できない通信障害をCORSと断定しません。失敗時は検証済み入力IPから生成したRDAP.org外部確認リンクを表示します。検索対象IPと接続元IPがRDAP.orgと転送先へ伝わることを画面に明記します。

#### 検証範囲

`logic.test.ts`はネットワーク・CIDR・roles・jCard・深いentity・欠損・未知拡張・安全なURLを、`api.test.ts`はIPv4／IPv6・fetch設定・HTTP・JSON・通信・本文読み込み中を含むtimeout・Abort・タイマー解放を検証します。`index.test.ts`は明示検索・エラー・再検索競合・入力変更・破棄後の更新抑止・安全なJSON表示とコピーを確認します。router／hostも一時入力の受け渡しを検証します。`tests/rdap-lookup.spec.ts`は検索・JSONコピー・非保存・IP確認からの遷移・履歴・エラー復帰・320px両テーマ・キーボード操作をモックAPIで検証します。

実サービスへのブラウザ接続・CORSはモックテストでは保証しません。RIRごとの接続確認は自動テストと分けて実施し、確認したOrigin・ブラウザと未確認事項を報告します。

### 全角・半角変換 — `width-converter`／テキスト・データ

#### 入出力とUnicode規則

`logic.ts`の純粋関数`convertWidth(input, direction, categories)`が変換を担当します。方向は`to-half`／`to-full`、カテゴリは英数字・記号・カタカナ・スペースの4つです。初期値は全角→半角、英数字・スペースON、記号・カタカナOFFです。記号はチェックボックスをONにすると変換します。全OFFでは入力をそのまま出力します。入力値自体は書き換えず、readonly textareaへ結果を表示します。

| カテゴリ | 変換範囲と制約 |
| --- | --- |
| 英数字 | ASCIIの`0–9`・`A–Z`・`a–z`と対応する全角英数字です。 |
| 記号 | ASCII U+0021–U+007Eから英数字を除いた文字と、対応するU+FF01–U+FF5Eです。チルダU+007E ↔ U+FF5E、バックスラッシュU+005C ↔ U+FF3Cを含みます。波ダッシュU+301C、円記号U+00A5・U+FFE5は保持します。 |
| カタカナ | 半角U+FF61–U+FF9Fに対応するカナ・小書き・長音・中黒・日本語句読点・濁点／半濁点です。句読点は記号カテゴリに依存しません。 |
| スペース | U+0020 ↔ U+3000のみです。タブ・改行・その他のUnicode空白は保持します。 |

カタカナ対応表は既知の半角1文字と、濁点・半濁点との組から生成します。NFKCを適用するのは対応表生成と、半角→全角の既知の半角カナおよび直後の濁点（半角または結合文字）の範囲だけです。全文を正規化しないため、丸数字・ローマ数字などの互換文字を変化させません。

合成済みのガ・パ・ヴ・ヷ・ヺなどと対応するカナ＋結合濁点に対応します。全角→半角では結合濁点U+3099・U+309A、幅のあるU+309B・U+309Cを半角U+FF9E・U+FF9Fへ変換します。半角→全角では単独の半角濁点・半濁点を結合文字U+3099・U+309Aにし、結合不能な組は基底カナと結合文字の並びになります。

ひらがなに続く結合濁点・半濁点はまとめて保持し、濁点だけを変換しません。ひらがな、ヵ・ヶ・ヮなど半角対応のないカナ、未選択カテゴリ、その他の非対応Unicodeも保持します。単独濁点などの扱いにより、全Unicodeで完全な往復一致は保証しません。

初期設定では`ＡＢＣ１２３！＠＃　ガギグ`が`ABC123！＠＃ ガギグ`になります。記号をONにすると`ABC123!@# ガギグ`になります。空入力は空出力となり、非対応文字を入力エラーにはしません。

#### 更新・コピー・破棄

入力・設定変更で同期変換します。`compositionstart`でIME変換中とし、その間と`InputEvent.isComposing`がtrueの入力イベントでは更新を抑制します。設定変更も変換中は保留します。`compositionend`で更新し、その後の最終inputも受け付けてイベント順序の違いに対応します。クリアは入力と変換中状態をリセットし、入力欄へフォーカスします。

コピー中は連打を防止し、入力・設定変更やIME開始で更新した世代番号により古い通知を抑制します。破棄時はフラグを立て、AbortControllerで全リスナーを解除して表示を削除します。

`logic.test.ts`は全カテゴリ・両方向、ASCII全94文字、半角カナ全範囲、合成／結合濁点・単独濁点・結合不能な組、ひらがなの保護、非対象Unicode、空入力・長文を検証します。`index.test.ts`はコピー成功／失敗が破棄後のDOMを更新せず、イベントも解除されることを検証します。

### Markdown表変換 — `markdown-table`／テキスト・データ

#### 共通モデルとMarkdown解析

`logic.ts`は`TableData = { rows: string[][] }`を共通モデルとし、`parseMarkdown`・`parseTsv`・`toMarkdown`・`toTsv`を提供します。先頭行をヘッダーとして扱います。すべての方向で列数の不一致をエラーにし、補完・切り捨てを行いません。

Markdownは単一表を対象とし、先頭行がヘッダー、2行目が必須区切りです。区切りセルはハイフン3個以上で、`---`、`:---`、`---:`、`:---:`を受理します。配置情報は保持しません。外側パイプは省略可能、前後の空行は無視、途中の空行はエラー、空白のみの入力は空表です。行区切りCRLF／CRはLFへ揃えます。

パイプ直前の連続バックスラッシュが偶数なら列区切り、奇数ならセル内容として扱います。コードスパン内でもパイプのエスケープが必要です。外側パイプの外にあるASCIIスペース・タブは無視します。セル両端のASCIIスペース各1文字のみを構文の余白として除去し、それ以上の空白・タブ・全角空白は保持します。幅揃えの多数のスペースも内容になります。端の空セルと外側パイプの曖昧さを避けるため、空セルがある表は外側パイプ付きの形式が適しています。

装飾・HTMLエンティティは解釈せず保持します。`<br>`、`<br/>`、`<br />`（大小文字不問）のみLFへ変換します。同じ長さのバッククォート列で閉じるセル内コードスパンではタグを文字列として保持し、閉じないバッククォートは通常の文字として扱います。通常部分ではバックスラッシュをパイプ・バックスラッシュ・`<`・バッククォートの前だけエスケープとして解釈し、エスケープされた`<`からは改行タグを認識しません。コードスパン内で解除するエスケープはパイプとバックスラッシュのみです。

完全なCommonMark/GFMパーサーではありません。属性付きタグ、コードブロック、HTML構文の入れ子などは解析対象外です。複数表・結合セル・HTMLプレビューには対応しません。

#### TSV解析と出力規則

TSVは状態機械で解析し、セル全体を囲む引用符、引用符内部の`""`、セル内タブ・改行、空セル・末尾空セルを扱います。行区切りはCRLF／LF／CRです。閉じない引用符、囲みの外の引用符、閉じ引用符後の区切り以外の文字はエラーです。引用符内の改行は解析時にはそのまま保持します。

空文字だけを空表とし、空白文字はセル内容です。最終改行1つは行終端として扱い、追加の空行は空セル1つの行として列数を検証します。`""`は空セル1つ、タブだけなら空セル2つです。

- TSV出力：行区切りCRLF、列区切りタブです。タブ・改行・引用符を含むセルを引用符で囲み、内部の引用符を二重化します。1列だけの空セルも`""`とし、空表と区別します。
- Markdown出力：外側パイプとASCIIスペース各1文字を付け、標準`---`区切り、行区切りLFで生成します。バックスラッシュ・パイプ・バッククォートと文字列としてのbrタグをエスケープし、実際のセル内CRLF／LF／CRだけを`<br>`へ統一します。

textareaはCRLFをLFへ正規化するため、コピー時は表示欄の値ではなく共通モデルから再生成します。TSVをExcelへ貼り付ける際の数値・日付・数式への自動型判定は完全には制御できません。文字列型の確実な保持にはXLSX出力を案内します。

モデルの往復検証は矩形の文字列表（空表以外は1列以上）を対象とします。TSVはセル内のCRLF／LF／CRも含めて保持します。Markdownの完全一致の往復はセル内改行がLFのモデルに限り、CRLF／CRはLFに正規化した値を期待します。Markdown原文の配置指定・区切り・余白などの構文を再現する保証はありません。

#### XLSX生成

`xlsx.ts`はExcelJS 4.4から移行した`exceljs-community` 5.2.1（MIT）を使用します。既存のXLSX出力仕様を維持しながら依存を置き換え、ブラウザ用ビルドと文字列型・書式・列幅・折り返しのAPIを利用します。バージョンは固定し、推移依存はlockfileで管理します。現行のVitest設定でNode向けエントリが動作するため、専用aliasは設定していません。

ダウンロード時だけ`import('./xlsx')`し、入力・変換・TSVコピーでは読み込みません。ExcelJSを含む生成用コードは遅延チャンクとなるため、初期ロードに含まれません。具体的なバンドルサイズは固定仕様にせず、必要時に`npm run build`の出力で確認します。

出力ファイルは`table.xlsx`、ワークシート名は`Table`です。全セルを文字列で設定し、表示形式`@`、折り返し・上揃え、1行目太字とします。セル内のCRはOOXMLのエスケープ表現にしてXMLの改行正規化を避け、入力中のエスケープ風文字列も保護します。列幅は各行のセルを改行で分け、コードポイントが255以下なら1、それ以外なら2として数えた長さに余白2を加え、8〜60の範囲に制限します。ExcelJSによる幅9の列の省略を防ぐため、列にも表示形式`@`を設定します。

数式オブジェクトを使用しないため、先頭ゼロ、長い数字、日付風・数式風文字列を文字列型として保持します。上限は1,048,576行、16,384列、1セル32,767で、セル長はJavaScriptの`string.length`（UTF-16コード単位）で判定します。超過は切り詰めず生成エラーにします。XLSXのアップロード・読み込みには対応しません。

#### UI・非同期処理・破棄

初期方向はMarkdown→Excelです。方向・入力の変更で再計算し、空表ではコピー・ダウンロードを無効にします。解析エラー時は古い結果を消去し、操作を無効にしてalertと`aria-invalid`で通知します。Excel→Markdownではダウンロードボタンを隠します。クリアは入力を空にして入力欄へフォーカスします。

コピーと生成それぞれの連打を防ぎ、世代番号と破棄フラグで入力・方向変更前や破棄後の完了を無視します。XLSXはimport後と生成後の両方で確認するため、古い入力のファイルをダウンロードしません。生成失敗はstatusで通知します。Object URLはダウンロード開始操作の1秒後、またはツール破棄時に解放します。破棄時はタイマーも解放し、AbortControllerでリスナーを解除します。

#### 構文・図の意味・制約

regexppのECMAScript 2025として解析します。フラグは`d g i m s u v y`、`u/v`は排他です。ブラウザの`RegExp`によるコンパイルやマッチングは行わないため、そのブラウザでの実行可否を保証するツールではありません。

- 連続文字は文字列、選択は並列経路、空の選択は「空（0文字）」とします。空白をtrimしません。スペースは`␣`、制御文字・不可視文字・XML非対応文字・単独サロゲートは可視のコードポイント表記にします。
- 文字クラス・範囲・Unicodeプロパティは原文を表示します。v集合の`&&`は共通部分、`--`は差集合と明記し、入れ子・`\q{…}`も保持します。集合を列挙・計算しません。文字列プロパティもパーサーの構文として受理します。
- `* + ? {m} {m,} {m,n}`と非貪欲形を、合計回数・優先順位のラベルと矢印付きの迂回・反復線で表現します。線だけで回数を決めず、ラベルの合計回数が制約です。巨大な回数も原文のラベルだけで示し、回数分のメモリを確保しません。`{0}`と`{0,0}`は本体を通りません。
- 捕捉グループにソース順の番号と名前を付け、非キャプチャと区別します。ECMAScript 2025の局所フラグも枠に明記し、`m/s`の変更は内部だけに反映します。選択肢間の重複名はregexppの規則に従います。
- 後方参照は点線の参照ノードと捕捉先番号で示し、捕捉先へ実行経路を接続しません。捕捉文字列に一致することと、未参加・前方参照が空文字列に一致し得ることを注意欄に明記します。
- アンカー・単語境界・肯定／否定先読み・後読みは**0文字の条件**です。主経路には条件ノードだけを置き、先読み・後読みの内部図は別セクションに置きます。後読みの内部はソース順表示で、実際の評価は右→左と明記します。入れ子の条件も独立した番号にします。
- `i`による文字集合の展開、検索開始位置、バックトラッキング順、全到達不能経路の判定は行いません。`d/g/y`は検索時の動作であり構造の分岐を増やしません。空の文字クラスには意味上の注意を出しますが、集合演算の結果が空になる場合などの完全な意味解析は行いません。

構文エラー、安全上限、描画エラーは区別してalertに表示し、構文エラーだけ入力を`aria-invalid=true`にします。regexppのエラー位置はUTF-16オフセットを1始まりで表示します。意味上の注意は構文エラーとは別欄です。空入力・空の選択・一致しない集合も明示的に描き、無言の空白を返しません。パーサーの診断本文は英語の場合があります。

図はmain.cssの既存カラートークンのライト／ダーク両配色と背景矩形・システムフォントをSVG内に持ちます。ホストのCSS変数がBlob内のSVGへ継承されないため、メインスレッドで保持するテーマ非依存の基本SVGに固定のdata-theme属性を追加して表示・保存します。テーマ変更はルート属性のMutationObserverで検知し、Workerの再起動・再解析は行いません。保存後は環境のテーマに依存せず保存時の配色を維持します。周辺UIは既存CSS変数を使用します。量指定子は上側に右向きの省略経路、下側に左向きの戻り経路をまとめ、囲み枠はグループに限定します。短い図と各セクションの経路は中央に配置します。デスクトップでは自然幅の80%を下限として表示領域に合わせ、モバイルでは原寸表示します。それ以上に広い図はキーボードで操作できる図の枠内に横・縦スクロールを限定します。保存するSVGは原寸のままです。

#### Worker・上限・リソース管理

`protocol.ts`にメッセージと共有定数、`runner.ts`にWorkerの生成・停止・世代管理、`worker.ts`に解析・描画の入口を分離します。UIは入力変更直後に旧図・警告・エラー・ダウンロードを無効化し、旧Workerをterminateしてから200msデバウンスします。IME変換中は停止し、確定後に更新します。空文字も解析対象です。「解析を中止」で待機・実行の両方を中断できます。

最新入力ごとにWorkerを作成し、結果返却時・エラー時・4秒タイムアウト時に停止します。キューに残ったイベントも世代番号で破棄します。ツール破棄時はWorker・デバウンス・期限タイマー・イベントリスナー・表示用URL・ダウンロード用URLを解放し、テーマ監視を解除します。画像のload/errorも入力世代・表示URLと破棄状態を確認し、旧画像イベントが新しい画面の操作を有効化しないようにします。

| 上限 | 理由 |
| --- | --- |
| 入力4,096 UTF-16コード単位 | 一般的な手書き式を収めつつ、Workerへの巨大な文字列コピーと解析前のメモリを抑える。超過はWorker起動前にも拒否 |
| 800 ASTノード・深さ48 | 小さな文字列でも選択・入れ子で膨らむ描画を抑え、再帰処理とDOM相当要素数を制限。regexppのVisitorで計測し循環参照をたどらない |
| 各辺16,000px・面積1,200万px | ブラウザの画像描画寸法とラスタライズ負荷を抑える。RGBA単一面相当は最大約48MBだが、実ブラウザの総メモリ量を保証する値ではない |
| SVG100万文字 | レイアウト後のシリアライズ・メインスレッドへの転送・Blob確保を制限 |
| Worker処理4秒（起動時間込み） | 解析自体の病的入力・低速環境でも強制終了し、UIを応答可能に保つ |

どの上限でも切り詰めた図は表示せず、分割を促します。AST制限より前のパーサー再帰エラーも制限として通知し、応答しないWorkerは期限で停止します。小さい端末や低速端末でも無制限の負荷にならないことを優先した上限です。

入力・結果・診断はURL、History state、ストレージ、ログに保存せず、外部送信・CDN・追加フォントも使いません。正規表現を実行しないため、入力を対象文字列へ適用するReDoSも発生させません。解析・描画自体の負荷には前述の制限を適用します。

描画要素は`svg/g/path/rect/circle/text/title/desc/style`だけをアダプターが生成し、属性・CSS・パスへユーザー入力を挿入しません。ラベルはXML特殊文字をエスケープし、XML 1.0非対応文字と単独サロゲートは可視化します。外部参照・リンク・イベント属性・スクリプト・foreignObjectは生成しません。UIの固定HTML以外は`textContent/value`で扱います。

### JST・UTC日時変換 — `datetime`／日時

#### 時計と24時間対応表

現在のJST・UTC年月日時分、JST基準の日付選択と24時間対応表、詳細変換の順に表示します。時計は60秒間隔とタブ再表示時に更新し、詳細入力を上書きしません。時計をライブリージョンにはしません。

表はJST 00:00〜23:00の24行で、UTCの時分と「前日／同日」を表示します。JST 00〜08時はUTCの前日、09〜23時は同日です。日付の初期値はJSTの今日で、「今日へ戻る」で復帰します。不正日付は補正せず、エラーを表示して表を空にします。

選択日がJSTの今日なら現在の時間帯を背景色と「現在」で示します。選択行は左線・ボタン枠・「選択中」および`aria-pressed`で区別します。時刻ボタンはキーボードで選択でき、詳細欄をJST・表の日付・選択時刻の00秒に設定します。詳細の日時が表の行の瞬間と一致した場合も選択表示になります。

日付をまたいでも表の選択日付を自動変更せず、今日と異なれば現在時間帯のハイライトを消します。詳細欄のUTC選択や「現在時刻を入力」は表の基準日付を変えません。

#### 入出力・境界条件

詳細入力はJST／UTC、`YYYY-MM-DD`の日付、時分秒です。時刻は`HH:mm`または`HH:mm:ss`を受理し、秒省略時は00秒です。変更時に即座に変換します。「現在時刻を入力」は選択ゾーンの現在日時を秒まで設定し、初回マウントでも現在のJST日時を設定します。

出力はJST日時・UTC日時（通常`YYYY-MM-DD HH:mm:ss`）、ISO 8601（UTC、末尾Z、秒精度）、整数のUnix秒・ミリ秒です。各値に個別コピーとreadonly欄を設けます。ISO・Unix timeは出力専用です。

入力年は0001〜9999年の先発グレゴリオ暦です。日付・時刻は厳密に検証し、不正値をDateの自動補正に任せません。1900年は平年、2000年はうるう年として扱います。24:00、うるう秒、ミリ秒入力は非対応です。不正入力では出力を消去し、コピーを無効にします。

変換境界の出力は0000年・10000年も扱います。例えば`0001-01-01 00:00:00 JST`のUTCは`0000-12-31 15:00:00`、`9999-12-31 23:59:59 UTC`のJSTは`10000-01-01 08:59:59`です。入力としてその年を受理するわけではありません。1970年以前の負のUnix timeにも対応します。

`logic.ts`はUnixミリ秒を基準とし、JSTを全期間UTC+09:00固定で計算します。歴史上の時差や夏時間を再現しません。UTC getterと`setUTCFullYear`を使い、0〜99年が1900年代になるDateの特殊処理と端末のローカルタイムゾーンへの依存を避けます。`Date.parse`による入力解釈は行いません。

#### コピー・破棄・主なテスト

コピー成功・失敗をstatusで通知し、入力更新の世代番号と破棄フラグで古い完了通知を抑制します。破棄時は時計タイマーを止め、AbortControllerで入力・ボタン・`visibilitychange`などのリスナーを解除します。

`logic.test.ts`は全24行、月末・年末・うるう年・0〜99年・入出力年境界、不正入力、秒省略、ISO・Unixの正負出力を検証します。epochの前後1秒と0秒、UTC／JSTの往復、入力範囲外になる境界出力も確認します。ローカル依存性はNode.js 26のTypeScript読み込みで別プロセスを起動し、`UTC`・`Asia/Tokyo`・`America/Los_Angeles`・`Pacific/Kiritimati`で夏時間切り替え日の変換・24時間表を比較します。`index.test.ts`は固定時計とfake timerで日付境界・再表示・破棄、コピー待機中の変更／破棄を確認します。

`tests/datetime.spec.ts`は固定時計と`America/Los_Angeles`のローカルゾーンで、表とハイライト、日付・行の選択、詳細変換、不正入力、実コピーと失敗、モバイル両テーマ、時間帯更新、切り替えを検証します。

## JWTデバッガーの詳細

`sample.ts`に公開学習用のUTF-8 Secretと、事前にHS256署名した固定Compact JWSを定義します。mount時に入力へ設定して既存のdecodeを実行し、署名は未検証のまま操作を待ちます。初期デモSecretはJWT入力変更時に消去しますが、Secretを手動編集した時点で初期値扱いを解除し、以後のJWT変更では保持します。アルゴリズム変更とクリアでは従来どおりキーを消去します。クリア後は空のまま、再読み込み・ツール復帰による新しいmountでのみサンプルを再設定します。入力やキーは保存しません。

`jwt-debugger`をテキスト・データカテゴリへ登録。`logic.ts`は256KiBのUTF-8入力上限、3セグメント、厳密なBase64URL（非ゼロ末尾ビットも拒否）、fatal UTF-8、JSONオブジェクトを検証し、形式別エラーを返します。Header/Payloadは配列・nullを拒否。署名空欄はnoneのデコード用途として許容します。

Claimsはiss/sub/aud/exp/nbf/iat/jtiを説明し、audの文字列配列も扱います。NumericDateは有限数値で評価し、expは現在時刻がexp以上で期限切れ、nbfは現在時刻が到達したら利用可能、未来iatは警告のみです。UTC/JST双方のDate表現範囲を確認し、小数秒の比較はNumber値で行います。表示はDateのミリ秒精度、JSTはUTC+09:00固定です。1秒ごとに端末時計で再評価し、破棄時にタイマー解除します。発行者・Audienceの期待値照合、時計ずれ許容値は扱いません。

`verify.ts`は検証操作時のみバンドル済みjoseを動的importし、compactVerifyで署名だけを確認します。明示選択したHS256/RS256/ES256の許可リストとHeaderのalg一致を要求し、importSPKIとjose/Web Cryptoでキー種別・曲線等を確認します。none、その他alg、b64:falseやcrit拡張は検証不可。Base64 Secretはパディングを含む標準Base64を厳密にデコードします。エラーは固定メッセージに置換し、入力やライブラリエラーをログに出しません。

UIは安全なvalue/textContent、readonly出力、独立したClaims・署名状態を使用します。入力・キー・方式変更、クリア、破棄で世代を更新し、検証・コピー完了時に世代と破棄状態を確認します。中止不能な暗号処理は完了後の表示を抑制し、破棄時はリスナー・タイマー・DOM入力と表示をクリアします。JavaScript文字列やWeb Crypto内部メモリの物理消去は保証できません。外部取得、URL/History/ストレージ/Cookie保存は行いません。

隣接Vitestテストは形式・Unicode・NumericDate境界、実際にテスト用キーで署名したHS256/RS256/ES256の成功・不一致・改ざん・不正キー・非対応alg、UI競合・破棄・非保存を検証します。`tests/jwt-debugger.spec.ts`は実署名、コピー成功/失敗、直接アクセス・再読み込み・履歴、両テーマ・狭い幅・キーボード、非通信・非保存を確認します。

JWTの表示・コピーは`json.ts`で構文検証済みの元JSONを字句単位に走査し、文字列外の空白のみ整形します。数値トークン・文字列リテラル・キー順・重複キーを保持し、Number値の再出力は行いません。深いJSONの出力膨張を抑えるためインデントは32階層で上限にします。`decodeJwt`は元のUTF-8文字列、表示JSON、解析済みオブジェクトを分離して返します。

日時Claimsはトップレベルの数値トークンをNumberの最短十進表記と係数・桁位置で比較します。丸め、オーバーフロー、アンダーフローで十進値が変わった場合は日時・期限判定を控え、精度警告を表示します。通常の0.1等の小数は従来どおり受理します（IEEE 754の二進表現が十進小数と完全一致することは要求しません）。巨大指数を展開せず、重複キーはJSON.parseと同じく最後の値に対応させます。表示の精度保持と、Number／Dateによる評価・ミリ秒表示の制約は独立しています。

JWT入力・Header・Payloadの色分けは`highlight.ts`が元の表示文字列を字句走査し、`textContent`とテキストノードだけで描画します。JSONの数値・エスケープ・重複キーを再生成しません。JWTの3セグメントはオレンジ・パープル・グリーン、JSONのキー・文字列・数値・真偽値/nullはブルー・グリーン・オレンジ・パープルで表示します。各色はライト／ダーク別のツール内CSS変数で定義します。

操作とコピー・デコード・検証の正本は従来の`textarea.value`です。背面の`pre`は`aria-hidden`・`pointer-events: none`とし、フォント・行高・余白・折り返しを揃え、scrollイベントとResizeObserverで表示領域とスクロールを同期します。変換中のIME、forced-colors、印刷、ResizeObserver非対応環境では通常のtextarea文字表示を使用します。字句が不正な場合、表示文字列が256Ki UTF-16コード単位を超える場合、JSONの表示トークンが2,048個を超える場合も色分けを省略し、非表示層のレイアウト負荷を避けます。これは描画専用の制限で、デコード・署名検証の256KiB上限や可否を変更しません。表示層の文字列を解析・コピーに使わず、破棄時は監視とイベント・表示内容を解放します。

ハイライト単体テストでは分類、ネスト・配列・Unicode、数値リテラルと文字列の完全保持、HTMLの安全性と描画上限を確認します。UI単体テストでは表示層の改変が検証・コピーへ影響しないこと、監視の破棄、描画上限とデコードの独立性を確認します。JWT E2Eでは両テーマ、選択コピー・貼り付け・Undo/Redo、長文の折り返し・スクロール・リサイズ、320px、IMEイベントとforced-colorsへの切り替えを検証します。IMEは合成イベントによる確認で、実際のOS IMEやSafari/WebKitは自動検証の対象外です。
