# Web Toolbox

**[公開サイトを開く](https://arscombinatoria.github.io/web-toolbox/)**

![Coverage](https://arscombinatoria.github.io/web-toolbox/coverage.svg)

ブラウザで使える小さな便利ツール集です。IPアドレス確認、全角・半角変換、Markdown表変換、正規表現の可視化、JST・UTC日時変換を提供する、バックエンドを持たない静的SPAです。

トップページのカードやサイドバーからツールを選べます。ヘッダーの「Web Toolbox」またはメニューの「ホーム」からトップページに戻れます。個別URLへの直接アクセス、再読み込み、ブラウザの戻る・進むに対応しています。モバイルではヘッダーからメニューを開けます。

入力・変換結果は原則ブラウザ内で処理し、URL・ログ・永続ストレージに保存しません。ツールを切り替えると入力は破棄されます。**IPアドレス確認ではipifyへ、IP登録情報検索では検索対象IPをRDAP.orgと転送先へ送信します。** トップページの表示だけでは外部サービスへの通信は行いません。

テーマは初期状態でOS設定に従います。ライト・ダークの手動選択だけをlocalStorageに保存し、「システム」を選ぶと解除します。ストレージが利用できなくても動作します。各ツールの出力はコピーボタンを使うほか、コピーに失敗した場合も選択して手動でコピーできます。

## IPアドレス確認

ツールを開くとグローバルIPv4・IPv6アドレスを自動取得します。それぞれの結果をコピーでき、「再取得」で両方を取得し直せます。一方の取得に失敗しても、他方の成功結果は表示します。10秒でタイムアウトし、自動リトライは行いません。

ブラウザからipifyのIPv4用API（`https://api.ipify.org?format=json`）とIPv6用API（`https://api6.ipify.org?format=json`）へ直接通信するため、**接続元IPアドレスがipifyに伝わります。** 取得したIPアドレスは保存せず、位置情報やローカルIPは取得しません。

取得結果は各IPバージョンの接続環境、DNS、提供元の稼働状況・CORS設定に依存します。IPv6の取得失敗だけではIPv6非対応とは判断できません。

## IP登録情報検索

IPv4・IPv6を入力し「検索」またはEnterでRDAP登録情報を取得します。通常の画面表示では自動検索しません。IPアドレス確認で取得に成功した各IPの「登録情報を検索」からは、そのIPを引き継いで検索します。この引き継ぎは同一SPA内のメモリだけを使い、戻る・進む・再読み込みでは検索を再実行しません。

RDAP.org（`https://rdap.org/ip/{IP}`）へブラウザから直接問い合わせ、標準リダイレクト先のネットワーク名・IP範囲・CIDR（応答にある場合）・国コード・種別・ステータス、管理組織・Abuseメール・公開連絡先、登録・更新日時を表示します。欠損項目は省略または「情報なし」とし、登録国は実際の所在地とは限りません。元のJSONは折りたたみ表示で確認・コピーできます。

**検索対象IPと接続元IPがRDAP.orgおよび転送先のRDAPサービスへ伝わります。** 入力・結果・連絡先情報は保存しません。10秒でタイムアウトし、自動リトライは行いません。新しい検索・入力変更・画面切り替えで古い通信を中止します。接続・サービス・CORS設定などで取得できない場合は、検証済みIPのRDAP.org外部確認リンクを表示します。RIR別判定・Bootstrap・CORS回避プロキシは使用しません。

## 全角・半角変換

テキストを入力し、変換方向と対象カテゴリ（英数字・記号・カタカナ・スペース）を選ぶと結果を更新します。初期設定は「全角 → 半角」で、英数字・スペースがON、記号・カタカナがOFFです。記号も変換する場合はチェックボックスをONにしてください。すべてOFFにすると入力をそのまま出力します。日本語IMEの変換中は更新を保留し、確定後に反映します。

例：`ＡＢＣ１２３！＠＃　ガギグ` → 初期設定では`ABC123！＠＃ ガギグ`、記号をONにすると`ABC123!@# ガギグ`になります。

英数字・記号はASCIIと対応する全角文字、カタカナは半角に対応するカナ・句読点・濁点など、スペースは通常の半角・全角スペースが対象です。タブ・改行、丸数字・ローマ数字・ひらがな、半角対応がないカナ（ヵ・ヶ・ヮなど）は保持します。波ダッシュ`〜`や円記号`¥`・`￥`も変換対象外です。

全文のUnicode正規化は行いません。単独濁点などの扱いにより、すべての文字で完全な往復一致を保証するものではありません。文字ごとの対応範囲は[詳細設計書](docs/architecture.md)に記載しています。

## Markdown表変換

変換方向を選んで表を貼り付けます。

- **Markdown → Excel**：Markdown表からExcel貼り付け用TSVをコピーするか、`.xlsx`をダウンロードできます。XLSXは全セルを文字列型で出力し、先頭ゼロ、長い数字、日付風・数式風文字列を保持します。ヘッダーは太字、列幅は上限付きで調整し、セル内改行は折り返して表示します。
- **Excel → Markdown**：Excelでコピーしたセル範囲をTSVとして貼り付けます。先頭行をヘッダーとし、標準の`---`区切りを生成します。引用符付きのタブ・改行・二重引用符、空セル・末尾空セルに対応します。**XLSXファイルの読み込み・アップロードには対応しません。**

**TSVをExcelへ貼り付ける際の自動型判定（数値・日付・数式）は完全には制御できません。文字列型を確実に保持する場合はXLSXダウンロードを利用してください。** XLSXの行・列・セル文字数上限を超える場合は、切り詰めずに生成エラーにします。

単一表のみを扱い、Markdownでは2行目に区切り行が必要です。列数不一致、不正な区切り行・引用符はエラーになります。配置指定は読み取れますが、配置情報は保持しません。複数表・結合セル・完全なCommonMark/GFM構文の解釈には対応しません。

`<br>`、`<br/>`、`<br />`はセル内改行と相互変換します。コードスパン内とエスケープされたタグは文字列として保持し、その他の装飾・HTMLは解釈しません。セル内のパイプはコードスパン内でもエスケープが必要です。セル両端のASCIIスペース各1文字を構文上の余白として除去し、それ以上は保持します。詳しい空白・改行・エスケープ規則は[詳細設計書](docs/architecture.md)を参照してください。

## 正規表現の可視化

`/`で囲まずにJavaScript（ECMAScript）のパターンを入力し、`d g i m s u v y`のフラグを選びます。`u`と`v`は排他選択です。前後の空白は保持し、入力から200ms後に自動更新します。空入力は「空（0文字）」として描画します。

文字列・文字クラス・範囲・選択・貪欲／非貪欲の量指定子、キャプチャ／非キャプチャ／名前付きグループ、後方参照、先読み／後読み・否定、アンカー・単語境界、Unicodeプロパティと`v`の集合演算に対応します。図をブラウザ内に表示し、単体表示可能な`regex-diagram.svg`をダウンロードできます。

**破線の条件は文字を消費しません。** 先読み・後読みの内部図は主経路から分離し、後読みはソース順の構造図に「評価は右→左」と明記します。後方参照は捕捉文字列への参照として区別します。繰り返しは枠の合計回数と優先順位で制約し、回数分に展開しません。文字クラス・Unicode集合の内部は原文表記で、文字一覧への展開や集合計算は行いません。マッチング・置換・実行順の再現・完全な到達可能性検証は対象外です。

解析には`@eslint-community/regexpp`（MIT）を使い、専用の小さなSVG描画アダプターを組み合わせています。処理はWeb Worker内で行い、入力変更・中止・画面切り替え時に停止します。構文エラー（可能ならUTF-16の位置）・安全上限・描画エラーを表示し、古い図は即座に消去します。意味上の注意は別欄に表示します。

安全上限は入力4,096 UTF-16コード単位、800 ASTノード、深さ48、図の各辺16,000px・面積1,200万px、SVG100万文字、処理4秒です。超過時は切り詰めずに通知します。図は選択中のライト・ダークテーマに合わせて表示・SVG保存し、大きな図は図の枠内でスクロールできます。入力・SVGは送信・保存しません。ライブラリ評価、上限の理由とセキュリティ対策は[詳細設計書](docs/architecture.md)を参照してください。

## JST・UTC日時変換

現在のJST・UTC日時と、JST基準の24時間対応表を表示します。現在日時は約1分ごととタブ再表示時に更新します。表の日付の初期値はJSTの今日で、「今日へ戻る」で戻せます。今日の現在時間帯と選択行を区別して表示します。

表の時刻を選ぶか、詳細欄にJST／UTC・日付・時分秒を入力すると、JST日時・UTC日時・ISO 8601（UTC・末尾Z）・Unix timeの秒／ミリ秒を即時出力し、個別にコピーできます。「現在時刻を入力」で詳細欄に現在日時を設定できます。時計の定期更新は詳細入力を上書きしません。

**ISO 8601とUnix timeは出力専用です。** 詳細欄でUTCを選んでも、表はJST日付基準です。入力年は0001〜9999年（先発グレゴリオ暦）、精度は秒で、変換境界の出力は0000年・10000年も扱います。JSTは全期間UTC+09:00固定で、端末のタイムゾーンに依存しません。不正な日時は補正せずエラーにします。うるう秒・ミリ秒入力には対応しません。Unix timeは1970年以前の負数にも対応します。

## 技術スタック・動作環境

- Vanilla TypeScript（strict）、Vite、HTML/CSS、ブラウザ標準APIを使用しています。
- 単体テストはVitest + jsdom、E2EテストはPlaywrightを使用しています。
- 開発・CIではNode.js **24 LTS**とnpmを使用します。メジャーバージョンは`.nvmrc`と`package.json`の`engines`で指定しています。
- モダンブラウザを対象としています。自動E2E検証はChromiumの詳細シナリオと、Chromium・Firefox共通の主要機能スモーク／IPアドレス欄のレイアウトを対象としています。

UIフレームワーク、外部フォント、アイコンライブラリは使用していません。XLSX生成にはExcelJS 4.4（MIT）を使用し、ダウンロード操作時に同一サイトのバンドルから動的に読み込みます。

## ローカル開発・テスト

### 起動

```sh
nvm use
npm ci
npm run dev
```

[ローカル開発サーバー](http://localhost:5173/web-toolbox/)を開いてください。`nvm`を使用しない場合は、Node.js 24を別途インストールしてください。

### テスト・ビルド

```sh
npm test
npm run test:badge
npm run build
npx playwright install --with-deps chromium firefox
npm run test:e2e
```

`npm run build`には型チェックを含むため、上の手順で別途実行する必要はありません。型チェックのみを行う場合は`npm run typecheck`を使えます。初回はPlaywrightのブラウザとOS依存パッケージのインストールが必要です。

E2Eはビルド済みの`dist/`をVite previewで配信し、実際の`/web-toolbox/`配下で検証します。`tests/smoke.spec.ts`ではIP表示・再取得、文字幅の双方向変換、Markdown／TSV変換、日時変換、RDAP検索・JSON表示、基本ナビゲーションをChromium・Firefoxの両方で確認します。`tests/ip-address-layout.spec.ts`も両ブラウザで実行し、IP欄の高さ・折り返し・画面幅への追従を両テーマで検証します。RDAPの検索・JSON・IP確認からの遷移と履歴・エラー・狭幅両テーマは`tests/rdap-lookup.spec.ts`で確認します。コピー・ダウンロード・IME・モバイルなどの詳細シナリオはChromiumで実行します。CIの再試行でのみ成功したケースも失敗扱いです。WebKitの自動検証は今回追加していません。

単体テスト・E2Eともipify・RDAP通信をモックし、実APIへはアクセスしません。実APIへの接続確認は別途必要です。各ツールの詳しい検証対象は[詳細設計書](docs/architecture.md)を参照してください。

### カバレッジ

```sh
npm run test:coverage
```

通常の`npm test`の代わりに実行すると、VitestのV8 Coverageで`src/`のアプリケーションコードを計測します。テスト・型宣言を除外し、未importのソースも含めます。バッジは**Linesカバレッジ**を示し、PlaywrightのE2Eカバレッジは合算しません。最低閾値は設定していません。

ローカルでバッジを生成する場合は、カバレッジ計測とビルドの後に`node scripts/generate-coverage-badge.mjs`を実行してください。`coverage/coverage-summary.json`から`dist/coverage.svg`を生成します。`coverage/`と`dist/`はGit管理対象外です。

### 本番ビルドの確認

```sh
npm run build
npm run preview
```

[ローカルプレビュー](http://localhost:4173/web-toolbox/)を開いてください。

## GitHub Pagesへのデプロイ

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。
2. **Settings → Actions → General** で、GitHub Actionsとワークフローで使用する公式Actionsの実行を許可してください。
3. `github-pages` environmentに承認・ブランチ制限がある場合は、`main`からのデプロイを許可してください。
4. PRのCI結果を確認して`main`へマージしてください。`main`へのpushでは、カバレッジ付き単体テスト・バッジ生成テスト・型チェックを含むビルド・E2Eの成功後、カバレッジSVGを含む`dist/`を公開します。PRでは検証のみ行い、公開しません。
5. Actionsの **CI and Pages** と[公開サイト](https://arscombinatoria.github.io/web-toolbox/)で結果を確認してください。

設定は[CIワークフロー](.github/workflows/ci-pages.yml)を参照してください。Viteの`base`は`/web-toolbox/`です。リポジトリ名や公開パスを変更する場合は、`vite.config.ts`とPlaywrightの配信パスを見直してください。ツール選択はクエリ方式のため、独自のSPA用404は不要です。

## ツールの追加方法

1. `src/tools/<tool-id>/index.ts`を作成し、同期関数`mount(container: HTMLElement): () => void`を実装してください。返す破棄関数でリスナー・タイマー・通信・購読と表示要素を解放してください。
2. `src/registry.ts`の`tools`にID、表示名、説明、カテゴリ、`load: () => import('./tools/<tool-id>/index')`を登録してください。ホームのカードとサイドバーは自動生成されます。カテゴリの追加・順序変更も同ファイルの`categories`で行います。
3. DOM操作と変換ロジックを分離し、必要な単体テストと、必要に応じて主要操作のE2Eテストを追加してください。URLの値をimportパスへ直接使用せず、非同期処理が破棄後の画面を更新しないようにしてください。
4. READMEの一覧・説明と詳細設計書を更新し、テストと型チェックを含むビルドを実行してください。
